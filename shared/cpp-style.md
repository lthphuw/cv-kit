# C++ rules for edge inference code

This is cv-kit's full rule catalogue for C++ that runs inference on edge devices (Jetson, ARM boards, phones):
C++20, built with `-fno-exceptions -fno-rtti`, errors as values, real-time per-frame paths. Every rule has a
stable ID, a strength, a default severity, a check and a source. `rules/cpp-style.md` is the short version that
Claude Code loads while it writes or edits C++; this file is what a review walks through.

- Cite rule IDs in findings (`CPP-EDGE-2`, `CPP-RES-19`), one finding per broken rule instance.
- A project's own written rule beats this catalogue, per rule ID and with a reason (see Precedence).
- Formatter output is not argued with: whatever the project's `.clang-format` produces is correct.
- A MUST rule has one escape only, a suppression on the line itself that names what it suppresses and why:
  `// NOLINT(check-name): reason` for a clang-tidy finding, and `// cv-kit: allow[CPP-XXX-n]: reason` for a
  rule that no tool checks. Name the check exactly as clang-tidy prints it: some diagnostics are printed under
  several alias names, and the NOLINT must list all of them (in clang-tidy 23, `NOLINT(google-explicit-constructor)`
  alone does not silence the finding, which is printed as `cppcoreguidelines-explicit-constructor,misc-explicit-constructor`).
  A suppression without a reason is itself a finding (CPP-DOC-18).

How to read a rule:
- `[MUST]` / `[MUST NOT]`: a review finding whenever broken. `[PREFER]`: a finding when broken without a
  reason in the code or the change description. A guideline that protects correctness is a MUST here even where
  its source only says "prefer".
- `(EDGE)`: the rule matters most on edge targets (memory, latency, power, the ARM memory model, binary size).
- *Check*: how the rule is enforced. clang-tidy checks named there are enabled by the shipped `.clang-tidy`
  (warnings are errors) unless the text says the check is off; compiler flags are in `cv_kit_strict` unless the
  text says otherwise. `grep:` patterns are extended regular expressions that point a reviewer at candidates;
  they prove nothing. `manual` means no tool covers the rule.
- *Severity*: the default for one finding (see Severity).
- *Source*: where the idea comes from (see Sources).

## Precedence

When two rules disagree, the higher item wins, and the conflict is listed in the Conflicts table.
1. The edge rules: CPP-ERR, CPP-EDGE and CPP-BUILD, plus the edge constraints that live in other sections
   (`noexcept` moves in CPP-CLS-14, type punning in CPP-EXPR-19, integer types in CPP-EXPR-22, spans in CPP-FN-35).
   They cover no exceptions, no RTTI, hot-path limits and the strict build.
2. Google C++ Style for naming, layout, comments, headers and includes, scoping, `using`, `auto`, banned library
   features and macros (CPP-HDR, CPP-LIB, CPP-NAME, CPP-FMT, CPP-DOC).
3. C++ Core Guidelines for correctness, lifetime, ownership, parameter passing, concurrency, classes, templates and
   performance (CPP-RES, CPP-CONC, CPP-EXPR, CPP-FN, CPP-CLS, CPP-TPL, CPP-PERF).

Inside one level, a MUST beats a PREFER. A tool's suggested fix never outranks a rule (a clang-tidy fix that
inserts `.at()`, `gsl::at` or `dynamic_cast` is rejected). A project deviates from a rule only in its own written
rule file, per rule ID, with a reason; a single line deviates only through the suppression forms above.

## Tooling

The `py-cpp-lint-setup` skill installs three files into a project; together they enforce every rule whose
*Check* names a tool.

| File | What it enforces |
|---|---|
| `.clang-format` | All of CPP-FMT except the manual points: `BasedOnStyle: Google`, `Standard: c++20`, `PointerAlignment: Left` with `DerivePointerAlignment: false`, `InsertBraces: true`, `InsertNewlineAtEOF: true`, and `IncludeBlocks: Regroup` with `IncludeCategories` for Google's five include groups (CPP-HDR-9; replace the `PROJECT_ROOT` placeholder). |
| `.clang-tidy` | `bugprone-*`, `clang-analyzer-*`, `concurrency-*`, `cppcoreguidelines-*`, `google-*`, `misc-*`, `modernize-*`, `performance-*`, `portability-*`, `readability-*`, plus `clang-diagnostic-thread-safety-analysis`, `clang-diagnostic-exit-time-destructors` and `clang-diagnostic-global-constructors`; warnings are errors. Off: `bugprone-easily-swappable-parameters`, `cppcoreguidelines-avoid-magic-numbers` / `readability-magic-numbers`, `misc-non-private-member-variables-in-classes` (and its alias), `cppcoreguidelines-pro-bounds-avoid-unchecked-container-access`, `cppcoreguidelines-pro-bounds-constant-array-index` (their fixes insert aborting `.at()` / `gsl::at`), `modernize-use-trailing-return-type`, `modernize-use-nodiscard`, `readability-identifier-length`. Options: Google naming (CPP-NAME table), lower-case `f` float suffix, symbolic operators, `TODO(...)` style, banned headers `<ratio>`, `<cfenv>`, `<fenv.h>`, `<filesystem>`, `do`/`while` allowed in macros, `(void)` accepted as a deliberate discard, `std::expected` and `cudaError` as must-check return types, function size 80 lines and cognitive complexity 25. `ExtraArgs`: `-Wno-unknown-warning-option` (the compile database comes from GCC), `-fexceptions` (only so the `noexcept` checks fire; the build keeps `-fno-exceptions`), `-Wthread-safety`, `-Wexit-time-destructors`, `-Wglobal-constructors`. |
| `cmake/cv_kit_strict.cmake` | `cv_kit_strict(<target>)`: C++20 without extensions; `-Wall -Wextra -Wpedantic -Werror -Wconversion -Wsign-conversion -Wshadow -Wold-style-cast -Wcast-align -Wnon-virtual-dtor -Woverloaded-virtual -Wnull-dereference -Wdouble-promotion -Wformat=2 -Wimplicit-fallthrough -Wundef -Wcast-qual -Wsuggest-override -Wzero-as-null-pointer-constant -Wdeprecated-copy-dtor -fno-exceptions -fno-rtti`; GCC adds `-Wduplicated-cond -Wlogical-op -Wuseless-cast -Wcast-align=strict`; Clang adds `-Wctad-maybe-unsupported`; `_GLIBCXX_ASSERTIONS` in Debug; options `CV_KIT_SANITIZE` (ASan+UBSan, no recovery) and `CV_KIT_TSAN` (ThreadSanitizer), never both. |

Tested with clang-format 23.1.3, clang-tidy 23.1.3, CMake 4.4 and GCC 13.3 (x86-64 host). Facts worth knowing
when reading the *Check* fields:
- With `-*` first in `Checks`, clang-tidy reports compiler warnings only for the three `clang-diagnostic-*`
  checks it names; other clang-only warnings need a clang build (CPP-BUILD-11).
- `-Wnull-dereference` only works in optimised builds (CPP-BUILD-7).
- GCC's `-fsanitize=undefined` does not include `float-cast-overflow`, and ASan's pointer-pair checks are not in
  the module's sanitizer options (see Per-project settings).
- A NOLINT must use the check names clang-tidy prints (see the intro).

What stays manual: every rule whose *Check* says `manual` or gives only a `grep:` pattern, the parts of a rule a
check covers only partly (the *Check* says so), tests that a rule requires (allocation counters, fault injection,
sanitizer runs, on-target measurements), and design questions such as ownership, lifetimes, thread ownership and
error policy. Those are where review time goes; the `py-cpp-review` skill walks them in the order below.

## Severity

Severity is rated per finding, on its own merits.
- **Critical**: can crash, corrupt memory or data, race, give wrong output, leak a resource in a long-running
  process, or break a hard constraint of the target (an exception or RTTI in edge C++; a blocking call or a heap
  allocation inside a per-frame real-time path that is documented as allocation-free).
- **Major**: a likely bug; a hazard for the next change (ownership unclear, a lifetime trap, an error ignored);
  a risk that the API gets misused; a measurable cost on a hot path; missing tests for changed behaviour.
- **Minor**: naming, formatting, comments, layout and rules that only serve readability, even when no tool fixes
  them; a suppression without a reason.

The *Severity* in a rule is the default. A single finding moves up when the instance can do Critical harm (a
readability rule broken in a way that hides a real bug is rated by the bug) and down when the code cannot be
reached from a shipped path. Examples:
- A `try`/`catch` block in a library compiled into the edge binary: **Critical** (CPP-ERR-16).
- `static_cast<Conv*>(layer)` with no `kind()` check before it: **Critical** (CPP-ERR-17).
- A wrapper around a throwing SDK whose exception can escape into `-fno-exceptions` code: **Critical** (CPP-ERR-19).
- `detections.push_back(d)` on a vector that is not reserved, inside a function marked `Hot path:`: **Critical** (CPP-EDGE-2).
- `std::lock_guard` on the queue mutex held while `context->enqueueV3(stream)` and the stream sync run: **Critical** (CPP-EDGE-8).
- `cudaMemcpyAsync(...)` result ignored in the inference stage: **Critical** (CPP-EDGE-26).
- A per-track `std::unordered_map` that never erases lost tracks in a 24/7 service: **Critical** (CPP-EDGE-4).
- `-ffast-math` added in `CMakeLists.txt` without a committed reference comparison: **Critical** (CPP-EDGE-16).
- A worker lambda capturing locals by reference and queued to a thread pool: **Critical** (CPP-FN-27).
- A model loader whose constructor opens the file and leaves `is_valid()` false on failure: **Major** (CPP-ERR-8, CPP-ERR-9).
- An error handled by `LOG(ERROR)` and `return Status::Ok()`: **Major** (CPP-ERR-3).
- A move constructor of a frame-buffer type without `noexcept`: **Major** (CPP-CLS-14).
- `std::chrono::system_clock` used to measure stage latency: **Major** (CPP-EDGE-14).
- A changed error return with no test that forces it: **Major** (CPP-ERR-21).
- `void Resize(int width, int height)` in a public header with no `Size` type: **Major** (CPP-FN-5).
- A `struct` with a private invariant-holding member, or a `class` that is passive data: **Minor** (CPP-CLS-1).
- `std::pair<float, int> Best()` in a public header: **Minor** (CPP-FN-12).
- A 30-line function body defined in a header without a profile: **Minor** (CPP-HDR-16).
- A loop variable declared at the top of a long function instead of in the `for`: **Minor** (CPP-EXPR-1).
- The literal `640` repeated in pre- and post-processing: **Minor** (CPP-EXPR-15), **Major** if the copies already disagree.
- `std::endl` in a startup banner: **Minor** (CPP-EDGE-7).
- `// NOLINT(cppcoreguidelines-pro-type-static-cast-downcast)` with no reason after it: **Minor** (CPP-DOC-18; the cast itself is judged by CPP-ERR-17).

## Review order

Walk the sections in this order, so the findings most likely to be Critical come first and nothing waits behind
formatting:
1. CPP-ERR: banned constructs, unchecked downcasts, error paths, throwing third-party code.
2. CPP-EDGE: hot paths (allocation, blocking, locks, queues, threads), vendor return codes, numerics, alignment.
3. CPP-RES: ownership and lifetime.
4. CPP-CONC: races, lock discipline, condition variables, thread lifetimes.
5. CPP-EXPR: undefined-behaviour-prone expressions, casts, integer arithmetic.
6. CPP-FN, CPP-CLS, CPP-TPL, CPP-PERF: interfaces and design.
7. CPP-HDR, CPP-LIB: headers, scoping, dependencies and library features.
8. CPP-NAME, CPP-FMT, CPP-DOC: last; mostly tool-covered.
9. CPP-BUILD: when build files, presets or CI change, or once per project.

Covered by tools, so a reviewer reports these only when the tool does not run in CI (then once, as "tool not
run", plus the most serious instance):
- Compiler flags (`cv_kit_strict`): the bans of CPP-ERR-16, discarded `[[nodiscard]]` results (CPP-ERR-2), float
  promotion and conversion (CPP-EDGE-15), the sign and narrowing parts of CPP-EXPR, old-style casts, shadowing,
  missing `override` (CPP-CLS-30).
- clang-tidy: most of CPP-NAME; the cast, narrowing and initialisation parts of CPP-EXPR; `owning-memory` and
  `no-malloc` in CPP-RES; `unused-raii`, `mt-unsafe` and thread-safety analysis in CPP-CONC (with annotations);
  the `performance-*` parts of CPP-PERF; CPP-EDGE-7, CPP-EXPR-19, CPP-EXPR-22 and the intrinsics part of
  CPP-EDGE-25; static-storage objects (CPP-HDR-29, CPP-HDR-30).
- clang-format: CPP-FMT apart from the points marked manual.
- Sanitizers and tests: CPP-RES-1 (LeakSanitizer on error paths), CPP-ERR-21, CPP-EDGE-2 (allocation counter),
  CPP-EDGE-10 (TSan replay).

Review time goes to the manual rules, above all CPP-ERR-3, CPP-ERR-8, CPP-ERR-11, CPP-ERR-19, CPP-EDGE-1,
CPP-EDGE-4, CPP-EDGE-8, CPP-EDGE-9, CPP-EDGE-26, CPP-EDGE-28, CPP-RES-13, CPP-RES-19, CPP-CONC-10 and CPP-CLS-8.

## CPP-ERR Error handling without exceptions

Errors are values: one project result type, `[[nodiscard]]`, factories instead of fallible constructors, and aborts only for bugs.

- **CPP-ERR-1** [MUST] The project uses exactly one error vocabulary, declared in one header: a status type plus a value-or-error type (`std::expected` with C++23 library support, else `tl::expected` or `absl::Status`/`absl::StatusOr`), with an `enum class` error code; new APIs never report failure through `int` codes, `bool` for a multi-cause failure, `std::pair<T, int>`, or out-parameters for the error. *Why:* one convention is easier to check and to propagate than several mixed ones. *Check:* manual; `grep: return -1;|std::pair<[^>]*,\s*(int|bool)>|bool\s+\w+\([^)]*\)\s*;` on fallible APIs. *Severity:* Major. *Source:* CG E.1, CG E.14, CG E.27; Google "Exceptions".
- **CPP-ERR-2** [MUST] The status and result types are declared `[[nodiscard]]` on the class (so every function returning them is covered), copy and move without allocating on the OK path, and have `noexcept` moves; any other function whose result must not be ignored (a pure query, a factory, a call whose only effect is its return value) is marked `[[nodiscard]]` itself; a deliberate discard is spelled out with a named call (`status.IgnoreError()`) or `(void)` plus a comment saying why. *Why:* without exceptions, a returned error is the only signal, and an ignored one is a silent failure; verified that a discarded `[[nodiscard]]` class result is an error under `-Werror` (`-Wunused-result`, on by default) and that `(void)` silences it, hence the comment. *Check:* g++ `-Werror` (`-Wunused-result`); clang-tidy `bugprone-unused-return-value` (flags ignored `std::expected` and `cudaError` results and accepts a `(void)` discard; the project adds its own result types, see Per-project settings); manual for plain functions (`modernize-use-nodiscard` is off: noisy on getters); `grep: \(void\)\s*[A-Za-z_:]+\(` for discards without a comment. *Severity:* Major. *Source:* CG E.25, CG I.10, CG E.16, CG ES.48; cv-kit.
- **CPP-ERR-3** [MUST] A function that cannot handle an error returns it to its caller, adding context where it helps; it never logs and then reports success, never drops the error, and never replaces a specific cause with a generic code (keep the original code and vendor value when wrapping). *Why:* the layer with a policy (drop the frame, restart the stage) can only act on errors that reach it intact. *Check:* manual; `grep: if \(!\w+\.ok\(\)\)\s*\{[^}]*(LOG|log|printf)[^}]*\}` without a `return`. *Severity:* Major. *Source:* CG E.17, CG E.15 (analogue).
- **CPP-ERR-4** [MUST] Every error carries enough to act on: the error code, the failed operation, the input it concerned (path, tensor or device name, frame index) and, when it comes from a vendor API, the vendor's code or name; on a hot path the context is static strings and integers, not formatted strings. *Why:* "inference failed" with no cause cannot be triaged from a field log. *Check:* manual. *Severity:* Major. *Source:* CG E.14; cv-kit.
- **CPP-ERR-5** [MUST] An error is logged once, by the layer that handles it (applies the policy); layers that only propagate it do not log it. *Why:* (experience) logging at every level multiplies log volume, which on a device fills flash and costs time per frame. *Check:* manual. *Severity:* Major. *Source:* CG E.17; cv-kit.
- **CPP-ERR-6** [MUST NOT] Signal failure with an in-band sentinel (`-1`, `nullptr`, `0`, an empty string, NaN) unless the sentinel is part of the type (`std::optional`, a pointer documented as "null when absent") and the declaration comment says what it means. *Why:* sentinels are easy to forget and collide with valid values (a detection at index 0, a legal 0.0f score). *Check:* manual; `grep: return (-1|nullptr|NAN|std::nan)` in fallible functions. *Severity:* Major. *Source:* cv-kit; CG E.14.
- **CPP-ERR-7** [MUST] The error channel is used only when a function could not do its job; expected outcomes ("no detections", "queue empty", "key not found", "no frame ready yet") are ordinary values (`std::optional`, an empty container, an `enum class` outcome). *Why:* callers should not branch on error codes for normal results, and errors should mean something is wrong. *Check:* manual. *Severity:* Major. *Source:* CG E.2, CG E.3.
- **CPP-ERR-8** [MUST] A type whose setup can fail (file or model load, device allocation, engine build, driver open, any call that returns a status) has a private constructor that cannot fail and only takes already-acquired resources, plus `static Result<T> Create(...)` (or `Result<std::unique_ptr<T>>` when the type is polymorphic or must not move); constructors do no fallible work. *Why:* a constructor has no way to report failure without exceptions, so a half-built object would escape. *Check:* manual; `grep:` constructor bodies calling `cudaMalloc|open\(|fopen|ioctl|deserialize|Load|Build`. *Severity:* Major. *Source:* CG C.40, CG C.41, CG C.42, CG E.5, CG NR.5; Google "Doing Work in Constructors".
- **CPP-ERR-9** [MUST NOT] Expose a public two-phase setup: no public `Init()`, `Initialize()`, `Setup()` or `Open()` that must be called before the object is usable, and no public `is_valid()` / `ok()` state on a half-built object. The only exception is a private member wrapping a third-party type that is itself two-phase. *Why:* every caller would have to remember the second call and the check. *Check:* `grep: (bool|Status|int|void)\s+(Init|Initialize|Setup)\s*\(|bool\s+(is_valid|IsValid)\s*\(`; manual. *Severity:* Major. *Source:* CG NR.5, CG C.41; Google "Doing Work in Constructors".
- **CPP-ERR-10** [MUST] Destructors never fail and never skip their job: they release unconditionally, log a failed release (rate-limited), and never abort or block without bound. When release can fail in a way the owner must learn about (flush, device close, stream sync, file write), the type offers an idempotent `[[nodiscard]] Status Close()` that the owner calls on the normal path; the destructor then does a best-effort release only if `Close()` was not called. *Why:* a destructor cannot return a status, and a release error found only in a destructor is lost. *Check:* manual. *Severity:* Major. *Source:* CG C.36, CG E.16.
- **CPP-ERR-11** [MUST] Bugs and runtime conditions use different mechanisms: a programmer error (broken invariant, violated internal precondition, impossible state) is caught by the project check macro that logs and aborts (`CVK_CHECK` kept in release when cheap, `CVK_DCHECK` debug only); a condition caused by the outside world (bad or missing file, camera timeout, corrupt frame, full queue, busy device, model/engine mismatch) returns a status. Never abort on outside data; never return a status for a bug in the caller. *Why:* aborting on field conditions takes down a device for a dropped frame; returning a status for a bug hides it. *Check:* manual. *Severity:* Major. *Source:* CG E.7, CG E.8, CG E.26; Google "Exceptions" (codes and assertions instead).
- **CPP-ERR-12** [MUST] A public function states its preconditions in the declaration comment and validates them once, where data enters (external data returns a status; internal contracts use `CVK_DCHECK`); class invariants are stated once on the class; inner loops and private helpers do not re-check what the boundary already checked. *Why:* checks belong where the cause is known, and repeated checks cost time per pixel. *Check:* manual. *Severity:* Major. *Source:* CG E.7, CG P.7, CG I.5, CG I.6, CG I.7, CG I.8.
- **CPP-ERR-13** [MUST] Abort only through the project check macros, and only for broken invariants, out-of-memory and unrecoverable device or engine state, after writing one synchronously flushed log line with file, line and the failed condition; library code never calls `exit`, `quick_exit`, `_Exit` or `std::terminate`, and never relies on bare `assert` (compiled out by `NDEBUG`) to guard anything that matters. A supervisor (systemd, watchdog, the Android lifecycle) restarts the process. *Why:* abort must be rare, explained and deliberate; `exit` from a library skips the owner's shutdown order. *Check:* `grep: \b(std::)?(abort|exit|quick_exit|_Exit|terminate)\s*\(|\bassert\s*\(`; manual. *Severity:* Major. *Source:* CG E.26; Google "Doing Work in Constructors" (termination as an acceptable response).
- **CPP-ERR-14** [MUST] Treat allocation failure as fatal except where the policy says otherwise: under `-fno-exceptions` a failed `new`, `make_unique` or container growth aborts the process (verified: `new` and `vector::reserve` print `std::bad_alloc` and abort; `reserve` above `max_size()` aborts with `length_error`). So large allocations happen at init (CPP-EDGE-3); sizes taken from outside data (headers, configs, tensor shapes) are validated before allocating; and where running out of memory must be survivable, allocate with `new (std::nothrow)` (verified to return `nullptr`), check it, hand it to a `std::unique_ptr` in the same statement, and return a status. *Why:* there is no handler to catch the failure, so an input-sized allocation is a crash-by-input. *Check:* manual; `grep: new\s*\(std::nothrow\)` (null check follows). *Severity:* Major. *Source:* CG E.12, CG E.26; Google "noexcept" (OOM may be fatal).
- **CPP-ERR-15** [MUST NOT] Use standard or GSL facilities that report errors by throwing as a checking mechanism: `.at()`, `std::get<T>(variant)`, `optional::value()`, `std::stoi`/`stof` family, `gsl::narrow`, `gsl::at`, `std::bitset::to_ulong`, runtime `std::thread` creation, `std::async`, `future::get` on a broken promise. Each aborts under `-fno-exceptions` (verified for `.at()`, `std::get`, `value()` and `std::thread` creation failure). Use instead: a bounds check at the boundary then `operator[]` (hardened in Debug, CPP-BUILD-3), `std::get_if` or `std::visit`, `has_value()` then `*`, `std::from_chars`, a project `CheckedNarrow<To>(x) -> std::optional<To>`, and threads created at init. *Why:* an abort is not error handling; the check must be visible and return a status. *Check:* `grep: \.at\(|std::get<|\.value\(\)|std::sto(i|l|ll|ul|ull|f|d|ld)\(|gsl::(narrow|at)\b|std::async`; clang-tidy `bugprone-unchecked-optional-access`; `cppcoreguidelines-pro-bounds-avoid-unchecked-container-access` and `cppcoreguidelines-pro-bounds-constant-array-index` stay off (their fixes insert `.at()` or `gsl::at`). *Severity:* Major. *Source:* cv-kit; Google "Exceptions".
- **CPP-ERR-16** [MUST NOT] Write `throw`, `try`, `catch`, `dynamic_cast`, `typeid`, or use `std::exception_ptr`, `std::current_exception`, `std::rethrow_exception`, `std::nested_exception` or `std::type_info` in edge code; build with `-fno-exceptions -fno-rtti`. *Why:* the target constraint; verified that g++ 13 rejects `try` and `throw` under `-fno-exceptions`, and `dynamic_cast` to a derived type and `typeid` (even on a non-polymorphic `int`) under `-fno-rtti`; an upcast `dynamic_cast` still compiles, so grep catches what the flag does not. *Check:* g++ `-fno-exceptions -fno-rtti`; `grep: \b(throw|try|catch|dynamic_cast|typeid)\b|exception_ptr|current_exception|rethrow_exception|nested_exception|type_info`. *Severity:* Critical. *Source:* Google "Exceptions", Google "Run-Time Type Information (RTTI)"; cv-kit.
- **CPP-ERR-17** [MUST NOT] Downcast with `static_cast` unless the dynamic type was checked immediately before, in the one audited helper per hierarchy that tests a `kind()` tag (never a type-name string) and carries `// NOLINT(cppcoreguidelines-pro-type-static-cast-downcast): kind() checked above`; a "maybe" downcast returns a pointer that callers null-check before use. *Why:* an unchecked downcast to the wrong type is undefined behaviour and corrupts memory; verified that the check fires on a tag-checked cast and that its suggested fix (`dynamic_cast`) does not compile here, so the NOLINT is expected. *Check:* clang-tidy `cppcoreguidelines-pro-type-static-cast-downcast`; manual. *Severity:* Critical. *Source:* CG C.146, CG C.147, CG C.148, CG C.153, CG Type.2; Google "Run-Time Type Information (RTTI)"; cv-kit.
- **CPP-ERR-18** [PREFER] Replace a downcast, in this order: a virtual function that does the work; a `std::variant` with `std::visit` or `std::get_if` for a closed set of kinds; a virtual `AsConv()`-style query returning a pointer or `nullptr`; only then the tag-checked helper of CPP-ERR-17. *Why:* each step down this list moves more checking from the compiler to the reviewer. *Check:* manual. *Severity:* Minor. *Source:* CG C.146, CG C.153; Google "Run-Time Type Information (RTTI)".
- **CPP-ERR-19** [MUST] Third-party code that can throw is reached only through one of: its C API (ONNX Runtime `OrtApi` returning `OrtStatus*`); its no-exceptions build mode, and then only if aborting on every error is acceptable (verified: ONNX Runtime 1.23.2 `onnxruntime_cxx_api.h` does not compile under `-fno-exceptions` unless `ORT_NO_EXCEPTIONS` is defined, and with it every error prints to `std::cerr` and calls `abort()`); arguments validated so the throwing path cannot be reached (for example OpenCV size, type and emptiness checks); or a separate wrapper library compiled with `-fexceptions` whose every entry point is `noexcept`, catches everything, and returns the project status, with no exception type in its header. *Why:* verified that an exception thrown below and caught above a `-fno-exceptions` frame skips that frame's destructors silently (locks stay held, buffers leak), and with no handler anywhere it terminates; the catch must therefore sit inside the wrapper. *Check:* manual; `grep: -fexceptions` in CMake (each use is a reviewed wrapper target). *Severity:* Critical. *Source:* cv-kit; Google "Exceptions".
- **CPP-ERR-20** [MUST] Error state that a C or vendor API keeps outside the return value (`errno`, `cudaGetLastError` / `cudaPeekAtLastError`, `glGetError`, TensorRT `ILogger` messages) is read on the same thread right after the call and turned into a returned status; the project defines no `last_error`-style global or member that callers query later. *Why:* verified on CUDA 12.8: after a failed `cudaMalloc`, a later successful call still leaves `cudaGetLastError()` reporting the earlier failure once, so a late check blames the wrong call. *Check:* `grep: \berrno\b|cudaGetLastError|cudaPeekAtLastError|glGetError|last_error`; manual. *Severity:* Major. *Source:* CG E.28.
- **CPP-ERR-21** [MUST] Every error return added or changed is exercised by a test that forces it (a fake vendor API returning an error, a truncated model file, a zero-size or oversized frame, a full queue) and runs under ASan+UBSan on host. *Why:* error paths run rarely in the field and are where leaks and use-after-free hide. *Check:* test; sanitizer: ASan+UBSan (CPP-BUILD-4). *Severity:* Major. *Source:* cv-kit; CG E (section introduction).

## CPP-EDGE Edge-device constraints

Hot path, used throughout: a function or loop that the project documents as running once or more per frame in steady state under a latency budget (CPP-EDGE-1), plus everything it calls.

- **CPP-EDGE-1** [MUST] Every hot path is declared: the function (or the loop's enclosing function) has a declaration comment starting `Hot path:` that names its rate and budget (for example `// Hot path: per frame, 4 ms on Orin NX, no allocation, no blocking.`), and per-frame code in a real-time pipeline without such a comment is itself a finding. *Why:* the hot-path rules below can only be applied to code that is known to be hot. *Check:* `grep: Hot path:`; manual. *Severity:* Major. *Source:* cv-kit.
- **CPP-EDGE-2** [MUST NOT] Allocate on the heap in a hot path in steady state: no `new`, `make_unique`, `make_shared`, container growth past reserved capacity (`push_back`, `resize`, `insert`, map/unordered_map insertion), `std::string` building or `std::to_string`, `std::stringstream`, `std::function` holding a capture larger than its inline buffer (verified with libstdc++ 13: a 4-byte capture allocates 0 times, a 32-byte capture once), a new `cv::Mat` per frame, coroutine frames, or thread creation. *Why:* allocator latency is unbounded and fragmentation grows over long runs. *Check:* test: a counting `operator new` around N steady-state frames expects 0 allocations; clang `[[clang::nonallocating]]` + `-Wfunction-effects` where CPP-EDGE-33 applies; `grep: new |make_(unique|shared)|push_back|emplace_back|resize\(|to_string|stringstream|std::function` in hot-path functions. *Severity:* Critical. *Source:* CG Per.14, CG Per.15; cv-kit.
- **CPP-EDGE-3** [MUST] Size all per-frame memory at init from config and model shapes (inside `Create()`), and reuse it every frame: scratch buffers are members, cleared but not shrunk; outputs go into caller-provided, reused buffers (an in-out `T&` or `std::span<T>`, CPP-FN-11); reserving and in-place construction: CPP-PERF-6. *Why:* this is what makes CPP-EDGE-2 possible. *Check:* the counting-allocator test of CPP-EDGE-2; manual. *Severity:* Major. *Source:* CG Per.14, CG R.5; Google "Functions > Inputs and Outputs".
- **CPP-EDGE-4** [MUST] The project states a memory budget per process (host RAM and device memory; on Jetson both come from the same DRAM) and measures the peak on target (CPP-BUILD-9); every container that can grow with input (detections, tracks, caches, history, pending logs) has a fixed capacity and a documented overflow policy (drop, evict oldest, or reject with a status). No cache without eviction. *Why:* unbounded growth in a process that runs for weeks is a leak with extra steps, ending in the OOM killer. *Check:* manual; test on target (peak RSS and device memory over a long run). *Severity:* Critical. *Source:* cv-kit.
- **CPP-EDGE-5** [MUST NOT] Make blocking calls in a hot path: file or socket I/O, synchronous logging to a terminal or file, `std::cout`/`printf`, `sleep_for`, `cudaDeviceSynchronize`, waiting on a lock that slow code holds, or any syscall that can wait; the only waits are the documented sync points of the pipeline (dequeue with timeout, the stream sync of the inference stage). *Why:* one blocked call stalls the frame and every stage behind it. *Check:* manual; clang `[[clang::nonblocking]]` + `-Wfunction-effects` (CPP-EDGE-33); `grep: std::cout|printf\(|fwrite|fopen|sleep_for|cudaDeviceSynchronize`. *Severity:* Critical. *Source:* CG Per.30; cv-kit.
- **CPP-EDGE-6** [MUST] Logging reachable from a hot path is rate-limited per call site (for example at most once per second, with a count of suppressed messages) or replaced by counters reported off the hot path, and goes to a non-blocking sink. *Why:* a per-frame log line at 30 fps is 2.6 million lines a day and blocks when the sink is slow. *Check:* manual; `grep:` log calls inside hot-path functions. *Severity:* Critical. *Source:* cv-kit.
- **CPP-EDGE-7** [MUST NOT] Use `std::endl`; write `'\n'` and flush explicitly where a flush is required. *Why:* every `std::endl` forces a flush, which stalls on eMMC, SD cards and serial consoles. *Check:* clang-tidy `performance-avoid-endl` (has a fix). *Severity:* Minor. *Source:* CG SL.io.50; mD C++ 01; cv-kit.
- **CPP-EDGE-8** [MUST NOT] Hold a lock across inference or any long step (engine enqueue plus sync, resize, NMS, a whole-frame copy, I/O, a callback); under the lock, only swap a pointer, index or slot. Locking mechanics are in CPP-CONC. *Why:* the camera thread blocks on the queue lock for the full inference time and frames are lost or the pipeline deadlocks. *Check:* manual; clang `[[clang::nonblocking]]` flags lock construction (verified) in annotated functions. *Severity:* Critical. *Source:* CG CP.43, CG CP.22.
- **CPP-EDGE-9** [MUST] Stages of a pipeline are connected by bounded queues (a ring buffer or a fixed pool of frame slots) with a documented full-queue policy: live video drops the oldest (or newest) frame and counts the drop; offline processing blocks with a timeout. The camera thread never blocks without bound. *Why:* an unbounded queue turns a slow stage into growing latency and memory. *Check:* manual; `grep: std::(queue|deque|list)<` in pipeline code. *Severity:* Critical. *Source:* cv-kit; mD C++ 05.
- **CPP-EDGE-10** [MUST] A frame buffer has exactly one owning stage at a time and moves to the next stage by handle (pool slot, `std::unique_ptr`, index); no stage writes a buffer another stage may still read, small metadata (timestamps, ROIs, detections) is passed by value, and concurrent readers get read-only views (`const T&`, `std::span<const T>`). *Why:* shared mutable frames are data races that x86 often hides and ARM exposes. *Check:* manual; sanitizer: TSan on host replay tests. *Severity:* Critical. *Source:* CG CP.3, CG CP.31, CG CP.32.
- **CPP-EDGE-11** [MUST] The set of threads is fixed at startup: one long-lived thread per stage plus a fixed-size worker pool whose size comes from configuration (clamped to at least 1; not raw `std::thread::hardware_concurrency()`, which can be 0 and ignores big.LITTLE and accelerator threads); only the pipeline setup code creates threads, and none is created per frame, per request or per item. *Why:* thread creation is a syscall plus an allocation, and under `-fno-exceptions` a failed creation aborts (verified: `std::system_error` "Resource temporarily unavailable" then abort). *Check:* `grep: std::(j)?thread\b|std::async|pthread_create` outside the pipeline setup code; manual. *Severity:* Major. *Source:* CG CP.4, CG CP.40, CG CP.41, CG Per.30; mD C++ 07.
- **CPP-EDGE-12** [MUST] Every thread is owned by the pipeline object as a `std::jthread` member (or a project joining wrapper where the toolchain lacks C++20 `<thread>`), stops through its `std::stop_token` or an atomic flag that also wakes its waits, and is joined; `detach()` is never called, and no thread object lives at namespace scope. Shutdown order: stop producers, wake and drain or drop the queues, join, then release devices. *Why:* a detached or unjoined thread outlives the objects and device handles it uses; verified that `std::jthread` with a stop token joins cleanly under the strict flags, and that a joinable `std::thread` destroyed without `join()` aborts. *Check:* `grep: \.detach\(\)|std::thread\b`; manual. *Severity:* Critical. *Source:* CG CP.23, CG CP.24, CG CP.25, CG CP.26; mD C++ 07; cv-kit.
- **CPP-EDGE-13** [MUST] A thread waiting for a frame or result blocks on a condition variable, semaphore or driver `poll()` with a predicate and a `steady_clock` timeout; it never spins with `yield()` or short sleeps, and a timeout becomes a status (stalled camera, hung accelerator) instead of a silent hang. *Why:* spinning burns battery and thermal headroom; waits without timeout turn a stalled device into a frozen feed. *Check:* `grep: yield\(\)|sleep_for\(.*(1|2|5)ms|while\s*\(!` in pipeline code; manual. *Severity:* Major. *Source:* mD C++ 07; cv-kit.
- **CPP-EDGE-14** [MUST] Use `std::chrono::steady_clock` for latency, timeouts, deadlines and rate limits; `system_clock` only for wall-clock timestamps in logs and metadata; `high_resolution_clock` not at all (verified: in libstdc++ 13 it is `system_clock`, which is not steady). Camera timestamps are compared only with clocks of the same domain (for example V4L2 monotonic buffer timestamps against `CLOCK_MONOTONIC`). *Why:* edge boards often boot without a real-time clock and jump at NTP sync, breaking any `system_clock` interval. *Check:* `grep: system_clock|high_resolution_clock`. *Severity:* Major. *Source:* mD C++ 07 (pitfall); cv-kit.
- **CPP-EDGE-15** [MUST] Float code stays in float: `float` literals (`0.5f`), `float` overloads of math functions, and no implicit promotion to `double`. *Why:* double arithmetic is slower on ARM NEON and much slower on GPUs; verified that `-Wdouble-promotion` fires on `x * 0.5` and on passing a `float` to `printf`, and `-Wconversion` (`-Wfloat-conversion`) catches `float f = 0.1;`; neither flags `float f = 1.0;` (exact), which is then a style point only. *Check:* g++ `-Wdouble-promotion -Wconversion`; clang-tidy `bugprone-narrowing-conversions`. *Severity:* Major. *Source:* cv-kit.
- **CPP-EDGE-16** [MUST NOT] Build any shipped code with `-ffast-math`, `-Ofast`, `-ffinite-math-only` or `-funsafe-math-optimizations` unless its outputs were compared against a reference build on the target within a stated tolerance and the comparison is committed; never pass them at link time. *Why:* verified with g++ 13 at `-O2`: under `-ffast-math`, `std::isnan` is folded to false so NaN checks vanish; and linking an object compiled without fast-math using `-ffast-math` still flushes subnormals to zero for the whole process (x86-64). *Check:* `grep: fast-math|Ofast|finite-math|unsafe-math` in CMake and toolchain files. *Severity:* Critical. *Source:* cv-kit.
- **CPP-EDGE-17** [MUST] Numeric comparisons against a reference (unit tests, model-output tests, the fast-math gate) use a stated per-output tolerance (absolute, relative or ULP) produced on the target build; bit-exact comparison is used only when both sides are built with `-ffp-contract=off` and the same math library. *Why:* verified that g++ 13 in `-std=c++20` mode contracts `a * b + c` into a fused multiply-add when the target has FMA (always on AArch64), so host and device results differ in the last bits. *Check:* test; manual. *Severity:* Major. *Source:* cv-kit.
- **CPP-EDGE-18** [MUST] Non-finite values (NaN, Inf) are detected where they enter: model outputs, sensor data and loaded calibration are checked at the stage boundary and turned into a status or a dropped frame; code after the boundary may assume finite values. *Why:* one NaN in a box regressor propagates silently through NMS and tracking. *Check:* test (inject NaN at each boundary); manual. *Severity:* Major. *Source:* cv-kit.
- **CPP-EDGE-19** [MUST] The project documents its denormal policy (flush-to-zero and denormals-are-zero on or off, on which threads) and, if on, sets it explicitly at thread start through the portability header, never as a side effect of compiler or linker flags; reference comparisons run with the same policy. *Why:* (experience) subnormals can cost large slowdowns on some cores, and flushing changes results; either choice must be deliberate. *Check:* manual. *Severity:* Minor. *Source:* cv-kit.
- **CPP-EDGE-20** [MUST] Conversions to and from fp16, bf16, int8 and uint8 (quantise, dequantise, pixel normalisation) go through named functions that state scale, zero point, rounding and saturation; no bare `static_cast<int8_t>(x)` from a float that may be out of range. *Why:* an out-of-range float-to-integer conversion is undefined behaviour, and silent wrap or truncation shifts every output. *Check:* manual; `grep: static_cast<u?int8_t>\(`; g++ `-Wconversion`. *Severity:* Major. *Source:* cv-kit; CG ES.46.
- **CPP-EDGE-21** [MUST] A struct that is written to a file or the wire, mapped from device memory, or shared with a CUDA kernel pins its layout with `static_assert` on `sizeof`, `alignof`, `std::is_trivially_copyable_v` and the offsets that matter; `#pragma pack` appears only in the portability header. *Why:* padding and alignment differ between compilers and ABIs, and a silent layout change corrupts every record. *Check:* manual; `grep: #\s*pragma\s+pack`. *Severity:* Major. *Source:* CG P.5; Google "Architecture Portability".
- **CPP-EDGE-22** [MUST] Buffers used with SIMD aligned loads, DMA or vendor APIs that need alignment are allocated with it (`alignas(N)` for fixed arrays and structs; an aligned allocator, `std::aligned_alloc` or `posix_memalign` inside an RAII handle; or the vendor allocator), the requirement is written on the API, and it is checked once at the boundary; nothing assumes `std::vector<uint8_t>::data()` is aligned beyond `alignof(std::max_align_t)`. *Why:* a misaligned access is undefined behaviour and faults on some ARM instructions; verified that UBSan reports a misaligned `float` load and that plain `-Wcast-align` is silent on x86-64 while `-Wcast-align=strict` flags the `unsigned char*` to `float*` cast. *Check:* sanitizer: UBSan (alignment); g++ `-Wcast-align=strict` (GCC builds); manual. *Severity:* Critical. *Source:* cv-kit.
- **CPP-EDGE-23** [MUST] Binary formats (model and calibration blobs, network messages, sensor packets) have a documented byte order and are decoded field by field with explicit byte order (assemble from bytes, or `std::endian` plus a byte swap); never `fread` or `memcpy` a whole struct from external data. *Why:* layout and byte order differ between writer and reader, and a whole-struct read also trusts unvalidated sizes. *Check:* `grep: fread\(&|memcpy\(&\w+,.*sizeof\((struct )?\w+\)`; manual. *Severity:* Major. *Source:* Google "Architecture Portability".
- **CPP-EDGE-24** [MUST] Image and tensor buffers cross APIs as a view type that carries element type, shape, stride (in bytes or elements, stated), layout (NCHW/NHWC/planar) and colour order, built on `std::span`; no `T*` plus separate size arguments; pointer arithmetic for rows and strides lives only inside the view type. *Why:* a pointer without its shape is where off-by-stride and wrong-layout bugs come from. *Check:* clang-tidy `cppcoreguidelines-pro-bounds-pointer-arithmetic`; `grep: \(\s*(const\s+)?\w+\s*\*\s*\w+\s*,\s*(int|size_t|int64_t)\s+\w+`. *Severity:* Major. *Source:* CG R.2, CG R.14, CG Bounds.1; cv-kit.
- **CPP-EDGE-25** [MUST] Non-portable code lives only in the project portability headers (one directory): SIMD intrinsics (`arm_neon.h`, `immintrin.h`), `__restrict__`, `__attribute__`, `__builtin_*`, `[[clang::...]]` and `[[gnu::...]]` attributes, `#pragma` (`omp`, `unroll`, `GCC`), inline assembly, `alloca`, statement expressions `({ ... })`, the `a ?: b` operator, `__PRETTY_FUNCTION__`, `__COUNTER__`, `#warning`, and platform `#if` (`__aarch64__`, `__ARM_NEON`, `__CUDACC__`, `__ANDROID__`; how to write those: CPP-LIB-13); each has a scalar fallback that is built and tested on host. *Why:* the rest of the code stays standard C++ and testable on any machine. *Check:* clang-tidy `portability-simd-intrinsics` (flags x86 `_mm_*` intrinsics, not NEON ones; disable it only in the portability directory, see Per-project settings), `portability-no-assembler`; `-Wpedantic -Werror` for VLAs, statement expressions and `?:`; `grep: __restrict__|__attribute__|__builtin_|#\s*pragma|\basm\b|__aarch64__|__ARM_NEON|immintrin|arm_neon` outside that directory. *Severity:* Major. *Source:* Google "Nonstandard Extensions", Google "Architecture Portability", Google "C++ Version"; CG P.2; cv-kit.
- **CPP-EDGE-26** [MUST] Every call into CUDA, TensorRT, ONNX Runtime, OpenCV, V4L2, EGL or another vendor API that can report failure is checked through a project helper that turns the vendor result into the project status with the call name, the vendor code or name, and the source location (`std::source_location`, so no macro is needed; verified to compile under the strict flags and to return `cudaErrorMemoryAllocation` with the right line on a real GPU). Library code returns that status and never aborts. This covers: `cudaGetLastError()` right after a kernel launch and the result of each sync; TensorRT `enqueueV3`/`setTensorAddress` `bool` results and `nullptr` from engine creation (and `ILogger` errors routed to the log); `OrtStatus*` results; OpenCV `bool` results (`VideoCapture::read`, `imwrite`) and empty `cv::Mat`; V4L2 `ioctl` returning -1 with `errno` (retry on `EINTR`; `EAGAIN` from a non-blocking `VIDIOC_DQBUF` is a normal "no frame" outcome, CPP-ERR-7). *Why:* an unchecked device call turns into garbage outputs frames later, far from the cause. *Check:* clang-tidy `bugprone-unused-return-value` (the shipped `CheckedReturnTypes` include `cudaError`, so an ignored `cudaMalloc` result is flagged); `grep: ^\s*(cuda\w+|ioctl|cv::\w+)\(` statements whose result is unused; manual. *Severity:* Critical. *Source:* cv-kit; CG E.28.
- **CPP-EDGE-27** [MUST] Host-to-device data movement is explicit: each copy is a visible call on a named stream (`cudaMemcpyAsync`), pinned host buffers for async copies are allocated at init, every stream and event is owned by one RAII handle and used by its owner, work goes on non-blocking streams (`cudaStreamNonBlocking`) rather than the legacy default stream, and library code never calls `cudaDeviceSynchronize`; managed or zero-copy memory (valid on Jetson's shared DRAM) is a documented design choice with its access pattern. *Why:* hidden copies and device-wide syncs serialise the whole GPU and wreck the latency budget. *Check:* `grep: cudaDeviceSynchronize|cudaMemcpy\(|cudaMallocManaged|<<<[^>]*>>>` (a launch without a stream argument); manual. *Severity:* Major. *Source:* cv-kit.
- **CPP-EDGE-28** [MUST] The host reads device results only after the producing work is known complete (a sync on that stream, or an event it recorded), and a device or pinned buffer is not reused or freed while queued work may still read or write it. *Why:* reading early or reusing a buffer still in flight is a race that yields wrong boxes intermittently. *Check:* manual; test with `compute-sanitizer --tool racecheck` on host (not tested by cv-kit). *Severity:* Critical. *Source:* cv-kit.
- **CPP-EDGE-29** [MUST NOT] Keep device or driver handles (CUDA allocations, streams, TensorRT runtime or engine, camera fds, EGL displays) in static or global storage; the application object owns them and releases them in order before `main` returns. The general rule on static and global variables is in CPP-HDR. *Why:* static destructors run after the driver may have begun shutdown (CUDA reports `cudaErrorCudartUnloading`) and after worker threads were torn down. *Check:* `grep: ^(static\s+)?\S*(cudaStream_t|IRuntime|ICudaEngine|cv::VideoCapture)\b` at namespace scope or as `static` locals; manual. *Severity:* Major. *Source:* cv-kit.
- **CPP-EDGE-30** [PREFER] Keep binary size on target in check: shipped builds use `-ffunction-sections -fdata-sections -Wl,--gc-sections`, and binary size is tracked per release (iostreams: CPP-LIB-9; template bloat: CPP-TPL-11; header bodies: CPP-HDR-16). *Why:* (experience) flash, OTA download and instruction cache are all limited on devices. *Check:* manual (size per release). *Severity:* Minor. *Source:* mD C++ 06, mD C++ 08; cv-kit.
- **CPP-EDGE-31** [MUST] Cross builds use a CMake toolchain file (system name and processor, sysroot, compilers, find-root-path modes) and find dependencies with `find_package` inside the sysroot; CMake files contain no host paths (`/usr/include`, `/usr/lib/x86_64-linux-gnu`, `/home/...`, `/opt/...` outside the toolchain file). *Why:* a host path silently links x86 libraries or headers of the wrong version into an ARM build. *Check:* `grep: /usr/(local/)?(include|lib)|x86_64-linux-gnu|/home/` in `CMakeLists.txt` and `*.cmake` (the toolchain file excepted). *Severity:* Major. *Source:* cv-kit; mD C++ 08.
- **CPP-EDGE-32** [MUST NOT] Use `-march=native`, `-mcpu=native` or `-mtune=native` in shipped builds; the target ISA is spelled out per device in the toolchain file or preset. Native tuning is allowed only in local benchmark builds that are never shipped. *Why:* a binary built on one board may use instructions another board of the same product line lacks, and dies with SIGILL. *Check:* `grep: (march|mcpu|mtune)=native`. *Severity:* Critical. *Source:* cv-kit.
- **CPP-EDGE-33** [PREFER] Pure compute functions on a hot path (preprocess kernels, NMS, decoding) are annotated through a portability macro that expands to `[[clang::nonblocking]]` (or `[[clang::nonallocating]]`) under clang and to nothing under GCC, and a clang-tidy or clang job runs with `-Wfunction-effects`. *Why:* verified with clang-tidy 23 that this flags `push_back`, `new`/`delete` and `std::lock_guard` inside an annotated function and passes a plain loop; g++ warns on the raw attribute (`-Wattributes`, an error under `-Werror`), hence the macro. *Check:* clang-tidy `clang-diagnostic-function-effects` once the project enables it (see Per-project settings); manual otherwise. *Severity:* Minor. *Source:* cv-kit.

## CPP-RES Resources, RAII and ownership

- **CPP-RES-1** [MUST] (EDGE) Tie every acquired resource (heap block, file descriptor, `FILE*`, `mmap` region, socket, lock, CUDA buffer or stream, TensorRT object, V4L2 buffer, EGL image) to an owning object whose destructor releases it; a function body never pairs acquire and release calls by hand, so every early `return` on an error path releases what was acquired before it, with no per-branch cleanup and no `goto` cleanup chain (a scope guard is the stopgap: CPP-RES-20). *Why:* status-propagating early returns skip hand-written cleanup, and a slow leak kills a process that runs for weeks. *Check:* clang-tidy `cppcoreguidelines-owning-memory`, `clang-analyzer-cplusplus.NewDeleteLeaks`, `clang-analyzer-unix.Malloc`; `grep: cudaMalloc|cudaFree|fopen|fclose|\bmmap\(|munmap|\bopen\(|\bclose\(`; clang-tidy `cppcoreguidelines-avoid-goto`; ASan (LeakSanitizer) on error-path tests. *Severity:* Critical. *Source:* CG P.8, R.1, C.31, E.6, E.13, E.18, E.25, NR.6; Google "Ownership and Smart Pointers"; mD C++ 04.
- **CPP-RES-2** [MUST] (EDGE) Wrap each vendor or OS C handle type in one small owning type (a move-only class, or `std::unique_ptr` with a custom deleter) and let the rest of the code use only that wrapper; keep `extern "C"` calls and raw handles inside the wrapper's `.cc`, and give the wrapper a C++ interface (RAII handles, spans, the project status). Code that must also compile as C keeps to the common subset and is built as C++ as well. *Why:* one audited place per handle kind means one place to get release order, error codes and moves right. *Check:* manual; `grep:` raw handle types (`cudaStream_t`, `nvinfer1::I`, `int fd`, `FILE\*`, `EGLImage`) outside wrapper files. *Severity:* Major. *Source:* CG CPL.1, CPL.2, CPL.3, P.11, I.30, C.31; cv-kit.
- **CPP-RES-3** [MUST NOT] Let a raw pointer `T*` or a reference `T&` own anything: no `delete` through a plain pointer outside a resource-handle implementation, never `delete &ref`, and never return freshly allocated memory as `T*`. *Why:* nothing in the type tells the caller to free it, so it either leaks or is freed twice. *Check:* clang-tidy `cppcoreguidelines-owning-memory`; `grep: return new\b|delete\s*&`. *Severity:* Critical. *Source:* CG R.3, R.4, I.11, F.22, F.42, GSL.view; Google "Ownership and Smart Pointers".
- **CPP-RES-4** [MUST NOT] Write naked `new`, `delete`, `new[]` or `delete[]` in application code; create heap objects with `std::make_unique`, keep sequences in containers, and keep any explicit `new` inside one allocator or factory function. Allocation failure: CPP-ERR-14. *Why:* every hand-written `delete` is a leak or double free waiting for the next early return; under `-fno-exceptions` a failing plain `new` aborts. *Check:* clang-tidy `cppcoreguidelines-owning-memory`, `modernize-make-unique`, `modernize-make-shared`; `grep: \bnew\b|\bdelete\b`. *Severity:* Major. *Source:* CG R.11, ES.60, ES.24, C.149, C.150, R.23; Google "Ownership and Smart Pointers"; mD C++ 04.
- **CPP-RES-5** [MUST] Give the result of an explicit acquisition to its owner in the same statement, and perform at most one explicit acquisition per expression statement. *Why:* anything between acquire and adopt, or two acquisitions with unspecified argument order, can leak. *Check:* `grep: new .*new ` on one line; manual. *Severity:* Major. *Source:* CG R.12, R.13.
- **CPP-RES-6** [MUST NOT] Use `malloc`, `calloc`, `realloc` or `free` for C++ objects, or mix them with `new`/`delete`; memory a C API insists on (for example `posix_memalign` for a DMA-aligned buffer) lives in a handle whose deleter calls the matching C free. *Why:* `malloc` runs no constructor and `free` no destructor, and mixing allocators is undefined. *Check:* clang-tidy `cppcoreguidelines-no-malloc`, `clang-analyzer-unix.Malloc`, `clang-analyzer-unix.MismatchedDeallocator`. *Severity:* Critical. *Source:* CG R.10, P.11; mD C++ 04.
- **CPP-RES-7** [MUST] Release with the form that matches the acquisition: `delete[]` for `new[]`, the library's own free function for its allocations, `std::unique_ptr<T[]>` (not `unique_ptr<T>`) for arrays, a custom deleter for C and CUDA handles. *Why:* a mismatched release is undefined behaviour that usually corrupts the heap later, far from the bug. *Check:* g++ `-Wmismatched-new-delete`; clang-tidy `clang-analyzer-unix.MismatchedDeallocator`, `bugprone-unique-ptr-array-mismatch`, `bugprone-shared-ptr-array-mismatch`; ASan (alloc-dealloc-mismatch). *Severity:* Critical. *Source:* CG ES.61; mD C++ 04.
- **CPP-RES-8** [MUST] Express exclusive ownership of a heap object with `std::unique_ptr`: factories of polymorphic types return it, and a function that takes ownership accepts it by value. When the type is not polymorphic and is cheap to move, return the object itself by value instead. *Why:* the type then documents and enforces the transfer, at zero size cost over a raw pointer. *Check:* clang-tidy `cppcoreguidelines-owning-memory`; manual. *Severity:* Major. *Source:* CG R.20, R.21, R.32, F.26, I.11; Google "Ownership and Smart Pointers".
- **CPP-RES-9** [MUST NOT] (EDGE) Use `std::shared_ptr` unless ownership is genuinely shared between owners whose lifetimes cannot be ordered, and say why in a comment; when sharing is justified, share immutable data (`std::shared_ptr<const T>`). A single owner that outlives every user (for example a pipeline object that joins its workers) is the default. *Why:* each copy is an atomic increment and decrement, destruction happens on whichever thread drops the last reference, and cycles leak. *Check:* `grep: shared_ptr<`; manual. *Severity:* Major. *Source:* CG R.21, F.27, CP.32; Google "Ownership and Smart Pointers".
- **CPP-RES-10** [PREFER] Create shared objects with `std::make_shared` (one allocation for object and count), except when long-lived `std::weak_ptr`s would keep a large buffer's memory pinned after the last owner is gone. *Why:* fewer allocations and better locality; the exception avoids a hidden memory hold. *Check:* clang-tidy `modernize-make-shared`. *Severity:* Minor. *Source:* CG R.22, C.151; mD C++ 04.
- **CPP-RES-11** [MUST] Break reference cycles among `shared_ptr` owners (parent links, observer lists, callbacks that capture their owner) with `std::weak_ptr`, or with a non-owning raw pointer whose target provably outlives it. *Why:* a cycle is never freed, which is a leak in a long-running process. *Check:* manual. *Severity:* Critical. *Source:* CG R.24; mD C++ 04.
- **CPP-RES-12** [MUST] (EDGE) Take a smart pointer as a parameter only when the function takes part in the object's lifetime, and pick the form that says how: `unique_ptr<T>` by value takes ownership; `unique_ptr<T>&` may replace the pointee; `shared_ptr<T>` by value keeps a share (and moves it into storage); `shared_ptr<T>&` may reseat the caller's pointer; `const shared_ptr<T>&` may or may not keep a share. A function that only uses the object takes `T&`, `const T&` or `T*`. The same holds for third-party smart pointers. *Why:* a smart-pointer parameter claims an ownership role and costs refcount traffic for nothing when it only reads. *Check:* clang-tidy `performance-unnecessary-value-param`; manual. *Severity:* Major. *Source:* CG F.7, R.30, R.31, R.32, R.33, R.34, R.35, R.36; Google "Ownership and Smart Pointers".
- **CPP-RES-13** [MUST] Before passing `*p` or `p.get()` from a smart pointer that another thread or the callee itself could reset (a member, a global, a model or config swapped at run time), copy the smart pointer into a local and pass from the local. *Why:* the object can be destroyed mid-call while the callee still uses it. *Check:* manual. *Severity:* Critical. *Source:* CG R.37.
- **CPP-RES-14** [PREFER] (EDGE) Use a local, a member or a `std::optional` member instead of a heap object that is created and destroyed in one scope; buffers too large for a worker stack go into members or arenas allocated once at setup (per-frame allocation rules: see CPP-EDGE). *Why:* scoped heap use costs an allocation for nothing; big frames on the stack overflow small thread stacks. *Check:* manual. *Severity:* Minor. *Source:* CG R.5; mD C++ 04.
- **CPP-RES-15** [MUST NOT] (EDGE) Put variable-length arrays or large objects (rule of thumb: more than a few KiB) on the stack of worker threads, or recurse with depth driven by image data. *Why:* edge thread stacks are often 64-256 KiB and an overflow is a crash with no error path. *Check:* g++ `-Wvla` (through `-Wpedantic`); manual. *Severity:* Critical. *Source:* CG ES.27, R.5; mD C++ 02, 04.
- **CPP-RES-16** [MUST] A class that defines its own `operator new` also defines the matching `operator delete` (and the reverse); to forbid one, `= delete` it explicitly. *Why:* a pool allocator paired with the global deallocator corrupts both. *Check:* clang-tidy `misc-new-delete-overloads`. *Severity:* Major. *Source:* CG R.15.
- **CPP-RES-17** [MUST] Treat raw pointer and reference data members as non-owning observers and document which object outlives which; owned members are values, containers or `std::unique_ptr`. A class that still holds an owning raw pointer needs a destructor and all five special members (CPP-CLS-11), and should be converted. *Why:* a raw member that silently owns leaks or double-frees on copy. *Check:* clang-tidy `cppcoreguidelines-owning-memory`, `cppcoreguidelines-special-member-functions`; manual. *Severity:* Major. *Source:* CG C.32, C.33, C.31.
- **CPP-RES-18** [MUST NOT] Call `std::unique_ptr::release()` except to hand the raw pointer to an API that takes ownership, in the same statement; use `reset()` to destroy early. *Why:* a dropped `release()` result is a leak. *Check:* clang-tidy `bugprone-unused-return-value`, `misc-uniqueptr-reset-release`, `readability-uniqueptr-delete-release`. *Severity:* Major. *Source:* cv-kit; CG R.3.
- **CPP-RES-19** [MUST NOT] (EDGE) Keep a pointer, reference, iterator, `span` or view into a container across an operation that may reallocate or erase it (`push_back`, `emplace_back`, `insert`, `resize`, `reserve`, `erase`, rehash of unordered containers), or into a frame or tensor buffer that is recycled for the next frame. *Why:* invalidated views read freed or overwritten memory, giving wrong output or crashes that appear only under load. *Check:* ASan (heap-use-after-free); clang-tidy `bugprone-dangling-handle` (partial); manual. *Severity:* Critical. *Source:* CG ES.65, Lifetime.1; mD C++ 04, 05.
- **CPP-RES-20** [PREFER] Until a dedicated owning type exists, release on scope exit with a scope guard (`absl::Cleanup` or a small project `ScopeExit`), never with `goto cleanup` blocks or repeated release calls on every return path. *Why:* the guard runs on every exit, including the early returns of status propagation. *Check:* clang-tidy `cppcoreguidelines-avoid-goto`; manual. *Severity:* Major. *Source:* CG GSL.util (`finally`), ES.76, E.19; cv-kit.
- **CPP-RES-21** [PREFER] (EDGE) Give `std::unique_ptr` a stateless deleter type (an empty struct with `operator()`) rather than a function pointer. *Why:* a function-pointer deleter doubles the handle size and adds an indirect call per release. *Check:* `grep: unique_ptr<[^>]*,\s*(void|decltype)\s*\(\*`; manual. *Severity:* Minor. *Source:* cv-kit.
- **CPP-RES-22** [PREFER] Where an owning raw pointer cannot be avoided (inside a resource handle, at a C ABI), mark it with `gsl::owner<T*>` and keep it private. *Why:* clang-tidy's owning-memory analysis tracks the annotation, and readers see the ownership. *Check:* clang-tidy `cppcoreguidelines-owning-memory`. *Severity:* Minor. *Source:* CG GSL.view (`owner`), R.3, I.11.

## CPP-CONC Concurrency

- **CPP-CONC-1** [MUST] (EDGE) Write every function as if it will be called from several threads: no mutable function-local `static` (caches, scratch buffers, counters) and no mutable namespace-scope or static member variables for program state; per-stream state lives in an object the caller owns, one per camera stream or thread. A mutable global that must exist (a `constinit` atomic counter, a signal flag) carries a comment saying why (CPP-DOC-13). *Why:* the static buffer in a helper races the moment a second stream is added. *Check:* clang-tidy `cppcoreguidelines-avoid-non-const-global-variables`, `concurrency-mt-unsafe`; `grep: ^\s+static\s+[^c(]` inside function bodies; manual. *Severity:* Critical. *Source:* CG CP.1, I.2, R.6; Google "Nonmember, Static Member, and Global Functions"; mD C++ 02, 07.
- **CPP-CONC-2** [MUST NOT] Allow a data race: an object written by one thread and accessed by another is either a `std::atomic` or guarded by the same mutex at every access. Containers allow concurrent `const` use only; any modification, including `std::map::operator[]` (which inserts), needs exclusion. *Why:* a data race is undefined behaviour, and the optimiser may hoist loads or turn a range check into a wild jump. *Check:* TSan; clang-tidy `clang-diagnostic-thread-safety-analysis` (needs the annotations of CPP-CONC-9); manual. *Severity:* Critical. *Source:* CG CP.2; Google "Use of const"; mD C++ 05, 07.
- **CPP-CONC-3** [MUST] Lock a mutex only through an RAII guard (`std::scoped_lock`, or `std::unique_lock` when the lock must be released early or passed to a condition variable); never call `lock()` and `unlock()` by hand. *Why:* every early return on an error status would otherwise leave the mutex locked. *Check:* `grep: \.(un)?lock\(\)`; clang-tidy `clang-diagnostic-thread-safety-analysis` (with annotations). *Severity:* Critical. *Source:* CG CP.20; mD C++ 07.
- **CPP-CONC-4** [MUST] Give every RAII object a name (`std::scoped_lock lock(mu_);`, `ScopeExit guard(...)`): an unnamed temporary is destroyed at the end of the statement, and `std::unique_lock<std::mutex>(mu_);` declares a new unlocked variable called `mu_`. *Why:* both compile and leave the critical section unprotected. *Check:* clang-tidy `bugprone-unused-raii`; g++ `-Wshadow`. *Severity:* Critical. *Source:* CG CP.44, ES.84; mD C++ 07.
- **CPP-CONC-5** [MUST] Acquire several mutexes in one `std::scoped_lock lock(a, b);`, never as nested guards on different mutexes. *Why:* two threads taking the same pair in different orders deadlock. *Check:* clang-tidy `modernize-use-scoped-lock`; TSan (lock-order-inversion). *Severity:* Critical. *Source:* CG CP.21; mD C++ 07.
- **CPP-CONC-6** [MUST] (EDGE) Hold a lock only around the shared-state access, in its own block: copy, move or swap the item out under the lock and do the work after releasing it. Never call callbacks, virtual functions, user lambdas, blocking I/O or logging sinks while holding a lock (inference and heavy kernels under a lock: CPP-EDGE-8). *Why:* foreign code under a lock can re-enter, block or take other locks, which stalls the camera thread or deadlocks. *Check:* clang-tidy `clang-analyzer-unix.BlockInCriticalSection`; manual. *Severity:* Critical. *Source:* CG CP.22, CP.43.
- **CPP-CONC-7** [MUST NOT] Use `std::recursive_mutex` to make re-entrant calls under a lock work; restructure so that callbacks run outside the lock (CPP-CONC-6). *Why:* recursive locking hides the re-entrancy that breaks the invariant. *Check:* `grep: recursive_mutex`. *Severity:* Major. *Source:* CG CP.22; cv-kit.
- **CPP-CONC-8** [MUST] (EDGE) Wait on a condition variable only with a predicate (`cv_.wait(lock, [&] { return !queue_.empty() || stop_; })`), include a stop flag in the predicate, and change the state the predicate reads while holding the same mutex before notifying, even when that state is an atomic. *Why:* a bare wait wakes spuriously, and a state change made outside the mutex between the check and the block loses the wakeup, freezing the pipeline. *Check:* clang-tidy `bugprone-spuriously-wake-up-functions` (catches waits under an `if` only); `grep: \.wait(_for|_until)?\(\s*\w+\s*(,[^,)]*)?\)`; TSan. *Severity:* Critical. *Source:* CG CP.42; mD C++ 07.
- **CPP-CONC-9** [MUST] Declare each mutex next to the data it protects and annotate the pairing (`ABSL_GUARDED_BY(mu_)` or a project `CVK_GUARDED_BY`) so clang's thread-safety analysis checks every access. *Why:* the pairing then lives in the code, not in a reviewer's memory. *Check:* clang-tidy `clang-diagnostic-thread-safety-analysis` (the shipped config passes `-Wthread-safety`; the project's annotation macro expands to nothing under GCC). *Severity:* Major. *Source:* CG CP.50, CP.9.
- **CPP-CONC-10** [MUST] Make everything a thread or task uses outlive it: a thread joined in the creating scope may use that scope's locals; work that outlives its creator owns what it needs (moved in) or uses objects whose owner joins it first; an argument passed with `std::ref` is not touched by the caller until after the join, unless locked. *Why:* otherwise the thread reads a destroyed stack frame. *Check:* manual. *Severity:* Critical. *Source:* CG CP.23, CP.24, F.53; mD C++ 07.
- **CPP-CONC-11** [MUST NOT] (EDGE) Use `volatile` for communication between threads (stop flags, ready bits, counters); use `std::atomic`. `volatile` is for memory-mapped hardware registers and lives only in a hardware-abstraction directory. *Why:* `volatile` gives no atomicity and no ordering; it appears to work on x86 and fails on ARM's weaker memory model. *Check:* `grep: \bvolatile\b`. *Severity:* Critical. *Source:* CG CP.8, CP.200, CP.111; mD C++ 07.
- **CPP-CONC-12** [MUST] (EDGE) Use the default `memory_order_seq_cst` for atomics. A weaker order (`relaxed` for a pure statistics counter, `acquire`/`release` for publishing data) needs a comment naming the paired operation, a reviewer who owns the concurrency design, and a stress test on the ARM target. *Why:* x86 hides most ordering bugs that Jetson and phone cores expose. *Check:* `grep: memory_order_(relaxed|acquire|release|acq_rel|consume)`; TSan; manual. *Severity:* Critical. *Source:* CG CP.100, CP.101, CP.102; mD C++ 07.
- **CPP-CONC-13** [MUST] Treat an atomic as protecting one object, not an invariant: check-then-act sequences and updates that span several variables take a lock or are a single read-modify-write (`fetch_add`, a `compare_exchange_weak` loop). *Why:* `if (n.load() > 0) n.store(n - 1);` races even though `n` is atomic. *Check:* manual. *Severity:* Critical. *Source:* CG CP.2; mD C++ 07.
- **CPP-CONC-14** [MUST NOT] Hand-write lock-free data structures (CAS-linked lists, custom ring buffers with relaxed indices) unless a measurement shows the lock is the bottleneck; use a vetted library queue. *Why:* lock-free code is subtle (ABA, ordering) and its bugs are rare, silent and target-specific. *Check:* `grep: compare_exchange_(weak|strong)`; manual. *Severity:* Major. *Source:* CG CP.100, CP.102.
- **CPP-CONC-15** [MUST] Do one-time initialisation with a function-local static (thread-safe since C++11; the build must not use `-fno-threadsafe-statics`) or `std::call_once`; never hand-roll double-checked locking on a plain or `volatile` flag. What the static may hold (trivially destructible or deliberately never destroyed): see CPP-HDR-29 and CPP-HDR-32. *Why:* hand-rolled double-checked locking publishes a half-built object. *Check:* `grep: fno-threadsafe-statics` in build files; manual. *Severity:* Critical. *Source:* CG CP.110, CP.111; Google "Static and Global Variables".
- **CPP-CONC-16** [MUST NOT] (EDGE) Use `std::async`, `std::promise` or `std::packaged_task` in edge code; submit work to the project work queue. Errors cross threads as values: queues, completion handles and stage outputs carry the project result type, and a worker's failure reaches the owning pipeline object (stage status, error counter, stop request). *Why:* `std::async` starts an OS thread per call with no pool, the future it returns blocks in its destructor when discarded, and under `-fno-exceptions` a failed thread start, a broken promise or a second `get()` aborts. *Check:* `grep: std::async|std::promise|std::packaged_task|set_exception`; clang-tidy `bugprone-unused-return-value` (discarded `std::async`). *Severity:* Major. *Source:* CG CP.60, CP.61; mD C++ 07; cv-kit.
- **CPP-CONC-17** [MUST] Use coroutines only through a library approved for the project: no custom promise or awaitable types, coroutine lambdas capture nothing, coroutine parameters are taken by value, no lock or guard is held across `co_await` / `co_yield`, and (EDGE) no coroutine runs in a per-frame real-time path (its frame is usually heap-allocated). *Why:* captures and reference parameters dangle after the first suspension, and a lock held across a suspension may be released on another thread. *Check:* clang-tidy `cppcoreguidelines-avoid-capturing-lambda-coroutines`, `cppcoreguidelines-avoid-reference-coroutine-parameters`, `cppcoreguidelines-no-suspend-with-lock`, `misc-coroutine-hostile-raii`; `grep: \bco_(await|yield|return)\b|promise_type|await_(ready|suspend|resume)`. *Severity:* Critical. *Source:* CG CP.51, CP.52, CP.53; Google "Coroutines".
- **CPP-CONC-18** [MUST] A signal handler only sets a lock-free `std::atomic<bool>` (or a `volatile std::sig_atomic_t`) stop flag; normal threads poll it and shut down by joining. *Why:* almost nothing is async-signal-safe, including locks, allocation and logging. *Check:* clang-tidy `bugprone-signal-handler`. *Severity:* Critical. *Source:* CG CP.201; cv-kit.
- **CPP-CONC-19** [MUST] (EDGE) Test every change to threaded code under TSan on a host build (for example with recorded frames) and stress it on the ARM target; a concurrency change without such a test is a finding. *Why:* races rarely show in a single run, and x86 hardware hides ordering bugs. *Check:* TSan. *Severity:* Major. *Source:* CG CP.9, CP.101.
- **CPP-CONC-20** [PREFER] (EDGE) Use `std::shared_mutex` only when measured read contention justifies it; for a "latest frame" or "current model" slot, swap a pointer under a plain mutex, double-buffer, or publish a `std::shared_ptr<const T>` with `std::atomic<std::shared_ptr<const T>>`. *Why:* reader-writer locks cost more than plain mutexes for short critical sections. *Check:* manual. *Severity:* Minor. *Source:* mD C++ 07; cv-kit.
- **CPP-CONC-21** [PREFER] (EDGE) Use an explicit worker pool, OpenMP or a vendor library for data parallelism rather than `std::execution::par`. *Why:* libstdc++'s parallel algorithms need TBB, which cross toolchains usually lack, and give no control over core placement. *Check:* `grep: std::execution::par`. *Severity:* Minor. *Source:* cv-kit.

## CPP-EXPR Expressions, statements, declarations and types

- **CPP-EXPR-1** [MUST] Give every variable the smallest scope that works: declare it right before first use, inside the `if`/`switch`/`for` init-statement when it is only used there, and move long-lived locals into a helper function. Exception (EDGE): an object whose construction allocates (vector, string, `cv::Mat`, scratch tensor) is created once outside a per-frame or per-pixel loop and reused (CPP-EDGE-3). *Why:* small scopes shorten how long locks, files and buffers are held and how far a stale value can travel. *Check:* manual. *Severity:* Minor. *Source:* CG ES.5, ES.6, ES.21, ES.74; Google "Local Variables"; mD C++ 01, 09.
- **CPP-EXPR-2** [MUST] Initialise every variable where it is defined; instead of declaring and then assigning in branches, compute the value in a helper or an immediately invoked lambda so it can be `const`. A large scratch buffer that is filled on the very next line may stay uninitialised, with a comment. *Why:* reading an uninitialised scalar or pointer is undefined behaviour and the most common crash in tutorial-derived code. *Check:* clang-tidy `cppcoreguidelines-init-variables`; g++ `-Wuninitialized`, `-Wmaybe-uninitialized`. *Severity:* Critical. *Source:* CG ES.20, ES.22, ES.28, Type.5; Google "Local Variables"; mD C++ 01, 04.
- **CPP-EXPR-3** [MUST] Declare one name per declaration (`int a = 0;` and `int* b = nullptr;` on separate lines); structured bindings are the exception. *Why:* `int* a, b;` makes only `a` a pointer. *Check:* clang-tidy `readability-isolate-declaration` (clang-format does not split such declarations). *Severity:* Minor. *Source:* CG ES.10, NL.21; mD C++ 01.
- **CPP-EXPR-4** [MUST NOT] Shadow a name from an enclosing scope, a data member or a base class. *Why:* the inner name silently wins and the outer one is never updated. *Check:* g++ `-Wshadow`. *Severity:* Major. *Source:* CG ES.12; mD C++ 07.
- **CPP-EXPR-5** [MUST] Give each variable one meaning; do not recycle a variable for an unrelated purpose. A scratch buffer deliberately reused across iterations to keep its capacity is the exception: scope it tightly and clear it before each reuse. *Why:* recycled names carry stale values into new logic. *Check:* manual. *Severity:* Minor. *Source:* CG ES.26.
- **CPP-EXPR-6** [PREFER] Use brace initialisation where a narrowing conversion must be rejected (arithmetic conversions such as `int64_t{count}`, aggregates) (container sizes versus element lists: CPP-LIB-15); never write `auto x{...}` or `auto x = {...}`. *Why:* braces turn silent narrowing into a compile error; `auto` with braces deduces `std::initializer_list`. *Check:* g++ `-Wnarrowing` (an error inside braces); manual. *Severity:* Minor. *Source:* CG ES.23, ES.64, T.68; Google "Casting".
- **CPP-EXPR-7** [MUST] Use designated initialisers only in C++20 form, with fields in declaration order (skipping is fine). *Why:* other forms are extensions and do not build on every toolchain. *Check:* compiler (g++ 13 rejects out-of-order designators). *Severity:* Minor. *Source:* Google "Designated Initializers".
- **CPP-EXPR-8** [MUST] Use `std::array` (or a fixed-capacity container) for fixed-size and `std::vector` for variable-size sequences, never C arrays or `new[]`, static tables included (`constexpr std::array<float, 9> kSobelX = {...};`); no variable-length arrays. *Why:* C arrays decay to pointers and lose their size at the first function call. *Check:* clang-tidy `modernize-avoid-c-arrays` (alias `cppcoreguidelines-avoid-c-arrays`); g++ `-Wvla` (through `-Wpedantic`). *Severity:* Major. *Source:* CG ES.27, Bounds.3, R.14, SL.con.1, SL.con.2; mD C++ 01, 04.
- **CPP-EXPR-9** [MUST] Use `auto` only when it helps the reader: the type is visible in the initialiser (`std::make_unique<T>`, a cast), it is noise (iterators), or it is required (lambdas, structured bindings); otherwise spell the type. Write `auto&` / `const auto&` / `auto*` whenever a reference or pointer is meant. *Why:* `auto x = v[i];` copies the element, and hidden types slow review. *Check:* clang-tidy `modernize-use-auto` (iterators, casts and `new` only, as configured), `readability-qualified-auto`, `performance-unnecessary-copy-initialization`; manual. *Severity:* Minor. *Source:* CG ES.11, T.12; Google "Type Deduction (including auto)".
- **CPP-EXPR-10** [MUST NOT] Write `decltype(auto)` where a plain type or `auto` works. *Why:* its reference-or-value result is easy to get wrong and can dangle. *Check:* `grep: decltype\(auto\)`. *Severity:* Minor. *Source:* Google "Type Deduction (including auto)".
- **CPP-EXPR-11** [PREFER] Use structured bindings for map entries and struct returns, with a `/*field=*/` comment when a binding's name differs from the field. *Why:* named elements instead of `.first`/`.second`, and no accidental copy of `pair<const K, V>`. *Check:* clang-tidy `performance-for-range-copy`; manual. *Severity:* Minor. *Source:* Google "Type Deduction (including auto)".
- **CPP-EXPR-12** [MUST] (EDGE) Make every local, reference and pointee that does not change after initialisation `const` (by-value parameters and returned locals excepted); do not put `const` on by-value parameters in declarations. *Why:* readers need not scan for writes, and const data can be shared across threads without locks. *Check:* clang-tidy `misc-const-correctness`, `readability-avoid-const-params-in-decls`. *Severity:* Minor. *Source:* CG Con.1, Con.4, ES.25, P.10; Google "Use of const".
- **CPP-EXPR-13** [MUST] (EDGE) Member functions are `const` unless they change the object's observable state, and `const` member functions must be safe to call concurrently: a `mutable` cache filled in a `const` method needs a mutex or an atomic, or the class is documented as not thread-safe. *Why:* the standard library and every reader assume concurrent `const` calls are safe. *Check:* clang-tidy `readability-make-member-function-const`; manual for `mutable`. *Severity:* Major. *Source:* CG Con.2; Google "Use of const".
- **CPP-EXPR-14** [MUST] Take pointer and reference parameters as pointer- or reference-to-`const` unless the function writes through them; input frames are `const Frame&` or `std::span<const std::uint8_t>`. *Why:* the signature then proves which arguments are read-only. *Check:* clang-tidy `readability-non-const-parameter`, `misc-const-correctness`. *Severity:* Minor. *Source:* CG Con.3; Google "Use of const".
- **CPP-EXPR-15** [MUST] (EDGE) Replace unexplained literals (input sizes, mean/std, thresholds, anchor sizes, class counts) with named constants, and use `constexpr` for values known at compile time (`inline constexpr` in headers, CPP-HDR-15) and `constinit` for non-const statics that must be constant-initialised. *Why:* the same `640` in five places drifts apart, and `constexpr` values live in read-only data, cost no start-up time and cannot race. *Check:* `grep: ^\s*(static\s+)?const\s+(int|float|double|u?int\d+_t)\s+k\w+\s*=` (candidates); manual (`readability-magic-numbers` is off: too noisy in kernels). *Severity:* Minor. *Source:* CG Con.5, Per.11, ES.45; Google "Use of constexpr, constinit, and consteval".
- **CPP-EXPR-16** [MUST NOT] Use `const_cast` to gain write access. The one allowed use is passing a pointer to a const-incorrect C API that does not write through it, inside that API's wrapper, with a NOLINT; share const and non-const accessor code with a private template helper. *Why:* writing to an object defined `const` is undefined behaviour. *Check:* clang-tidy `cppcoreguidelines-pro-type-const-cast`. *Severity:* Major. *Source:* CG ES.50, Type.3, Con.3; Google "Casting".
- **CPP-EXPR-17** [MUST NOT] Write C-style casts `(T)x`, or functional casts `T(x)` to a non-class type; `(void)expr` to discard a value and `T(x)` for a class type are allowed. *Why:* a C cast silently picks `reinterpret_cast` or `const_cast` when `static_cast` fails. *Check:* g++ `-Wold-style-cast`; clang-tidy `cppcoreguidelines-pro-type-cstyle-cast`, `google-readability-casting`. *Severity:* Minor. *Source:* CG ES.48, ES.49, ES.64, Type.4; Google "Casting".
- **CPP-EXPR-18** [MUST] Choose the weakest conversion that is correct: an implicit conversion or brace initialisation for safe widening, `static_cast` for value conversions and for audited downcasts (CPP-ERR-17), `reinterpret_cast` only for pointer/integer conversions at hardware or driver boundaries; never a cast to the type a value already has. *Why:* every stronger cast switches off a check. *Check:* clang-tidy `readability-redundant-casting`; g++ `-Wuseless-cast`. *Severity:* Minor. *Source:* CG ES.48, ES.49, Type.1, Type.1.3, Type.1.4; Google "Casting".
- **CPP-EXPR-19** [MUST NOT] (EDGE) Read an object as an unrelated type through `reinterpret_cast`, a pointer cast via `void*`, or a union; copy the bits with `std::bit_cast` (values) or `std::memcpy` (buffers) after checking size and alignment. Inspecting bytes through `unsigned char*` or `std::byte*` is fine. *Why:* this breaks strict aliasing (the optimiser may drop or reorder the reads) and can fault on misaligned loads on ARM. *Check:* clang-tidy `cppcoreguidelines-pro-type-reinterpret-cast`, `cppcoreguidelines-pro-type-union-access`, `bugprone-casting-through-void`, `bugprone-bitwise-pointer-cast`; g++ `-Wcast-align=strict` (GCC builds). g++ `-O2 -Wall` stays silent on a typical pun, so the linter and review are the real check. *Severity:* Critical. *Source:* CG Type.1.1, ES.48, C.183, Per.4; Google "Casting"; cv-kit.
- **CPP-EXPR-20** [MUST NOT] (EDGE) Rely on implicit narrowing (floating to integer, 64-bit to 32-bit, signed to unsigned, `double` to `float`); write the conversion with `static_cast` after a range check, or with a project checked-narrow helper that returns `std::optional`. Never use `gsl::narrow`, which aborts under `-fno-exceptions`. *Why:* silent truncation gives wrong sizes, wrong indices and wrong quantised values. *Check:* g++ `-Wconversion`, `-Wsign-conversion`, `-Wfloat-conversion`; clang-tidy `cppcoreguidelines-narrowing-conversions` (alias `bugprone-narrowing-conversions`). *Severity:* Major. *Source:* CG ES.46, P.4, GSL.util (`narrow`, `narrow_cast`); Google "Integer Types".
- **CPP-EXPR-21** [MUST] (EDGE) Convert floating to integer only with an explicit rounding choice (`std::lround`, `std::floor` then cast) and a range check first, as in quantisation and coordinate conversion. *Why:* converting an out-of-range or NaN float to an integer is undefined, and truncation toward zero shifts boxes and quantised values. *Check:* clang-tidy `bugprone-incorrect-roundings`; UBSan `-fsanitize=float-cast-overflow` (GCC leaves it out of `-fsanitize=undefined`; see Per-project settings). *Severity:* Critical. *Source:* CG ES.46; cv-kit.
- **CPP-EXPR-22** [MUST] (EDGE) Pick integer types by role: `int` for small counts and loop counters; `int64_t` or `ptrdiff_t` for sizes, byte counts and indices that can reach 2^31; exact-width `<cstdint>` types (`uint8_t`, `int8_t`, `int16_t`, `int32_t`, with `float`) for tensor elements, pixels, file and wire formats and structs shared with device code (byte counts: CPP-EXPR-25; pixel `char`: CPP-EXPR-27). Do not spell `short`, `long`, `long long` or `unsigned int`. *Why:* `long` is 32 bits on ARMv7 and 64 on AArch64, and `w*h*c*batch` exceeds `int`. *Check:* clang-tidy `google-runtime-int`; g++ `-Wconversion -Wsign-conversion`; manual. *Severity:* Major. *Source:* Google "Integer Types"; CG ES.102, ES.103, ES.107; cv-kit.
- **CPP-EXPR-23** [MUST NOT] Use an unsigned type to say "never negative"; unsigned types are for bit patterns, masks, intended modular arithmetic and fixed-width pixel or quantised storage. *Why:* unsigned arithmetic hides a negative intermediate as a huge positive value instead of failing visibly. *Check:* g++ `-Wsign-conversion`; manual. *Severity:* Major. *Source:* CG ES.101, ES.102, ES.106, I.6; Google "Integer Types".
- **CPP-EXPR-24** [MUST NOT] Mix signed and unsigned operands in arithmetic or comparison (`int i < v.size()`); convert once (`std::ssize(v)`) or compare with `std::cmp_less`. *Why:* the signed operand is converted to unsigned, so `-1 < v.size()` is false. *Check:* g++ `-Wsign-compare`, `-Wsign-conversion`; clang-tidy `modernize-use-integer-sign-comparison`. *Severity:* Major. *Source:* CG ES.100, ES.107; Google "Integer Types".
- **CPP-EXPR-25** [MUST] (EDGE) Prevent integer overflow: widen before multiplying (`int64_t{w} * h * c`), check products of untrusted dimensions (header fields, model metadata) with `__builtin_mul_overflow` or a checked helper, and never decrement an unsigned value past zero (write reverse loops with a signed index). *Why:* signed overflow is undefined, and a wrapped byte count under-allocates a buffer. *Check:* clang-tidy `bugprone-implicit-widening-of-multiplication-result`, `bugprone-misplaced-widening-cast`, `bugprone-too-small-loop-variable`; UBSan `-fsanitize=signed-integer-overflow`. *Severity:* Critical. *Source:* CG ES.103, ES.104, ES.107; Google "Integer Types"; mD C++ 01.
- **CPP-EXPR-26** [MUST] Guarantee that every integer divisor and `%` operand is non-zero (a precondition for programmer errors; a returned error for data-dependent zeros such as an empty set or a zero stride, see CPP-ERR), and make integer division inside floating-point formulas visibly intentional. *Why:* division by zero is undefined; `4 / 5` silently yields 0 in a scale factor. *Check:* clang-tidy `clang-analyzer-core.DivideZero`, `bugprone-integer-division`; UBSan `-fsanitize=integer-divide-by-zero`. *Severity:* Critical. *Source:* CG ES.105; mD C++ 01.
- **CPP-EXPR-27** [MUST] (EDGE) Use plain `char` only for text; pixel and quantised data are `uint8_t` / `int8_t`. *Why:* plain `char` is unsigned on ARM Linux and signed on x86, so the same code computes different values. *Check:* clang-tidy `bugprone-signed-char-misuse`. *Severity:* Major. *Source:* CG ES.101; cv-kit.
- **CPP-EXPR-28** [MUST NOT] (EDGE) Use `long double`; the floating types are `float` and `double` (float literals and promotion: CPP-EDGE-15). *Why:* `long double` is 80, 64 or 128 bits depending on the target, so results differ between host and device. *Check:* `grep: \blong\s+double\b`. *Severity:* Major. *Source:* Google "Floating-Point Types".
- **CPP-EXPR-29** [MUST NOT] Read and write (or write twice) the same object without sequencing in one expression (`v[i] = i++`), or depend on the order in which function arguments are evaluated. *Why:* the first is undefined, the second unspecified and different between compilers. *Check:* g++ `-Wsequence-point`; manual. *Severity:* Critical. *Source:* CG ES.43, ES.44.
- **CPP-EXPR-30** [MUST] Keep expressions simple: no assignment inside a condition or subexpression, no `++`/`--` buried in a condition, no chained comparisons (`a < b < c`), no nested conditional operators. *Why:* these hide side effects and misread precedence. *Check:* clang-tidy `bugprone-assignment-in-if-condition`, `bugprone-inc-dec-in-conditions`, `bugprone-chained-comparison`, `readability-avoid-nested-conditional-operator`. *Severity:* Major. *Source:* CG ES.40.
- **CPP-EXPR-31** [MUST] (EDGE) Parenthesise whenever bitwise operators meet comparison or arithmetic (`(flags & kMask) == kMask`) and whenever `&&` and `||` mix. *Why:* `==` binds tighter than `&`, a classic bug in pixel-format and register code. *Check:* g++ `-Wparentheses`; clang-tidy `readability-math-missing-parentheses`. *Severity:* Major. *Source:* CG ES.41.
- **CPP-EXPR-32** [MUST] Write `nullptr` for null pointers (never `0` or `NULL`) and `'\0'` for the null character. *Why:* `0` and `NULL` are integers and pick integer overloads. *Check:* clang-tidy `modernize-use-nullptr`; g++ `-Wzero-as-null-pointer-constant`; `'\0'`: manual. *Severity:* Minor. *Source:* CG ES.47; Google "0 and nullptr/NULL"; mD C++ 04.
- **CPP-EXPR-33** [MUST] Write `sizeof(variable)` when the size belongs to a specific object, `sizeof(Type)` only for formats not tied to a variable, and never apply `sizeof` to a pointer or container to measure its elements. *Why:* `sizeof(var)` follows type changes; `sizeof(ptr)` is 4 or 8. *Check:* clang-tidy `bugprone-sizeof-expression`, `bugprone-sizeof-container`. *Severity:* Major. *Source:* Google "sizeof"; mD C++ 04.
- **CPP-EXPR-34** [PREFER] Write `++i` / `--i` unless the old value is used. *Why:* the postfix form may copy an iterator for nothing. *Check:* `grep: \w(\+\+|--)\s*\)` in `for` headers. *Severity:* Minor. *Source:* Google "Preincrement and Predecrement"; CG P.9.
- **CPP-EXPR-35** [MUST NOT] Dereference a pointer that may be null, dangling or past the end: test a nullable pointer before use, and never form a pointer more than one past the end of an array. *Why:* each of these is undefined and usually a crash on device. *Check:* clang-tidy `clang-analyzer-core.NullDereference`, `clang-analyzer-cplusplus.NewDelete`; g++ `-Wnull-dereference`; ASan. *Severity:* Critical. *Source:* CG ES.65, Lifetime.1, I.12, C.148; mD C++ 04.
- **CPP-EXPR-36** [MUST NOT] (EDGE) Do pointer arithmetic or subscript raw pointers in application code; iterate a `std::span`, use range-for, or use the image view's row accessor. Stride arithmetic lives in one audited view type or SIMD kernel, with a NOLINT (CPP-FN-33). *Why:* raw pointer walks are where buffer overruns come from. *Check:* clang-tidy `cppcoreguidelines-pro-bounds-pointer-arithmetic`, `cppcoreguidelines-pro-bounds-array-to-pointer-decay`; ASan. *Severity:* Major. *Source:* CG ES.42, Bounds.1, Bounds.3, I.13, F.22; mD C++ 04.
- **CPP-EXPR-37** [MUST NOT] Compare (`<`, `>`) or subtract pointers that do not point into the same array or object. *Why:* the result is undefined and the optimiser may assume it never happens. *Check:* ASan `-fsanitize=pointer-compare,pointer-subtract` (with `detect_invalid_pointer_pairs=1`; not in the shipped sanitizer options, see Per-project settings). *Severity:* Critical. *Source:* CG ES.62.
- **CPP-EXPR-38** [MUST] (EDGE) Check bounds once, where data enters an API (sizes against the view, indices against the shape), then index without per-element checks; prefer range-for, algorithms and spans to indexing; never use `.at()` as the check (CPP-ERR-15); hardened standard-library builds in Debug catch the rest (CPP-BUILD-3). *Why:* per-element checks cost per-pixel time, and a missing boundary check is a buffer overrun. *Check:* clang-tidy `cppcoreguidelines-pro-bounds-pointer-arithmetic`; Debug tests with `_GLIBCXX_ASSERTIONS`; manual (`cppcoreguidelines-pro-bounds-constant-array-index` is off because its fix inserts an aborting `gsl::at`). *Severity:* Major. *Source:* CG ES.55, Bounds.2, Bounds.4, P.7, SL.con.3; cv-kit.
- **CPP-EXPR-39** [MUST] Use `std::move` only to hand a named object to a new owner: never on a `const` object (it silently copies), on a returned local (CPP-FN-16) or on a forwarding reference (CPP-FN-9), and do not use an object after moving from it except to assign to or destroy it. *Why:* a misplaced move either copies anyway or leaves an emptied object in use. *Check:* clang-tidy `performance-move-const-arg`, `bugprone-use-after-move`, `bugprone-move-forwarding-reference`. *Severity:* Major. *Source:* CG ES.56; mD C++ 04.
- **CPP-EXPR-40** [PREFER] (EDGE) Use range-for to visit every element, bound by `const auto&` (or `auto&` to modify); use an index loop only when the index itself is needed, with the index declared in the loop header. *Why:* range-for cannot run off the end, and a by-value loop variable copies each element. *Check:* clang-tidy `modernize-loop-convert`, `performance-for-range-copy`, `performance-implicit-conversion-in-loop`. *Severity:* Minor. *Source:* CG ES.71, ES.72, ES.73, ES.55, P.3.
- **CPP-EXPR-41** [MUST NOT] Modify a `for` loop's counter inside the body, or erase from a container while iterating except through the iterator that `erase` returns (`it = v.erase(it)`) or `std::erase_if`. *Why:* both skip or revisit elements and can run off the end. *Check:* manual. *Severity:* Major. *Source:* CG ES.86; mD C++ 05.
- **CPP-EXPR-42** [MUST] A `switch` on an `enum class` lists every enumerator and has no `default:`, so adding an enumerator breaks the build; a `switch` on anything else has a `default:` that handles or reports the unexpected value. Prefer a `switch` to an `if`/`else if` chain when selecting among enumerators. *Why:* a blanket `default` hides the new `PixelFormat` that nobody handled. *Check:* g++ `-Wswitch` (in `-Wall`); clang-tidy `bugprone-switch-missing-default-case`. *Severity:* Major. *Source:* CG ES.70, ES.79, Enum.2; Google "Switch Statements".
- **CPP-EXPR-43** [MUST] End every non-empty `case` with `break`, `return` or `continue`; an intended fallthrough is written `[[fallthrough]];`. *Why:* silent fallthrough runs the next case's code. *Check:* g++ `-Wimplicit-fallthrough`. *Severity:* Major. *Source:* CG ES.78; Google "Switch Statements"; mD C++ 01.
- **CPP-EXPR-44** [MUST NOT] Use `goto`, except a forward jump out of nested loops when extracting a function would be worse; replace `goto cleanup` with RAII (CPP-RES-1, CPP-RES-20). *Why:* jumps skip initialisation and make cleanup paths unreviewable. *Check:* clang-tidy `cppcoreguidelines-avoid-goto`. *Severity:* Major. *Source:* CG ES.76.
- **CPP-EXPR-45** [MUST NOT] Write `do`/`while` loops outside macro bodies (`do { ... } while (0)`); use `while` or `for`. *Why:* the condition sits at the bottom where it is easy to miss, and the first pass skips it. *Check:* clang-tidy `cppcoreguidelines-avoid-do-while` (macro bodies are ignored). *Severity:* Minor. *Source:* CG ES.75.
- **CPP-EXPR-46** [PREFER] Keep `break` and `continue` rare in non-trivial loops; move a search into a function that returns the result. *Why:* several exits make loop invariants hard to see. *Check:* manual. *Severity:* Minor. *Source:* CG ES.77.
- **CPP-EXPR-47** [MUST] Write an intentionally empty body as `{}` with a comment, never a lone `;`. *Why:* `if (x);` and `for (...);` look like bugs because they usually are. *Check:* g++ `-Wempty-body`, clang-tidy `bugprone-suspicious-semicolon` (both catch `if (x);` only); `grep -E '^\s*(for|while)\s*\(.*\)\s*;\s*$'` for loops (clang-format's `InsertBraces` leaves `while (...);` alone). *Severity:* Major. *Source:* CG ES.85, NL.4; Google "Looping and Branching Statements".
- **CPP-EXPR-48** [PREFER] Test pointers and booleans directly (`if (p)`, `if (!done)`) but compare integers explicitly (`if (n != 0)`). *Why:* an integer condition hides whether zero is a count or an error code. *Check:* clang-tidy `readability-implicit-bool-conversion` (pointer conditions allowed), `readability-simplify-boolean-expr`. *Severity:* Minor. *Source:* CG ES.87.
- **CPP-EXPR-49** [PREFER] Remove duplicated logic: give a repeated operation a name (a function, or a named lambda inside one scope), hoist statements shared by branches, and use a standard algorithm (or a well-tested library one) instead of a hand loop or a hand-rolled container. *Why:* duplicated code is fixed in one place and not the other. *Check:* clang-tidy `bugprone-branch-clone`, `misc-redundant-expression`, `readability-use-anyofallof`. *Severity:* Minor. *Source:* CG ES.1, ES.2, ES.3, P.3, F.1, F.10.

## CPP-FN Functions and interfaces

- **CPP-FN-1** [MUST] A function does one logical job that its name states; aim for about 40 lines, and split any function that exceeds the configured `readability-function-size` (80 lines) or `readability-function-cognitive-complexity` (25) thresholds unless a reason is recorded with a NOLINT. *Why:* long, branchy functions hide bugs from review and test, and small ones inline well. *Check:* clang-tidy `readability-function-size`, `readability-function-cognitive-complexity`. *Severity:* Minor. *Source:* CG F.1, F.2, F.3; Google "Write Short Functions".
- **CPP-FN-2** [MUST] Put every input and output in the signature: no global mode switches that change behaviour, no results or errors reported through `errno`-style side channels in project code (`errno` and vendor last-error state: CPP-ERR-20). A global that only controls logging verbosity is acceptable. *Why:* hidden inputs make functions untestable and racy. *Check:* `grep: \berrno\b`; manual. *Severity:* Major. *Source:* CG I.1, F.8.
- **CPP-FN-3** [PREFER] (EDGE) Write pre- and post-processing kernels as pure functions whose result depends only on their arguments. *Why:* pure kernels can be split across cores and tested against a reference without setup. *Check:* manual. *Severity:* Minor. *Source:* CG F.8.
- **CPP-FN-4** [MUST] (EDGE) Type parameters precisely: no `void*` in project interfaces (only inside a C-boundary wrapper), no runs of `bool` or `int` flags (use an `enum class` or an options struct), and units in the type rather than bare `int`/`double`: `<chrono>` durations and time points in interfaces (`std::chrono::microseconds timeout`, not `int timeout_ms`; clocks: CPP-EDGE-14), a strong `Pixels` type. *Why:* the compiler can then reject swapped or mis-scaled arguments, and the optimiser sees the real types. *Check:* `grep: \bvoid\s*\*` in headers; `grep: \(.*bool \w+,.*bool \w+`; manual. *Severity:* Major. *Source:* CG I.4, P.1, Per.7, Per.10, T.3, SL.chrono.
- **CPP-FN-5** [MUST] (EDGE) Do not put neighbouring parameters of the same type whose order matters (width/height, rows/cols, src/dst, x/y) in an interface; pass a `Size`, `Shape`, `Rect` or `Point` struct, use distinct types, or make the source `const`. Commutative pairs (`Max(a, b)`) are exempt. *Why:* width/height swaps are the classic CV bug and compile silently. *Check:* manual (`bugprone-easily-swappable-parameters` is off: too noisy on existing code). *Severity:* Major. *Source:* CG I.24, I.4; cv-kit.
- **CPP-FN-6** [PREFER] (EDGE) Keep parameter lists short (four or fewer is the aim; more than six means a struct); bundle related values into a named struct passed by `const&`. *Why:* long lists invite swaps, and 32-bit ARM passes only four integer arguments in registers. *Check:* manual. *Severity:* Minor. *Source:* CG I.23, F.2.
- **CPP-FN-7** [MUST] (EDGE) Pass ordinary parameters by direction and cost: an input that is cheap to copy (scalars, enums, `std::span`, `std::string_view`, small trivially copyable view structs of up to about 16 bytes) by value; any other input by `const T&`; an in-out parameter by `T&`. Never take scalars as `const int&`, and never take `std::string`, `std::vector` or `cv::Mat` by value when the function only reads it. *Why:* by-value large inputs copy (and for `cv::Mat` touch an atomic refcount) on every call; `const&` to a scalar adds an indirection and an aliasing hazard. *Check:* clang-tidy `performance-unnecessary-value-param`; `grep: const\s+(int|float|double|bool|size_t|u?int\d+_t)\s*&`; manual. *Severity:* Major. *Source:* CG F.15, F.16, F.17; Google "Inputs and Outputs".
- **CPP-FN-8** [MUST] Take a sink parameter (one the function stores or consumes) by value and `std::move` it into place. Use `T&&` parameters only for move constructors and move assignments, `&&`-qualified methods that consume `*this`, forwarding references, or a `const T&` / `T&&` overload pair backed by a measurement. *Why:* the by-value sink is one function that is optimal for both lvalues and rvalues; stray `T&&` parameters invite moves that never happen. *Check:* clang-tidy `cppcoreguidelines-rvalue-reference-param-not-moved`, `modernize-pass-by-value`; `grep: \w&&\s+\w+\s*[,)]`. *Severity:* Major. *Source:* CG F.18, F.15; Google "Rvalue References".
- **CPP-FN-9** [MUST] Pass a forwarding reference (`T&&` with `T` deduced, or `auto&&`) on with `std::forward<T>` exactly once on each path, never with `std::move`, and do not touch it after forwarding. *Why:* moving or double-forwarding steals from lvalues the caller still owns. *Check:* clang-tidy `cppcoreguidelines-missing-std-forward`, `bugprone-move-forwarding-reference`, `bugprone-use-after-move`, `bugprone-forwarding-reference-overload`. *Severity:* Major. *Source:* CG F.19, ES.56; Google "Rvalue References".
- **CPP-FN-10** [MUST] Express optionality in the parameter type: a parameter that may be absent is `const T*` / `T*` (nullable, never owning) or `std::optional<T>` for small by-value inputs; one that must be present is a reference. A plain pointer parameter always means "one object, maybe null, not owned". *Why:* callers and callees then agree on who checks for null. *Check:* manual. *Severity:* Major. *Source:* CG F.60, F.22, F.23, I.12, GSL.view (`not_null`); Google "Inputs and Outputs".
- **CPP-FN-11** [MUST] (EDGE) Return results by value (several results as a named struct; a fallible result as the project result type, see CPP-ERR) rather than through out-parameters. Out-parameters are allowed for two cases only: a caller-owned buffer reused across frames (an in-out `T&` that the callee clears and refills, keeping capacity), and an object that is expensive to move. Output and in-out parameters come after all inputs, and new inputs are not appended after them. *Why:* return values are clearer and elided; buffer reuse is what keeps the frame loop allocation-free (see CPP-EDGE). *Check:* `grep: void \w+\(.*&\s*out`; manual. *Severity:* Minor. *Source:* CG F.20, F.21; Google "Inputs and Outputs".
- **CPP-FN-12** [MUST] Return several values as a struct with named fields (unpacked with structured bindings), not as `std::pair` or `std::tuple`; use `std::optional<T>` or the project result type instead of `pair<T, bool>`. Pairs and tuples are for generic code and for interoperating with APIs that already return them. *Why:* `.first`/`.second` and `get<1>` hide meaning and are easy to swap. *Check:* `grep: (std::)?(pair|tuple)<.*>\s+\w+\(` in headers; manual. *Severity:* Minor. *Source:* CG F.21; Google "Structs vs. Pairs and Tuples".
- **CPP-FN-13** [MUST NOT] Return or store (in a member, container, global, lambda capture or out-parameter) a pointer, reference, iterator, `std::span`, `std::string_view` or `cv::Mat` header that refers to a local, a temporary or a by-value parameter of the current function. *Why:* the referent dies at return, so every later use is undefined. *Check:* g++ `-Wreturn-local-addr`, `-Wdangling-reference`, `-Wdangling-pointer`; clang-tidy `bugprone-dangling-handle`, `clang-analyzer-core.StackAddressEscape`, `bugprone-return-const-ref-from-parameter`; ASan (stack-use-after-return, stack-use-after-scope). *Severity:* Critical. *Source:* CG F.43, ES.65, Lifetime.1; mD C++ 04.
- **CPP-FN-14** [MUST NOT] Write functions or constructors that require a reference argument to outlive the call (a constructor that stores a `const T&`); take a pointer and document the lifetime and non-null requirement, or copy the value. *Why:* a reference parameter binds happily to a temporary that dies at the end of the full expression. *Check:* clang-tidy `cppcoreguidelines-avoid-const-or-ref-data-members`; manual. *Severity:* Major. *Source:* Google "Inputs and Outputs"; CG C.12.
- **CPP-FN-15** [MUST NOT] Return `T&&`, or return by value as `const T`. *Why:* a returned rvalue reference dangles as soon as the temporary dies, and a `const` value cannot be moved from. *Check:* clang-tidy `readability-const-return-type`; `grep: &&\s+\w+\s*\([^)]*\)\s*(const)?\s*[{;]`. *Severity:* Major. *Source:* CG F.45, F.49.
- **CPP-FN-16** [MUST NOT] Wrap a returned local or by-value parameter in `std::move` (`return std::move(result);`). *Why:* it blocks copy elision, and the implicit move happens anyway. *Check:* g++ `-Wpessimizing-move`, `-Wredundant-move`. *Severity:* Minor. *Source:* CG F.48, ES.56; mD C++ 07.
- **CPP-FN-17** [PREFER] Return a reference (`T&` / `const T&`) only when an object always exists and the caller must not own it; return `T*` only to mean "maybe absent" or a position. *Why:* the return type should say whether a null check is needed and who owns the result. *Check:* manual. *Severity:* Minor. *Source:* CG F.44, F.42; Google "Inputs and Outputs".
- **CPP-FN-18** [PREFER] Outside the special members covered by CPP-CLS-14, add `noexcept` only where it is a deliberate, lasting promise (hash, comparison, small accessors in hot code); write it unconditionally, since nothing throws under `-fno-exceptions`. *Why:* `noexcept` cannot be removed later without risk to callers that rely on it. *Check:* manual. *Severity:* Minor. *Source:* CG F.6; Google "noexcept".
- **CPP-FN-19** [PREFER] (EDGE) Make a function `constexpr` when it is needed at compile time (lookup tables, fixed model dimensions, colour-conversion coefficients) and `consteval` when it must never run at run time; keep compile-time work modest, do not contort a function to make it `constexpr`, and never use `constexpr` to force inlining. *Why:* compile-time tables cost no start-up time and cannot race, while heavy compile-time work slows cross builds and can bloat code. *Check:* manual. *Severity:* Minor. *Source:* CG F.4, Per.11, T.123; Google "Use of constexpr, constinit, and consteval".
- **CPP-FN-20** [MUST] Name every parameter in declarations, unless the meaning is obvious (`Tensor(const Tensor&) = delete;`); in a definition, comment an unused parameter's name out (`void OnFrame(int /*frame_id*/)`), or leave it unnamed when its role is obvious; a parameter unused only in some build configurations gets `[[maybe_unused]]`. *Why:* the name documents the role even when the value is ignored, and the warning stays meaningful. *Check:* g++ `-Wunused-parameter`; clang-tidy `misc-unused-parameters`, `readability-named-parameter`. *Severity:* Minor. *Source:* CG F.9; Google "Function Declarations and Definitions".
- **CPP-FN-21** [MUST NOT] Write C-style variadic functions (`...`, `va_list`), or call them (the `printf` family) outside one audited formatting helper (the logger back end, or `snprintf` into a fixed buffer) that carries `// NOLINT(cppcoreguidelines-pro-type-vararg): <reason>`; never use `gets` or a non-literal format string. Use overloads, a variadic template that forwards to one non-template sink, `std::initializer_list` or `std::span`; `std::format` is allowed outside real-time paths (it allocates). *Why:* C varargs bypass type checking, so a wrong argument or format specifier is undefined behaviour, and an untrusted format string is exploitable. *Check:* clang-tidy `cppcoreguidelines-pro-type-vararg`, `modernize-avoid-variadic-functions`, `bugprone-unsafe-functions`; g++ `-Wformat=2`; `grep: va_start|va_arg|va_list|<cstdarg>`. *Severity:* Major. *Source:* CG F.55, ES.34, T.100, Type.8, SL.io.3; mD C++ 01.
- **CPP-FN-22** [MUST] Overload a name only when every overload does the same thing for different types or argument counts, so a reader need not know which one is chosen; document the set once. Prefer one `std::string_view` parameter over a `const std::string&` / `const char*` pair. *Why:* overloads that differ in meaning make call sites lie. *Check:* manual. *Severity:* Major. *Source:* CG C.162, C.163; Google "Function Overloading".
- **CPP-FN-23** [MUST NOT] Use default arguments on virtual functions, or defaults whose value can change between calls (`= next_id++`, a mutable global); on non-virtual functions a constant default is allowed, and an overload is preferred when it reads better. *Why:* defaults bind to the static type, so a virtual's default depends on the call path. *Check:* clang-tidy `google-default-arguments`; `grep: =\s*\w+(\+\+|--)` in parameter lists. *Severity:* Major. *Source:* CG F.51, C.140; Google "Default Arguments".
- **CPP-FN-24** [PREFER] Write leading return types; use a trailing return type only where the language needs it or where it makes a complex template signature readable. *Why:* consistency with the rest of the code base. *Check:* manual (`modernize-use-trailing-return-type` is rightly disabled). *Severity:* Minor. *Source:* Google "Trailing Return Type Syntax".
- **CPP-FN-25** [MUST NOT] Give public functions declared in headers a deduced return type (`auto F()`, `decltype(auto) F()`); deduced returns are for short, narrow-scope helpers and lambdas. *Why:* the body becomes the interface, and an edit silently changes the API. *Check:* `grep: ^\s*(static\s+|inline\s+|constexpr\s+)*(auto|decltype\(auto\))\s+\w+\s*\(` in public headers (excluding `->` trailing returns). *Severity:* Major. *Source:* Google "Type Deduction (including auto)".
- **CPP-FN-26** [PREFER] Use a lambda only when you need captures or a local callable; when a namespace-scope function would do, or overloading is wanted, write a function. *Why:* named functions overload, show up in stack traces and are testable. *Check:* `grep: ^(static\s+)?(const\s+)?auto\s+\w+\s*=\s*\[\]`. *Severity:* Minor. *Source:* CG F.50.
- **CPP-FN-27** [MUST NOT] (EDGE) Capture by reference, or capture a raw pointer or `this`, in a lambda that can outlive the current scope: one that is returned, stored in a member or `std::function`, queued to a thread, pool or async API, or registered as a camera/inference callback. Capture by value or move ownership in (`[frame = std::move(frame)]`, `[*this]`), and list captures explicitly. *Why:* the captured stack objects die before the callback runs, which is a use-after-free that only shows under load. *Check:* clang-tidy `bugprone-capturing-this-in-member-variable` (partial); `grep: \[\s*&` near `thread|jthread|Enqueue|Submit|Post|async|Callback`; manual. *Severity:* Critical. *Source:* CG F.53, CP.24, CP.31; Google "Lambda Expressions"; mD C++ 02, 07.
- **CPP-FN-28** [MUST] Use the default reference capture `[&]` only when the lambda clearly finishes before every captured object dies (algorithm predicates, work joined in the same scope); otherwise list each capture. *Why:* `[&]` hides what the lambda depends on. *Check:* manual. *Severity:* Major. *Source:* CG F.52; Google "Lambda Expressions".
- **CPP-FN-29** [MUST NOT] Use `[=]` in a member function whose lambda reads members; capture `this` explicitly (or `[*this]` for a copy). Keep `[=]` for short lambdas binding a few obvious locals. *Why:* `[=]` captures `this` by pointer, so members are effectively captured by reference (and the implicit form is deprecated in C++20). *Check:* clang-tidy `cppcoreguidelines-misleading-capture-default-by-value`; g++ `-Wdeprecated`. *Severity:* Major. *Source:* CG F.54; Google "Lambda Expressions".
- **CPP-FN-30** [MUST NOT] Use init-captures to invent new names or values (`[limit = 42]`); use them only to move or copy an existing variable, keeping its name (`[buf = std::move(buf)]`). *Why:* a lambda that defines its own state is a function object in disguise. *Check:* `grep: \[[^]]*\b\w+\s*=\s*[^&]` in capture lists; manual. *Severity:* Minor. *Source:* Google "Lambda Expressions".
- **CPP-FN-31** [PREFER] Write a generic lambda (`auto` parameters) when one callable must accept several argument types, and the explicit template form (`[]<typename T>(T x)`) when the body needs the type. *Why:* lambdas cannot be overloaded by name, and `decltype(x)` tricks are hard to read. *Check:* manual. *Severity:* Minor. *Source:* CG C.170; Google "Type Deduction (including auto)".
- **CPP-FN-32** [PREFER] Keep control flow shallow: guard clauses with early return (including the status-propagation macro from CPP-ERR), merged conditions, and no `else` after `return`. *Why:* the happy path stays at the outer level and each check reads alone. *Check:* clang-tidy `readability-else-after-return`, `readability-function-cognitive-complexity`. *Severity:* Minor. *Source:* CG F.56.
- **CPP-FN-33** [MUST] Confine every unavoidable rule break (pointer arithmetic, casts on raw bytes, SIMD intrinsics, `const_cast` for a C API) to a small implementation function behind a safe interface, with the NOLINT and its reason there; public headers carry no NOLINT for semantic checks. *Why:* the unsafe surface stays small enough to review and test. *Check:* `grep: NOLINT` in public include directories; manual. *Severity:* Major. *Source:* CG I.30, P.11.
- **CPP-FN-34** [PREFER] (EDGE) At a binary boundary shared by code from different compilers or standard libraries (plugin `.so`, JNI, vendor delegate), expose only a C-style interface: `extern "C"` functions, trivially copyable structs, integer status codes. *Why:* C++ classes, `std::` types and exceptions do not cross toolchain boundaries safely. *Check:* manual. *Severity:* Major. *Source:* CG I.26.
- **CPP-FN-35** [MUST] (EDGE) Pass a sequence across an interface as a container (when ownership moves) or as a non-owning view that carries its length: `std::span<T>` / `std::span<const T>` by value, `std::string_view` for text, and the image view of CPP-EDGE-24 for pixels. Never as `T*` plus a count, `(uint8_t* p, int w, int h)`, or a `T[]` parameter. A pre-C++20 toolchain uses the project's single span type. *Why:* the size travels with the data, so bounds can be checked once and the width/height/stride set cannot drift apart. *Check:* clang-tidy `cppcoreguidelines-pro-bounds-array-to-pointer-decay`, `modernize-avoid-c-arrays`, `cppcoreguidelines-pro-bounds-pointer-arithmetic`; `grep: \(\s*(const\s+)?\w+\s*\*\s*\w+\s*,\s*(int|size_t|int64_t|std::size_t)\b`. *Severity:* Major. *Source:* CG I.13, R.2, R.14, F.24, P.6, SL.con.1, SL.str.11, GSL.view (`span`); Google "Integer Types"; mD C++ 04; cv-kit.

## CPP-CLS Classes, hierarchies, operators and enums

- **CPP-CLS-1** [MUST] Use `struct` only for passive data whose fields may each take any value independently (all public, no invariant; constructors and helpers that enforce nothing are fine); anything with an invariant or private state is a `class`, and a `struct` never contains `private:` or `protected:`. *Why:* the keyword tells the reader whether fields can be set freely. *Check:* `grep: private:|protected:` inside `struct` bodies; manual. *Severity:* Minor. *Source:* CG C.2, C.8; Google "Structs vs. Classes".
- **CPP-CLS-2** [PREFER] (EDGE) Group values that belong together into a named type (`Rect`, `TensorShape`, `Detection`, `Keypoint`) instead of loose parallel variables or parameters. *Why:* a plain aggregate costs nothing at run time and removes whole classes of mix-ups. *Check:* manual. *Severity:* Minor. *Source:* CG C.1.
- **CPP-CLS-3** [MUST] Every data member of a `class` is private (static constants excepted), there is no `protected` data, and derived classes get protected member functions instead; debug counters get an accessor or live in a separate struct. *Why:* the class can only keep its invariant if it controls every write. *Check:* manual (`misc-non-private-member-variables-in-classes` is off); `grep: protected:` followed by data members. *Severity:* Major. *Source:* CG C.9, C.133, C.134, C.3; Google "Access Control", "Inheritance".
- **CPP-CLS-4** [PREFER] Write a member function only when it reads or writes private state (or the language requires a member: virtuals, `=`, `[]`, `()`, `->`); otherwise write a non-member in the same namespace as the type so argument-dependent lookup finds it. *Why:* fewer members means a smaller surface that can break the invariant. *Check:* clang-tidy `readability-convert-member-functions-to-static` (partial); manual. *Severity:* Minor. *Source:* CG C.4, C.5.
- **CPP-CLS-5** [MUST NOT] Define a type and declare a variable of it in one statement (`struct Opts {...} opts;`). *Why:* the declaration hides in the closing brace. *Check:* `grep: ^\s*}\s*[A-Za-z_]\w*\s*[;={]`. *Severity:* Minor. *Source:* CG C.7.
- **CPP-CLS-6** [PREFER] (EDGE) Default to concrete value types; introduce a class hierarchy only when behaviour must be selected at run time (for example several inference backends), and make a function virtual only when an override exists or is planned. *Why:* hierarchies add a vptr per object, indirection, heap allocation and blocked inlining. *Check:* manual. *Severity:* Minor. *Source:* CG C.10, C.11, C.132; Google "Inheritance".
- **CPP-CLS-7** [MUST NOT] Give a copyable or movable type `const` or reference data members; store a value, or a pointer documented as non-null. *Why:* such members silently delete assignment, so the type cannot live in a reassigned `std::vector` or `std::optional`. *Check:* clang-tidy `cppcoreguidelines-avoid-const-or-ref-data-members`. *Severity:* Major. *Source:* CG C.12.
- **CPP-CLS-8** [MUST] (EDGE) Declare data members in dependency order: a member used by another during construction or destruction comes first (TensorRT runtime before engine before execution context; CUDA stream before the buffers queued on it; shared state before the thread member that reads it, so the thread is joined before the state dies). *Why:* members are built in declaration order and destroyed in reverse; a wrong order is a use-after-free at shutdown. *Check:* g++ `-Wuninitialized` (use in the initializer list); manual. *Severity:* Critical. *Source:* CG C.13; cv-kit.
- **CPP-CLS-9** [MUST] Follow the rule of zero when members already manage themselves (containers, smart pointers, RAII handles): write none of the destructor, copy or move operations. Write a destructor only for an action no member performs, and never to reset or "clean up" members by hand. *Why:* hand-written special members are where double frees and missed moves come from. *Check:* manual (`grep: ~\w+\(\)\s*\{` in classes whose members are all RAII). *Severity:* Major. *Source:* CG C.20, C.30.
- **CPP-CLS-10** [MUST] (EDGE) Make copy and move intent explicit for every class with a private section: declare the copy and/or move operations (`= default`) or delete the copy operations (which also suppresses moves) in the `public:` section. Passive structs and classes whose copyability follows obviously from their public members may omit them. *Why:* the reader of the header must know whether a type is copyable, move-only or neither; for buffers and device handles that decides correctness. *Check:* clang-tidy `cppcoreguidelines-special-member-functions` (once any is declared); manual. *Severity:* Major. *Source:* Google "Copyable and Movable Types"; CG C.20, C.21.
- **CPP-CLS-11** [MUST] (EDGE) Rule of five: once any of the destructor, copy constructor, copy assignment, move constructor or move assignment is declared (including `= default` or `= delete`), declare all five. A lone `virtual ~Base() = default;` is not enough. *Why:* a user-declared destructor removes the implicit moves, so every "move" silently becomes a deep copy of the tensors inside. *Check:* clang-tidy `cppcoreguidelines-special-member-functions` (configured with `AllowSoleDefaultDtor: false`); g++ `-Wdeprecated-copy-dtor`. *Severity:* Major. *Source:* CG C.21, C.33; Google "Copyable and Movable Types"; mD C++ 03.
- **CPP-CLS-12** [MUST] Keep special members consistent with each other: copy construction and copy assignment are both deep or both shallow and match what the destructor releases, and defaulted operations are reviewed like code (a defaulted copy of a type holding an owning raw handle is a double free). *Why:* inconsistent special members corrupt memory on the first copy. *Check:* manual. *Severity:* Critical. *Source:* CG C.22, C.33, C.61; Google "Copyable and Movable Types".
- **CPP-CLS-13** [MUST] Write `= default` for a special member whose default meaning is right, and `= delete` (in the public section) to disable one; no hand-written member-wise bodies and no private-and-undefined tricks. *Why:* defaulted members stay correct when members change and keep triviality. *Check:* clang-tidy `modernize-use-equals-default`, `modernize-use-equals-delete`. *Severity:* Minor. *Source:* CG C.80, C.81; Google "Copyable and Movable Types".
- **CPP-CLS-14** [MUST] (EDGE) Mark move constructors, move assignments and `swap` functions `noexcept`, and make them really move (steal the representation, never copy through a temporary). *Why:* `std::vector` and other containers copy elements on reallocation unless the move is `noexcept`, and that holds under `-fno-exceptions` too (with g++ 13, growing a vector of four elements made 4 copies and 0 moves without `noexcept`, 0 copies and 4 moves with it); for frame or tensor types that is a large hidden copy. *Check:* clang-tidy `performance-noexcept-move-constructor` (alias `cppcoreguidelines-noexcept-move-operations`), `performance-noexcept-swap` (alias `cppcoreguidelines-noexcept-swap`), `performance-noexcept-destructor` (they stay silent on `-fno-exceptions` compile commands, so the shipped `.clang-tidy` passes `-fexceptions` to clang-tidy only). *Severity:* Major. *Source:* CG C.66, C.84, C.85, C.102, C.37, F.6, E.12, E.16; Google "noexcept"; mD C++ 03.
- **CPP-CLS-15** [MUST] (EDGE) Leave a moved-from object valid, and leave a moved-from resource handle empty: the move nulls the source's handle (pointer to `nullptr`, descriptor to `-1`) so the source's destructor releases nothing. Callers only assign to or destroy a moved-from object. *Why:* a handle that keeps its pointer after the move frees the resource twice (double `cudaFree`, double `munmap`). *Check:* clang-tidy `bugprone-use-after-move`; manual for the callee side. *Severity:* Critical. *Source:* CG C.64, ES.56; mD C++ 04.
- **CPP-CLS-16** [MUST] Copy and move assignment operators are non-virtual, take `const T&` and `T&&`, return a non-const `T&` to `*this`, and stay correct when the source is the object itself (by construction, or with an explicit check). *Why:* self-assignment happens through aliases and `std::swap`, and a wrong signature breaks generic code. *Check:* clang-tidy `misc-unconventional-assign-operator` (alias `cppcoreguidelines-c-copy-assignment-signature`), `bugprone-unhandled-self-assignment`; g++ `-Wself-move`. *Severity:* Major. *Source:* CG C.60, C.62, C.63, C.65, F.47.
- **CPP-CLS-17** [PREFER] Give value types with non-trivial members a `noexcept` member `swap` and a free `swap` in the same namespace; generic code calls `using std::swap; swap(a, b);`. *Why:* the custom swap exchanges representations instead of three moves, and the two-step call finds it. *Check:* manual; `grep: std::swap\(` in templates. *Severity:* Minor. *Source:* CG C.83, C.165.
- **CPP-CLS-18** [MUST] A constructor establishes the class invariant and initialises every member, so the object is fully usable as soon as it exists. Construction that can fail follows CPP-ERR-8 and CPP-ERR-9. *Why:* reading a member that no constructor set is undefined behaviour. *Check:* clang-tidy `cppcoreguidelines-pro-type-member-init`; g++ `-Wuninitialized`. *Severity:* Critical. *Source:* CG C.40, C.41, C.42, Type.6; Google "Doing Work in Constructors"; mD C++ 03.
- **CPP-CLS-19** [MUST] Put constant member defaults on the member declaration (`int stride_ = 0;`) rather than repeating them in constructors or assigning them in a default constructor; that default constructor is then `= default` or omitted. *Why:* one place per default, and no member is forgotten in one constructor. *Check:* clang-tidy `modernize-use-default-member-init` (alias `cppcoreguidelines-use-default-member-init`). *Severity:* Minor. *Source:* CG C.45, C.48.
- **CPP-CLS-20** [MUST] Initialise members in the member initializer list, written in declaration order, instead of assigning them in the constructor body. *Why:* assignment default-constructs first (twice the work for strings, vectors, `cv::Mat` headers), and the list order is not the real order. *Check:* clang-tidy `cppcoreguidelines-prefer-member-initializer`; g++ `-Wreorder`. *Severity:* Minor. *Source:* CG C.47, C.49; mD C++ 03.
- **CPP-CLS-21** [MUST] (EDGE) Default constructors are cheap and cannot fail: no allocation, no I/O, no device calls; the empty state is null pointers and zero sizes. *Why:* arrays and pools of default-constructed objects must not mean one allocation each, and a reset after an error must not fail. *Check:* manual. *Severity:* Major. *Source:* CG C.44, C.104, C.43.
- **CPP-CLS-22** [PREFER] Share constructor logic by delegating to another constructor, not with copy-pasted bodies or a private `init()`; when a derived class adds no members needing initialisers, inherit the base constructors with `using Base::Base;`. *Why:* one code path for initialisation. *Check:* clang-tidy `bugprone-undelegated-constructor` (catches the classic mistake); manual. *Severity:* Minor. *Source:* CG C.51, C.52; mD C++ 03.
- **CPP-CLS-23** [MUST] Mark `explicit` every constructor callable with one argument (including through defaulted parameters) and every conversion operator; copy, move and `std::initializer_list` constructors stay implicit, and a deliberate implicit conversion between interchangeable types needs a NOLINT with the reason, listing every check name clang-tidy prints for it (CPP-DOC-18). *Why:* implicit conversions turn an `int` into a `Tensor` or a buffer into a dangling pointer without anyone noticing. *Check:* clang-tidy `google-explicit-constructor` (aliases `cppcoreguidelines-explicit-constructor`, `misc-explicit-constructor`). *Severity:* Major. *Source:* CG C.46, C.164, GSL.util (`[[implicit]]`); Google "Implicit Conversions".
- **CPP-CLS-24** [MUST NOT] Call a virtual function, directly or through a helper, from a constructor or destructor; if setup needs derived-class behaviour, a factory performs that step after construction. *Why:* the call reaches the base version (or a pure virtual, which is undefined). *Check:* clang-tidy `clang-analyzer-optin.cplusplus.VirtualCall`. *Severity:* Critical. *Source:* CG C.82, C.50; Google "Doing Work in Constructors".
- **CPP-CLS-25** [MUST NOT] (EDGE) Use `memset`, `memcpy`, `memmove` or `memcmp` on objects that are not trivially copyable; any bulk copy of typed elements sits next to `static_assert(std::is_trivially_copyable_v<T>)` and takes its size from `sizeof(object)` or `span.size_bytes()`. *Why:* byte copies skip constructors, clobber vptrs and owning pointers, and are undefined behaviour. *Check:* g++ `-Wclass-memaccess`; clang-tidy `bugprone-undefined-memory-manipulation`, `bugprone-suspicious-memset-usage`. *Severity:* Critical. *Source:* CG C.90, SL.con.4; cv-kit.
- **CPP-CLS-26** [PREFER] Make copyable types regular (a copy is independent and compares equal to the original), resource handles move-only, and types with identity (owners of mutexes, engines, streams) neither copyable nor movable. *Why:* readers can then reason about values without reading implementations. *Check:* manual. *Severity:* Minor. *Source:* CG C.11, C.61, C.101; Google "Copyable and Movable Types".
- **CPP-CLS-27** [MUST NOT] (EDGE) Make a type implicitly copyable when a copy is surprising or expensive (it owns a frame, tensor or model buffer); make it move-only and give it an explicit `Clone()` if deep copies are needed. *Why:* an innocent `auto x = y;` must not copy megabytes per frame. *Check:* manual. *Severity:* Major. *Source:* Google "Copyable and Movable Types"; mD C++ 04; cv-kit.
- **CPP-CLS-28** [MUST] Inherit only for real is-a relationships and prefer composition otherwise; all inheritance is `public` (hold a member instead of inheriting privately). *Why:* implementation inheritance spreads one class's logic over several files and couples them. *Check:* `grep: (class|struct)\s+\w+\s*(final\s*)?:\s*(private|protected)\s`; manual. *Severity:* Minor. *Source:* CG C.120; Google "Inheritance"; mD C++ 03.
- **CPP-CLS-29** [MUST] Give a base class a destructor that is virtual and public, or non-virtual and protected (the second form for CRTP and mixin bases that are never deleted through the base). *Why:* deleting a derived object through a base pointer without a virtual destructor is undefined. *Check:* clang-tidy `cppcoreguidelines-virtual-class-destructor`; g++ `-Wnon-virtual-dtor`, `-Wdelete-non-virtual-dtor`. *Severity:* Critical. *Source:* CG C.35, C.127, I.25; mD C++ 03.
- **CPP-CLS-30** [MUST] Mark every overriding function, including destructors, with exactly one of `override` or `final`, and never repeat `virtual` on it; `virtual` appears only where a new virtual function is introduced. *Why:* the compiler then rejects a signature that silently stopped overriding. *Check:* clang-tidy `modernize-use-override` (alias `cppcoreguidelines-explicit-virtual-functions`); g++ `-Wsuggest-override`. *Severity:* Major. *Source:* CG C.128; Google "Inheritance"; mD C++ 03.
- **CPP-CLS-31** [MUST] An interface is an abstract class with only public pure virtual functions, no data, a public virtual defaulted destructor, and deleted copy and move operations (so derived classes declare their own); a class may inherit several such interfaces. *Why:* users then depend only on the contract, never on a base's state. *Check:* clang-tidy `cppcoreguidelines-special-member-functions`, `cppcoreguidelines-virtual-class-destructor`; manual for data in interfaces. *Severity:* Major. *Source:* CG I.25, C.121, C.122, C.126, C.129, C.135; Google "Inheritance".
- **CPP-CLS-32** [MUST NOT] Use multiple implementation inheritance or virtual base classes: at most one base may carry data or non-pure functions (standard mixins such as `std::enable_shared_from_this` are tolerated). *Why:* diamonds add hidden pointers per object and obscure which state is used. *Check:* `grep: :\s*(public\s+)?virtual\s|virtual\s+public`; manual (`fuchsia-multiple-inheritance` is off). *Severity:* Minor. *Source:* CG C.129, C.136, C.137; Google "Inheritance".
- **CPP-CLS-33** [MUST] (EDGE) Prevent slicing: a polymorphic base deletes its public copy and move operations (or makes them protected when derived classes need them), polymorphic objects are handled only through references or pointers, and a needed deep copy is a virtual `Clone()` returning `std::unique_ptr<Base>`. *Why:* copying a derived object into a base by value drops the derived state and silently runs the base's behaviour. *Check:* clang-tidy `cppcoreguidelines-slicing`, `cppcoreguidelines-special-member-functions`. *Severity:* Critical. *Source:* CG C.67, C.130, C.145, ES.63; Google "Copyable and Movable Types".
- **CPP-CLS-34** [MUST] When a derived class overrides or adds one overload of a base-class name, bring the remaining base overloads into scope with `using Base::Name;`. *Why:* otherwise they are hidden and calls resolve to an unexpected overload. *Check:* g++ `-Woverloaded-virtual`. *Severity:* Major. *Source:* CG C.138; Google "Function Overloading".
- **CPP-CLS-35** [MUST NOT] Redeclare a base-class data member or non-virtual member function in a derived class. *Why:* that hides the base member instead of overriding it, so two copies of the state exist and the call depends on the static type. *Check:* clang-tidy `bugprone-virtual-near-miss` (near-miss overrides); manual. *Severity:* Major. *Source:* mD C++ 03; cv-kit.
- **CPP-CLS-36** [PREFER] (EDGE) Put `final` on a leaf implementation class (or function) when a profile or the generated code shows that devirtualising a hot call helps; do not add it as a habit. *Why:* `final` blocks future extension, so it should buy something measurable. *Check:* manual. *Severity:* Minor. *Source:* CG C.139; Google "Inheritance".
- **CPP-CLS-37** [MUST NOT] (EDGE) Pass an array of derived objects as a pointer to base, or do pointer arithmetic on a pointer to a polymorphic base. *Why:* indexing then uses the base's size and walks into the middle of objects. *Check:* clang-tidy `cppcoreguidelines-pro-bounds-array-to-pointer-decay`, `bugprone-pointer-arithmetic-on-polymorphic-object`. *Severity:* Critical. *Source:* CG C.152, T.81.
- **CPP-CLS-38** [PREFER] Do not write get/set pairs that only read and write a member with no invariant; make the type a struct with public fields. Accessors exist to keep an invariant or convert a representation (naming: CPP-NAME-10). *Why:* trivial accessors add code and copy-paste bugs without protecting anything. *Check:* manual. *Severity:* Minor. *Source:* CG C.131; Google "Access Control"; mD C++ 03.
- **CPP-CLS-39** [PREFER] Use `friend` sparingly, declared in the same file as the class it befriends (typical: a builder, a test fixture), and prefer one friend over making a member public for a single client. *Why:* friends widen the set of code that can break the invariant. *Check:* `grep: \bfriend\b`; manual. *Severity:* Minor. *Source:* Google "Friends".
- **CPP-CLS-40** [MUST] Overload an operator only with its conventional meaning (and expected cost), only on your own types, declared in the type's namespace and header, and together with its natural partners (`+` with `+=`; `==`, plus `<=>` only when there is one obvious ordering). *Why:* readers trust operators to behave like the built-ins; ADL must find them. *Check:* clang-tidy `misc-unconventional-assign-operator` (assignment only); manual. *Severity:* Major. *Source:* CG C.160, C.167, C.168, T.21; Google "Operator Overloading".
- **CPP-CLS-41** [MUST] Write symmetric binary operators (`==`, `<=>`, `+`, `*`) as non-members or hidden friends; comparisons are `noexcept` and cannot fail (invalid states compare unequal). *Why:* both operands then get the same conversions, and comparisons are used inside algorithms that cannot handle failure. *Check:* `grep: bool operator(==|!=|<|<=|>|>=)\s*\(const \w+&[^,]*\)\s*const`; manual. *Severity:* Minor. *Source:* CG C.86, C.161; Google "Operator Overloading".
- **CPP-CLS-42** [MUST NOT] Overload `&&`, `||`, the comma operator or unary `&`; define an operator just because a container wants one (pass a comparator instead); or declare virtual comparison operators (user-defined literals: CPP-LIB-4). *Why:* these break evaluation order, short-circuiting or address semantics, or compare only the base part. *Check:* clang-tidy `google-runtime-operator` (unary `&`); `grep: operator\s*(&&|\|\||,)\s*\(|virtual\s+\w+\s+operator(==|<=>|<)`. *Severity:* Major. *Source:* CG C.166, C.87; Google "Operator Overloading".
- **CPP-CLS-43** [PREFER] Pointer-like handles provide `operator*` and `operator->`; custom containers (ring buffers, fixed-capacity vectors) follow standard conventions: `value_type`, `size()`, `data()`, `begin()`/`end()`, a cheap empty default state, value semantics and an `std::initializer_list` constructor where meaningful. *Why:* standard algorithms and range-for then just work. *Check:* manual. *Severity:* Minor. *Source:* CG C.100, C.101, C.103, C.104, C.109.
- **CPP-CLS-44** [MUST] A hasher type (passed to the unordered container as a template argument; never a `std::hash` specialisation, CPP-HDR-21) is `noexcept`, cannot fail, and mixes fields with a real hash-combine rather than plain XOR. *Why:* XOR cancels symmetric fields and clusters keys, which turns lookups into linear scans. *Check:* manual. *Severity:* Major. *Source:* CG C.89; cv-kit.
- **CPP-CLS-45** [MUST] Use `enum class` for every enumeration (plain `enum` only in C-interop headers), and represent a set of related named constants as an enumeration, not as integer macros or an anonymous `enum { ... }` bag. *Why:* scoped enums do not convert to `int` and let the compiler check `switch` coverage. *Check:* clang-tidy `cppcoreguidelines-use-enum-class`, `modernize-macro-to-enum` (alias `cppcoreguidelines-macro-to-enum`); `grep: \benum\s*(:\s*\w+\s*)?\{`. *Severity:* Major. *Source:* CG Enum.1, Enum.2, Enum.3, Enum.6.
- **CPP-CLS-46** [MUST] (EDGE) Give enumerators explicit values when they must match something external (model class indices, label maps, wire or file formats, register values, bit flags), and add a `static_assert` on the count or last value; otherwise leave values implicit. *Why:* reordering a pinned enum silently changes what a class index means. *Check:* clang-tidy `readability-enum-initial-value`; manual. *Severity:* Major. *Source:* CG Enum.8.
- **CPP-CLS-47** [PREFER] (EDGE) Give an enum a small fixed underlying type (`std::uint8_t`) when it is stored per element, serialised or forward-declared; accept `performance-enum-size`'s suggestion unless an ABI fixes the width. *Why:* per-detection fields and packed structs shrink. *Check:* clang-tidy `performance-enum-size`. *Severity:* Minor. *Source:* CG Enum.7.
- **CPP-CLS-48** [PREFER] Give an enum the operations it needs (flag `|` and `&`, `ToString`) as `constexpr` functions in its namespace, instead of scattering casts at call sites. *Why:* one place converts, and call sites stay typed. *Check:* manual (repeated `static_cast<Enum>(...)`). *Severity:* Minor. *Source:* CG Enum.4, C.168.
- **CPP-CLS-49** [MUST NOT] (EDGE) Use a bare union, or any union for type punning; use `std::variant` (read with `std::get_if` or `std::visit`, never `std::get`, which aborts on the wrong alternative under `-fno-exceptions`) and `std::bit_cast` / `std::memcpy` for bit reinterpretation. A hand-written tagged union is allowed only inside one class that owns the tag and the member lifetimes. *Why:* reading an inactive member is undefined behaviour, and fp16/int8 bit tricks are where it bites. *Check:* clang-tidy `cppcoreguidelines-pro-type-union-access`; `grep: \bunion\b`. *Severity:* Critical. *Source:* CG C.180, C.181, C.182, C.183, Type.7, P.4.
- **CPP-CLS-50** [PREFER] (EDGE) Use the Pimpl idiom only for long-lived objects at a shared-library or ABI boundary (engine, session), never for per-frame value types; define its special members out of line where the implementation is complete. *Why:* Pimpl costs one allocation per object and a pointer chase per call. *Check:* manual. *Severity:* Minor. *Source:* CG I.27.

## CPP-TPL Templates and generic code

- **CPP-TPL-1** [MUST] (EDGE) Write a template only when more than one type actually uses it (or a second use is concrete and imminent); a function called with one type names that type. *Why:* every instantiation adds binary size and compile time, and speculative genericity is paid for on every cross build. *Check:* manual. *Severity:* Minor. *Source:* CG T.1, T.2; Google "Type Deduction (including auto)"; mD C++ 06.
- **CPP-TPL-2** [MUST] Express containers and algorithms over many element types as typed templates, not as `void*` plus an element size plus casts; a type-erased non-template core under a thin typed wrapper is the allowed form. *Why:* type information lets the compiler check and optimise. *Check:* clang-tidy `bugprone-casting-through-void`, `cppcoreguidelines-pro-type-reinterpret-cast`; `grep: \bvoid\s*\*`. *Severity:* Major. *Source:* CG T.3, T.84.
- **CPP-TPL-3** [PREFER] Constrain a public template with standard concepts (`std::integral`, `std::floating_point`, `std::ranges::contiguous_range`) in a `requires` clause, not with the `template <Concept T>` shorthand; on a C++17 toolchain use `static_assert` with type traits. List only the properties the algorithm needs, not logging or debugging conveniences. *Why:* misuse then fails at the call with a readable message. *Check:* clang-tidy `modernize-use-constraints`; `grep: template\s*<\s*[A-Za-z_:]+\s+[A-Z]\w*\s*>` (shorthand form). *Severity:* Minor. *Source:* CG T.10, T.11, T.13, T.41, I.9, T.48, T.121; Google "Concepts and Constraints".
- **CPP-TPL-4** [MUST NOT] Define new concepts in public headers, single-operation concepts (`Addable`), concepts that restate a standard concept or trait, or concepts whose main content is a semantic promise the compiler cannot check. A new concept is rare, internal to a library, and documents its semantic requirements in a comment. *Why:* concept zoos add maintenance and error-message noise without safety. *Check:* `grep: ^\s*(template\s*<[^>]*>\s*)?concept\s+\w+` in public headers; manual. *Severity:* Minor. *Source:* CG T.20, T.22, T.23, T.26; Google "Concepts and Constraints".
- **CPP-TPL-5** [MUST NOT] Overload on a constraint and its negation (`C<T>` versus `!C<T>`), or build overload sets from `||`/`!` constraint soup; write an unconstrained fallback plus a constrained overload, or delete the fallback, and tell semantically different concepts apart with a tag or trait. *Why:* complementary constraints are fragile and produce ambiguous calls. *Check:* `grep: requires\s*\(?\s*!|enable_if(_t)?<\s*!`. *Severity:* Major. *Source:* CG T.24, T.25, T.30, T.31.
- **CPP-TPL-6** [PREFER] Prefer `requires` clauses and `if constexpr` to `std::enable_if` and SFINAE detection tricks; where SFINAE is unavoidable (C++17), put it in a non-type parameter (`std::enable_if_t<Cond, int> = 0`) so two overloads do not become redeclarations. *Why:* constraints are readable and give better errors. *Check:* clang-tidy `modernize-use-constraints`; `grep: enable_if`. *Severity:* Minor. *Source:* CG T.48, T.121; Google "Concepts and Constraints"; mD C++ 06.
- **CPP-TPL-7** [MUST] (EDGE) Keep template metaprogramming in a few low-level components: isolate it from public headers, comment what it generates, make misuse produce clear errors (`static_assert` with a message), compute values with `constexpr` functions rather than recursive templates, and compute types with alias templates and the `_t` / `_v` traits. *Why:* metaprograms are hard to maintain, slow the build and bloat the binary. *Check:* clang-tidy `modernize-type-traits`; manual. *Severity:* Minor. *Source:* CG T.120, T.122, T.123, T.124, T.125, T.142; Google "Template Metaprogramming"; mD C++ 06.
- **CPP-TPL-8** [MUST NOT] Rely on class template argument deduction for a template that declares no deduction guide (standard-library templates count as opted in). *Why:* CTAD on a template not designed for it deduces surprising types. *Check:* clang `-Wctad-maybe-unsupported` (set for Clang builds by `cv_kit_strict`); manual in GCC-only projects. *Severity:* Minor. *Source:* CG T.44; Google "Class Template Argument Deduction".
- **CPP-TPL-9** [PREFER] (EDGE) Pass operations to algorithms and kernels as lambdas or function objects (inlinable), not function pointers; keep `std::function` out of per-frame and per-element paths, using a template parameter or a non-owning callable reference there. *Why:* function pointers and `std::function` block inlining and vectorisation; `std::function` may allocate, and calling an empty one aborts under `-fno-exceptions`. *Check:* manual. *Severity:* Major. *Source:* CG T.40, T.49; cv-kit.
- **CPP-TPL-10** [PREFER] Use type erasure only at boundaries that need it (plugin interfaces, stored callbacks), never inside hot loops. *Why:* erasure adds an indirection and hides types from the optimiser. *Check:* manual. *Severity:* Minor. *Source:* CG T.49, T.5.
- **CPP-TPL-11** [MUST] (EDGE) Control instantiation bloat: move members that use only some of the template parameters into a smaller template or a non-template base, avoid virtual functions in class templates (all of them are instantiated whether used or not), put a thin typed wrapper over a non-template core, and use `extern template` for heavy common instantiations. *Why:* duplicated machine code costs flash, RAM and instruction cache on device. *Check:* manual (compare symbol sizes with `nm --size-sort`). *Severity:* Minor. *Source:* CG T.5, T.61, T.62, T.80, T.84; mD C++ 06.
- **CPP-TPL-12** [MUST] Inside templates, qualify calls to your own helpers (`detail::Pack(x)`) and leave a call unqualified only when it is a deliberate customisation point (`swap`, `begin`); do not put unconstrained templates with common names (`operator==`, `size`) in a namespace that also holds types. *Why:* unqualified calls let argument-dependent lookup pick an unrelated function, and the result depends on include order. *Check:* manual. *Severity:* Major. *Source:* CG T.47, T.60, T.69.
- **CPP-TPL-13** [MUST NOT] Specialise function templates; overload instead, or delegate to a class template and specialise that. *Why:* specialisations do not take part in overload resolution, so the expected one is often not called. *Check:* `grep: template\s*<\s*>` followed by a function definition. *Severity:* Major. *Source:* CG T.144; mD C++ 06.
- **CPP-TPL-14** [MUST NOT] Use a variadic template for a list of values of one type (take `std::initializer_list` or `std::span`); keep variadic front ends thin and forward to one non-template sink. *Why:* each distinct pack is a new instantiation. *Check:* manual. *Severity:* Minor. *Source:* CG T.100, T.103, F.55.
- **CPP-TPL-15** [PREFER] Provide alternative implementations behind one interface with class template specialisation, tag dispatch or `if constexpr` (for example a trivially copyable `memcpy` fast path). *Why:* callers keep one name and the fast path stays checked. *Check:* manual. *Severity:* Minor. *Source:* CG T.64, T.65, T.67.
- **CPP-TPL-16** [PREFER] Keep generic code generic: compare iterators with `!=`, test `empty()` rather than `size() == 0`, take the least-derived parameter type that does the job, initialise with `{}`. *Why:* code accidentally tied to one container or type fails on the next. *Check:* clang-tidy `readability-container-size-empty`. *Severity:* Minor. *Source:* CG T.143, T.68.
- **CPP-TPL-17** [MUST NOT] Write abbreviated function templates (`void Normalise(auto& img)`) outside lambdas; name the template parameter. *Why:* `auto` parameters hide that the function is a template. *Check:* `grep: ^[^\[]*\b\w+\s*\([^)]*\bauto\b\s*[&*]*\s*\w+` outside lambdas. *Severity:* Minor. *Source:* Google "Type Deduction (including auto)".
- **CPP-TPL-18** [PREFER] (EDGE) Assert compile-time facts next to the type they concern: `static_assert` on trivial copyability before bulk copies (layout of shared structs: CPP-EDGE-21), on concept conformance, and on enum counts. *Why:* the check costs nothing at run time and fails at the commit that breaks it. *Check:* manual. *Severity:* Minor. *Source:* CG P.5, T.150.

## CPP-PERF Performance

- **CPP-PERF-1** [MUST] (EDGE) Optimise only against a stated budget (latency, throughput, memory, power) that is being missed, and only the stage that dominates; a change that adds complexity for speed comes with a before/after measurement. *Why:* unneeded tuning adds bugs and maintenance cost, and gains on a minor stage are invisible. *Check:* manual (ask for the budget and the numbers in the PR). *Severity:* Major. *Source:* CG Per.1, Per.2, Per.3, Per.6; Google "Rvalue References".
- **CPP-PERF-2** [MUST] (EDGE) Measure on the target device with the production compiler flags, at steady state after warm-up, per pipeline stage (decode, preprocess, inference, postprocess), using `std::chrono::steady_clock` or a profiler (Nsight Systems, `perf`, `simpleperf`). *Why:* (experience) x86 development-box numbers routinely mislead about ARM targets with different caches, clocks and thermal throttling. *Check:* manual. *Severity:* Major. *Source:* CG Per.6; cv-kit.
- **CPP-PERF-3** [MUST NOT] Assume that clever or low-level code is faster than simple code: write the simple loop first, keep it as the reference implementation in tests, and keep a hand-tuned version only if it measurably wins. *Why:* optimisers handle plain loops well, and tricks such as byte reinterpretation often block them (and break aliasing rules). *Check:* manual. *Severity:* Major. *Source:* CG Per.4, Per.5.
- **CPP-PERF-4** [PREFER] (EDGE) Design interfaces that leave room to optimise: pass full type and size information (typed spans and views), keep data contiguous, and do not force indirection, allocation or ownership on callers. *Why:* an interface that hides sizes or types blocks every later speed-up. *Check:* manual. *Severity:* Minor. *Source:* CG Per.7, Per.10.
- **CPP-PERF-5** [MUST] (EDGE) Avoid needless copies of large objects in per-frame code: read through `const&`, iterate by reference, move into sinks, and never copy a `cv::Mat`, tensor or `std::vector` just to read it. *Why:* each copy is an allocation plus a memory pass at camera rate. *Check:* clang-tidy `performance-unnecessary-copy-initialization`, `performance-unnecessary-value-param`, `performance-for-range-copy`, `performance-move-const-arg`. *Severity:* Major. *Source:* CG P.9, F.16, ES.71; Google "Copyable and Movable Types".
- **CPP-PERF-6** [MUST] (EDGE) Reserve capacity when the final size is known, construct elements in place (`emplace_back`), build strings with one append pass, and reuse buffers across iterations (`clear()` keeps capacity); the rule that the frame loop allocates nothing is CPP-EDGE-2. *Why:* growth reallocations copy everything and fragment the heap of a long-running process. *Check:* clang-tidy `performance-inefficient-vector-operation`, `modernize-use-emplace`, `performance-inefficient-string-concatenation`. *Severity:* Major. *Source:* CG Per.14, P.9; mD C++ 05.
- **CPP-PERF-7** [MUST] (EDGE) Store images and tensors as one contiguous buffer with explicit shape and stride (never `T**` or `std::vector<std::vector<T>>`), default to `std::vector` over node-based containers (`std::list`, `std::map`), and use flat sorted vectors or open addressing for lookups on hot paths. *Why:* memory access dominates run time, and node containers cost an allocation and a cache miss per element. *Check:* `grep: \*\*\s*\w+|vector<\s*(std::)?vector<|std::list<`; manual. *Severity:* Major. *Source:* CG Per.16, Per.18, Per.19, P.9; mD C++ 04, 05.
- **CPP-PERF-8** [MUST] (EDGE) Traverse memory in storage order: row by row for row-major images, and loop nests that match the tensor layout (NCHW or NHWC) in use. *Why:* strided traversal multiplies cache misses and defeats vectorisation. *Check:* manual. *Severity:* Major. *Source:* CG Per.19.
- **CPP-PERF-9** [PREFER] (EDGE) In structs that are stored in bulk or touched per element, order members by access frequency and size to reduce padding and cache lines. *Why:* smaller structs mean more of them per cache line. *Check:* clang-tidy `clang-analyzer-optin.performance.Padding`; `pahole`. *Severity:* Minor. *Source:* CG Per.16, Per.17, Per.18, P.9.
- **CPP-PERF-10** [MUST NOT] (EDGE) Make a virtual call, a `std::function` call or a function-pointer call per pixel or per element inside a hot loop; dispatch once per tensor or frame, then run a templated or inlined inner loop. *Why:* indirect calls per element block inlining and SIMD. *Check:* manual. *Severity:* Major. *Source:* CG C.132, C.10, I.25, T.40, Per.13; cv-kit.
- **CPP-PERF-11** [PREFER] (EDGE) Remove redundant indirection and aliasing in kernels: hoist loop-invariant values (`size()`, `strlen`, member loads through `this`) into locals, and use `__restrict__` only through the portability header (CPP-EDGE-25). *Why:* possible aliasing forces the compiler to reload memory on every iteration. *Check:* manual. *Severity:* Minor. *Source:* CG Per.12, Per.13, P.9.
- **CPP-PERF-12** [MUST] (EDGE) Keep `shared_ptr` copies, atomic read-modify-writes and lock acquisitions out of per-element loops; take them once per frame or batch. *Why:* each is an atomic operation that serialises cores. *Check:* manual. *Severity:* Major. *Source:* CG F.7, R.34, CP.43; cv-kit.
- **CPP-PERF-13** [PREFER] (EDGE) Avoid context switches on the critical path: at most one thread hand-off per pipeline stage, batched small work items, and a thread count close to the core count that leaves cores for capture and inference. *Why:* each switch costs microseconds and cache warmth. *Check:* manual (`perf sched`, Nsight Systems). *Severity:* Minor. *Source:* CG Per.30, CP.40, CP.41.
- **CPP-PERF-14** [PREFER] (EDGE) Use the smallest data type that keeps accuracy (fp16 or int8 tensors validated against a reference, `uint8_t` masks rather than `std::vector<bool>`, small enum fields). *Why:* smaller data moves faster through memory, which usually dominates. *Check:* manual. *Severity:* Minor. *Source:* CG Per.18; mD C++ 05; cv-kit.
- **CPP-PERF-15** [PREFER] Select the top K results with `std::nth_element` or `std::partial_sort`, not a full sort or a heap of everything. *Why:* NMS and top-K run every frame and a full sort does needless work. *Check:* manual. *Severity:* Minor. *Source:* mD C++ 05; cv-kit.

## CPP-HDR Header files, source files and scoping

- **CPP-HDR-1** [MUST] Name headers `.h` and sources `.cc`; a project that already uses `.hpp`/`.cpp` keeps that pair, and one tree never mixes both pairs. *Why:* one convention lets globs, build rules and reviewers find every file. *Check:* `grep: find . -name '*.hpp' -o -name '*.hh' -o -name '*.cpp' -o -name '*.cxx'` (compare with the project's pair). *Severity:* Minor. *Source:* Google C++ "Naming > File Names"; CG SF.1, NL.27; cv-kit.
- **CPP-HDR-2** [MUST] A fragment meant to be pasted in at a specific point (X-macro list, generated table) ends in `.inc`, is rare, and is the only kind of file allowed to skip a guard; never `#include` a `.cc`/`.cpp`, never create `-inl.h` files, and never write a computed include (`#include CVKIT_PLATFORM_HEADER`). *Why:* hidden or computed dependencies defeat include-cleaner, clangd and build-dependency scanning. *Check:* clang-tidy `bugprone-suspicious-include` for included sources; `grep: '#\s*include\s+[A-Za-z_]'`, `grep: '-inl\.h'`. *Severity:* Major. *Source:* Google C++ "Header Files > Self-contained Headers"; mD C++ 08 (3.4), mD BONUS Headers (2.5).
- **CPP-HDR-3** [MUST] Every `.cc` has a matching `.h` declaring what it exports, except unit tests and a file that holds only `main()`. *Why:* the header is the checked contract between the file and its users. *Check:* manual (script: `.cc` without a sibling `.h`). *Severity:* Minor. *Source:* Google C++ "Header Files".
- **CPP-HDR-4** [MUST] (EDGE) Every header compiles as the only include of an otherwise empty translation unit: it includes what it needs and has no "include X first" precondition. *Why:* code that leans on what an includer happened to pull in breaks when the target uses another standard library (libstdc++, libc++, an NDK release). *Check:* a generated one-include translation unit per header in CI; clang-tidy `misc-include-cleaner` for missing includes. *Severity:* Major. *Source:* Google C++ "Header Files > Self-contained Headers"; CG SF.11; mD BONUS Headers (2.4).
- **CPP-HDR-5** [MUST] Guard each header with `#ifndef`/`#define` as its first lines and `#endif  // <GUARD>` as its last, where the guard is `<PROJECT>_<PATH>_<FILE>_H_` built from the path under the project source root (`cvkit/infer/tensor.h` gives `CVKIT_INFER_TENSOR_H_`), upper case, trailing underscore, never starting with `_` and never containing `__`. *Why:* short guards (`UTILS_H`) collide between libraries and silently empty one of the two headers; a reversed `#ifdef` guard compiles nothing. *Check:* a script that derives the guard from the path; clang-tidy `readability-identifier-naming` accepts the `_H_` form (shipped `MacroDefinitionIgnoredRegexp`) and `bugprone-reserved-identifier` catches reserved guard names; `llvm-header-guard` stays off (it rejects correct Google guards); cpplint `build/header_guard` (not shipped). *Severity:* Minor (Major for a guard that can collide with another library's, such as `UTILS_H`). *Source:* Google C++ "Header Files > The #define Guard"; CG SF.8; mD C++ 09 (2.8), mD BONUS Headers (2.3, 2.4).
- **CPP-HDR-6** [MUST NOT] Use `#pragma once`, alone or beside a guard. *Why:* it is non-standard and can misfire on the symlinked or duplicated SDK headers found in cross-compilation sysroots. *Check:* clang-tidy `portability-avoid-pragma-once`. *Severity:* Minor. *Source:* Google C++ "Exceptions to the Rules > Windows Code"; CG SF.8; mD C++ 08 (3.12).
- **CPP-HDR-7** [MUST] (EDGE) Include what you use: each file directly includes a header that provides every symbol it names, including symbols its own `.h` already pulls in, and includes nothing it does not use; an umbrella header is allowed only when it says so in its file comment. *Why:* transitive includes differ between standard libraries and versions, so "works by accident" breaks on the target. *Check:* clang-tidy `misc-include-cleaner` (flags missing `<vector>`/`<cstddef>` and unused includes, with fixes). *Severity:* Minor. *Source:* Google C++ "Header Files > Include What You Use"; CG SF.10; mD BONUS Headers (2.4).
- **CPP-HDR-8** [MUST] Put every `#include` before any declaration or code, right after the file comment and the guard; the only late includes allowed are a short platform-conditional block at the end of the include list, and it belongs in the portability layer (CPP-LIB-13). *Why:* includes in the middle of a file hide dependencies and make results depend on what precedes them. *Check:* `grep` (an `#include` line after the first non-preprocessor line); manual. *Severity:* Minor. *Source:* Google C++ "Header Files > Names and Order of Includes"; CG SF.4; mD BONUS Headers (2.5, pitfall).
- **CPP-HDR-9** [MUST] Order includes in five groups separated by one blank line, alphabetical inside each: (1) the related header (`resize.h` for `resize.cc` and `resize_test.cc`), (2) C system headers (`<sys/mman.h>`, `<linux/videodev2.h>`), (3) C++ standard headers, (4) other libraries (OpenCV, TensorRT, ONNX Runtime, Abseil), (5) the project's own headers. *Why:* the related header first proves it self-contained in its own build; fixed groups make diffs and reviews predictable. *Check:* clang-format `IncludeBlocks: Regroup` with the shipped `IncludeCategories` once the `PROJECT_ROOT` placeholder is replaced (see Per-project settings). *Severity:* Minor. *Source:* Google C++ "Header Files > Names and Order of Includes"; CG SF.4, SF.5; mD BONUS Headers (2.2).
- **CPP-HDR-10** [MUST] Write project includes as quoted paths from the project source root (`"cvkit/infer/tensor.h"`), never with `.` or `..`; use angle brackets only for C/C++ standard and OS headers and for third-party libraries whose documentation requires them. *Why:* root-relative paths are unique and do not change meaning with the including file's location. *Check:* `grep: '#\s*include\s+"\.\.?/'`; manual. *Severity:* Minor. *Source:* Google C++ "Header Files > Names and Order of Includes"; CG SF.12 (conflict); mD C++ 01 (2.2).
- **CPP-HDR-11** [MUST] (EDGE) Spell every include path with the exact case of the file on disk and with `/` separators. *Why:* developers on case-insensitive macOS or Windows hosts build for case-sensitive Linux targets. *Check:* `grep: '#\s*include\s*[<"][^>"]*\\'`; clang `-Wnonportable-include-path` in a clang build; manual. *Severity:* Major. *Source:* CG SF.13.
- **CPP-HDR-12** [MUST NOT] Create include cycles; break them by moving declarations, not by trusting guards. *Why:* a cycle makes the result depend on which header is included first. *Check:* clang-tidy `misc-header-include-cycle`. *Severity:* Major. *Source:* CG SF.9.
- **CPP-HDR-13** [MUST NOT] Forward-declare an entity the project does not own (anything in `std`, `cv`, `nvinfer1`, `Ort`); include its header. For the project's own entities include too, and forward-declare only to break a cycle or to fix a measured compile-time problem, with a comment that says which. *Why:* forward declarations hide dependencies, break when the target becomes an alias or a template, and swapping one for an include can change which overload is chosen. *Check:* `grep: '^\s*(class|struct)\s+\w+;'` in headers, then manual; clang-tidy `bugprone-forward-declaration-namespace` catches only namespace mismatches. *Severity:* Major. *Source:* Google C++ "Header Files > Forward Declarations"; mD C++ 08 (2.4), mD BONUS Headers (2.4) (conflict).
- **CPP-HDR-14** [MUST] Define in a header only what is ODR-safe: classes, templates, `constexpr` functions, functions defined inside the class body, functions marked `inline`, and `inline` variables. *Why:* a plain definition in a header gives duplicate symbols, or silent ODR violations when TUs see different macros. *Check:* clang-tidy `misc-definitions-in-headers`. *Severity:* Major. *Source:* Google C++ "Header Files > Defining Functions in Header Files"; CG SF.2; mD C++ 08 (2.8, 2.9).
- **CPP-HDR-15** [MUST] (EDGE) A constant or table declared in a header is `inline constexpr` at namespace scope (or `extern const` in the header with one definition in a `.cc`); never a plain namespace-scope `const`/`constexpr` array or `std::array` in a header. *Why:* namespace-scope `const` has internal linkage, so every TU that uses a 16 KB lookup table may carry its own copy. *Check:* manual (`grep: '^\s*(static\s+)?(const|constexpr)\s.*(\[|std::array)'` in headers). *Severity:* Minor. *Source:* mD C++ 08 (2.9); CG SF.2; cv-kit.
- **CPP-HDR-16** [MUST] (EDGE) Define a function in a header only when its body is short (about 10 lines) or it must be visible (template, `constexpr`, an inline hot path backed by a profile); longer bodies go in the `.cc`. A long definition that must stay in the header sits below the public API (private section, an `internal` namespace, or after a comment marking the rest of the file as implementation detail). A template may live only in a `.cc` when every instantiation is there (explicit instantiation). *Why:* every header body is compiled in every includer, which costs build time and code size, and becomes part of the ABI. *Check:* manual (script counting body lines of in-header definitions). *Severity:* Major. *Source:* Google C++ "Header Files > Defining Functions in Header Files", "Self-contained Headers", "Classes > Declaration Order"; CG F.5; mD C++ 02 (2.6), mD BONUS Headers (2.5).
- **CPP-HDR-17** [MUST] Put all code in a namespace whose top level is the project's own (`cvkit`), opened after the includes and closed at the end of the file; only `main()` and `extern "C"` boundary functions may live in the global namespace. *Why:* global names collide with vendor SDKs and other plugins at link time. *Check:* clang-tidy `misc-use-internal-linkage` for external `.cc` symbols with no header declaration; `grep` for top-level declarations outside `namespace`. *Severity:* Major. *Source:* Google C++ "Scoping > Namespaces"; CG SF.20.
- **CPP-HDR-18** [MUST NOT] Write a using-directive (`using namespace x;`) anywhere: headers, `.cc` files, function bodies, tests, and `std::literals` included. Qualify names, or use a using-declaration for one name (`using ::cvkit::infer::Tensor;`) inside a `.cc` or a function body. *Why:* a directive imports an open-ended, changing set of names and can change overload resolution. *Check:* clang-tidy `google-build-using-namespace`. *Severity:* Major. *Source:* Google C++ "Scoping > Namespaces"; CG SF.6, SF.7 (conflict); mD C++ 01 (2.3) (conflict).
- **CPP-HDR-19** [MUST NOT] Put a namespace alias (`namespace fs = ...;`) or a using-declaration at namespace scope in a public header; they become part of its API. Both are fine in `.cc` files, function bodies, and namespaces marked internal. *Why:* every includer inherits the names. *Check:* clang-tidy `google-global-names-in-headers` (only the global namespace); `grep: '^\s*(namespace\s+\w+\s*=|using\s+[\w:]+::\w+\s*;)'` in headers. *Severity:* Minor. *Source:* Google C++ "Scoping > Namespaces", "Other C++ Features > Aliases".
- **CPP-HDR-20** [MUST NOT] (EDGE) Use inline namespaces. *Why:* they exist for ABI versioning, which the project does not do by hand. *Check:* `grep: 'inline\s+namespace'` (no clang-tidy check fires). *Severity:* Minor. *Source:* Google C++ "Scoping > Namespaces".
- **CPP-HDR-21** [MUST NOT] Declare anything in namespace `std`: no forward declarations and no specialisations; give an unordered container a hasher type as its template argument instead of specialising `std::hash`. *Why:* adding to `std` is undefined behaviour except for narrow cases, and the narrow cases are easy to get wrong. *Check:* clang-tidy `bugprone-std-namespace-modification` (`cert-dcl58-cpp` is the same check). *Severity:* Major. *Source:* Google C++ "Scoping > Namespaces"; CG SL.3 (conflict).
- **CPP-HDR-22** [MUST] Mark API parts that users must not name with an internal namespace that carries the library or file name (`cvkit::infer_internal`), and never name another library's internal namespace (`cv::detail`, `absl::..._internal`). *Why:* internal namespaces have no stability promise. *Check:* `grep: '::\w*(internal|detail)\w*::'` outside the owning library. *Severity:* Major. *Source:* Google C++ "Scoping > Namespaces".
- **CPP-HDR-23** [MUST] Write nested namespaces on one line (`namespace cvkit::infer {`). *Why:* one open, one close, one comment. *Check:* clang-tidy `modernize-concat-nested-namespaces`. *Severity:* Minor. *Source:* Google C++ "Scoping > Namespaces".
- **CPP-HDR-24** [MUST] (EDGE) Give every function, variable and type used only in one `.cc` internal linkage by putting it in an unnamed namespace, not with `static`, and do not repeat `static` inside that namespace. *Why:* two `.cc` files that each define a helper `struct Box` violate the ODR silently; internal symbols let the compiler inline and drop dead code. *Check:* clang-tidy `misc-use-internal-linkage`, `misc-use-anonymous-namespace`, `readability-static-definition-in-anonymous-namespace`. *Severity:* Major. *Source:* Google C++ "Scoping > Internal Linkage"; CG SF.22; mD C++ 08 (2.5, 2.7).
- **CPP-HDR-25** [MUST NOT] (EDGE) Open an unnamed namespace or declare a namespace-scope `static` function or variable in a header. *Why:* every TU gets its own copy of the code and data. *Check:* clang-tidy `google-build-namespaces`, `misc-anonymous-namespace-in-header`; `grep: '^static\s'` in headers. *Severity:* Major. *Source:* Google C++ "Scoping > Internal Linkage"; CG SF.21; mD C++ 08 (2.7).
- **CPP-HDR-26** [MUST] Declare each entity shared between files once, in a header that its defining `.cc` includes; no hand-written `extern` declarations of functions or variables inside `.cc` files. *Why:* a mismatched hand-written declaration is undiagnosed undefined behaviour. *Check:* `grep: '^\s*extern\s+[^"]'` in `.cc` files; clang-tidy `misc-use-internal-linkage`. *Severity:* Major. *Source:* CG SF.3, SF.5; mD C++ 08 (2.8).
- **CPP-HDR-27** [MUST] Put nonmember functions in a namespace rather than in a class made only of static members (a traits or policy class is the exception). *Why:* a namespace is the C++ unit of grouping (mutable globals: CPP-CONC-1). *Check:* manual. *Severity:* Minor. *Source:* Google C++ "Scoping > Nonmember, Static Member, and Global Functions".
- **CPP-HDR-28** [PREFER] Initialise a container with its contents (`std::vector<int> ids = {1, 2, 3};`) rather than with a run of `push_back` calls. *Why:* one statement, no reallocation churn. *Check:* manual. *Severity:* Minor. *Source:* Google C++ "Scoping > Local Variables".
- **CPP-HDR-29** [MUST NOT] (EDGE) Give static storage duration (namespace scope, static member, function-local `static`) to an object that is not trivially destructible: no `std::string`, `std::vector`, `std::map`, `std::unordered_map`, `std::function`, `std::unique_ptr`, `std::shared_ptr`, or class with a user-written destructor; a static reference bound to such a temporary counts too. *Why:* exit-time destructors run in an unspecified order and race with worker threads still running at shutdown. *Check:* clang-tidy `clang-diagnostic-exit-time-destructors` (catches a global `std::map`, a global `std::unique_ptr`, a function-local static `std::map`); it does not fire on a constant-initialised `const std::string` (C++20 constant destruction), so also `grep: '^\s*(static\s+)?(const\s+)?std::(string|vector|map|unordered_\w+|set|function|unique_ptr|shared_ptr)\b'` at namespace scope. *Severity:* Major (Critical when a thread can touch the object during exit). *Source:* Google C++ "Scoping > Static and Global Variables"; cv-kit; mD C++ 01 (2.5).
- **CPP-HDR-30** [MUST] Mark a constant-initialised static-storage variable `constexpr` (or `constinit` when it is mutable or not usable in constant expressions), and do not use dynamic initialisation for namespace-scope or static member variables at all; a value that needs run-time code becomes a function-local static or a member of an object built at init. *Why:* (EDGE) dynamic initialisation order across TUs is unspecified and adds startup time. *Check:* clang-tidy `clang-diagnostic-global-constructors` (flags `const int kLimit = Compute();`); clang-tidy `misc-static-initialization-cycle`, `cppcoreguidelines-interfaces-global-init`, `bugprone-dynamic-static-initializers`. *Severity:* Major. *Source:* Google C++ "Scoping > Static and Global Variables"; CG I.22.
- **CPP-HDR-31** [MUST] Use these forms for static data: a string constant is `constexpr std::string_view kName = "...";` (or `constexpr const char* kName = "...";` when a C API needs NUL termination); a lookup table is a `constexpr std::array` of trivially destructible elements (for example pairs of `int` and `std::string_view`), searched linearly or with `std::lower_bound` when sorted; a custom constant type has a `constexpr` constructor and a trivial destructor, backed by `static_assert(std::is_trivially_destructible_v<T>)`. If a dynamic container is truly needed, create it once and never destroy it (`static const auto& table = *new Table(...);` at function scope) and record the leak-checker suppression. *Why:* these forms live in read-only data and run no code at start or exit. *Check:* manual. *Severity:* Minor. *Source:* Google C++ "Scoping > Static and Global Variables" (common patterns); cv-kit.
- **CPP-HDR-32** [MUST] (EDGE) Touch a function-local static that has dynamic initialisation for the first time during startup or `Create()`, never first inside a per-frame real-time path. *Why:* the first call runs the initialiser under a guard lock, which is an allocation and a lock on the frame. *Check:* manual. *Severity:* Major. *Source:* Google C++ "Scoping > Static and Global Variables"; cv-kit.
- **CPP-HDR-33** [MUST] (EDGE) Declare a namespace- or class-scope `thread_local` `constinit`; get complex per-thread state from a function-scope `thread_local` behind an accessor; keep `thread_local` types trivially destructible and count their memory per thread, or at least never let one's destructor reach another `thread_local`; use `thread_local`, never `pthread_key_create` or `__thread`. *Why:* memory grows with the thread count, first access on a thread runs unbounded code (a stall on a real-time thread), and thread-exit destructors can touch thread-locals that are already gone. *Check:* `grep: 'thread_local'` without `constinit` outside function bodies; `grep: 'pthread_key_create|\b__thread\b'`. *Severity:* Major. *Source:* Google C++ "Scoping > thread_local Variables"; CG CP.1.

## CPP-LIB Library and language-feature policy

- **CPP-LIB-1** [MUST] (EDGE) Write C++20; use no C++23 language or library feature (`std::print`, `std::mdspan`, `std::flat_map`, `if consteval`, explicit object parameters) except the error type picked under CPP-ERR (`std::expected` only when the toolchain ships it). If a vendor toolchain (JetPack GCC, the NVCC host compiler, an NDK clang) is older, the project states its standard once and uses the fallback each rule names; check a feature against the oldest target toolchain before relying on it. *Why:* edge cross-toolchains lag the host. *Check:* build flags (CPP-BUILD); `grep: '#\s*include\s*<(print|mdspan|flat_map|flat_set|stacktrace|generator|expected)>'` (allow `<expected>` only where CPP-ERR picked it). *Severity:* Major. *Source:* Google C++ "C++ Version"; cv-kit.
- **CPP-LIB-2** [MUST NOT] (EDGE) Use C++20 modules (`export module`, `import`). *Why:* compiler, build-system and tool support is immature, more so on cross-toolchains. *Check:* `grep: '^\s*(export\s+)?(module|import)\b'`, files `*.cppm`, `*.ixx`. *Severity:* Major. *Source:* Google C++ "Other C++ Features > C++20 modules".
- **CPP-LIB-3** [MUST NOT] Include `<ratio>`, `<cfenv>`, `<fenv.h>` or `<filesystem>`. Using `std::chrono` durations, which use `std::ratio` internally, is fine. *Why:* they invite template-heavy interfaces, are unreliable across compilers (floating-point environment), or are weak for testing and security (filesystem). *Check:* clang-tidy `portability-restrict-system-includes` (the shipped `Includes` value bans the four headers and leaves `<chrono>` alone). *Severity:* Major. *Source:* Google C++ "Other C++ Features > Disallowed standard library features".
- **CPP-LIB-4** [MUST NOT] Use user-defined literal suffixes, the standard library's included (`"x"s`, `"x"sv`, `10ms`, `2i`): write `std::chrono::milliseconds(10)`, `std::string("x")`, `std::string_view("x")`. Defining `operator""` is banned too. *Why:* suffixes need a using-directive and hide the type. *Check:* `grep: '"[^"]*"(s|sv)\b|\b[0-9]+(h|min|s|ms|us|ns)\b|operator\s*""'`. *Severity:* Minor. *Source:* Google C++ "Classes > Operator Overloading"; CG SL.str.12, NL.11 (conflict).
- **CPP-LIB-5** [MUST] (EDGE) Before adding a library, use the one the codebase already uses for that job; otherwise prefer the standard library, then existing first-party code, then a new third-party library (Abseil only when it is already a dependency). A new dependency follows the project's licence, vendoring and pinning policy, cross-compiles for every target, and justifies its binary size; a library that can throw is called only behind the exception boundary of CPP-ERR. *Why:* every dependency is licence, patching and size cost on every device. *Check:* manual. *Severity:* Major. *Source:* Google C++ "Other C++ Features > Third-party Libraries"; CG SL.1, SL.2; cv-kit.
- **CPP-LIB-6** [MUST] Inside the portability layer, wrap each extension in a project-prefixed macro or inline function (`CVKIT_RESTRICT`, `CVKIT_PREDICT_TRUE(x)`, `CVKIT_EXPORT`, `CVKIT_ALWAYS_INLINE`) that has a portable fallback branch, and document each wrapper. *Why:* the wrapper can be switched off per compiler, and callers never see the extension. *Check:* manual. *Severity:* Major. *Source:* Google C++ "Other C++ Features > Nonstandard Extensions", "Exceptions to the Rules > Windows Code".
- **CPP-LIB-7** [MUST] Write type aliases with `using`, never `typedef`, and use alias templates to shorten trait expressions. *Why:* one readable syntax that also works for templates. *Check:* clang-tidy `modernize-use-using`. *Severity:* Minor. *Source:* Google C++ "Other C++ Features > Aliases"; CG T.42, T.43; mD C++ 01 (2.5).
- **CPP-LIB-8** [MUST] Treat an alias in a public header (namespace scope or a public class section) as API: add it only when callers are meant to use the name, and document whether it is guaranteed to stay the same type. Convenience aliases go in `.cc` files, function bodies, private sections or internal namespaces. Never alias a pointer type (`using FloatPtr = float*;`). *Why:* clients start depending on any alias they can see; a pointer alias hides where `const` applies. *Check:* manual. *Severity:* Major. *Source:* Google C++ "Other C++ Features > Aliases"; mD C++ 01 (2.5).
- **CPP-LIB-9** [MUST] (EDGE) Use streams only for developer-facing output in tools and tests; library diagnostics go through the project logger; device libraries include no `<iostream>` and use no `std::locale`/`imbue` on an inference path; do not use stream manipulators or stateful stream APIs (`std::hex`, `std::setprecision`, `xalloc`, `register_callback`); overload `<<` only for value types, printing the value, and put internals in a `DebugString()` method. *Why:* `<iostream>` adds static initialisers, locale machinery and size; stream state leaks between users. *Check:* clang-tidy `portability-restrict-system-includes` with `-iostream` in a device-code `.clang-tidy` (see Per-project settings); `grep: operator<<\s*\(\s*std::ostream` for operators to review; `grep: 'std::(cout|cerr|clog)|imbue|xalloc|register_callback|std::(hex|oct|setw|setprecision|setfill|fixed|scientific)\b'`. *Severity:* Major. *Source:* Google C++ "Other C++ Features > Streams", "Classes > Operator Overloading"; CG SL.io.3 (conflict), SL.str.10, C.167; cv-kit.
- **CPP-LIB-10** [MUST NOT] Define a macro where a C++ construct does the job: constants become `constexpr` variables or enumerators, inline code becomes a (`constexpr`) function or template, a long name becomes a reference or alias. Macros remain for include guards, the portability layer, and logging/check macros that need the call site (prefer `std::source_location` there too). *Why:* macros ignore scope and types and are invisible to the debugger. *Check:* clang-tidy `cppcoreguidelines-macro-usage` (the project allows its logging and check macros through `AllowedRegexp`, see Per-project settings), `modernize-macro-to-enum`. *Severity:* Major. *Source:* Google C++ "Other C++ Features > Preprocessor Macros"; CG ES.30, ES.31; mD C++ 08 (3, 3.5, 3.13).
- **CPP-LIB-11** [MUST NOT] Define macros in a header, except the guard and the documented, project-prefixed macros of the portability and logging headers; a macro needed in one `.cc` is defined right before its use and `#undef`'d right after; never `#undef` another component's macro to redefine it; never use a macro to declare pieces of an API (`class CVKIT_DECLARE(Foo)`), visibility macros such as `CVKIT_EXPORT` excepted. *Why:* a header macro leaks into every includer and cannot be namespaced. *Check:* `grep: '^\s*#\s*define'` in headers other than the guard and the two named headers; manual. *Severity:* Major. *Source:* Google C++ "Other C++ Features > Preprocessor Macros"; mD C++ 08 (3.9, 3.13).
- **CPP-LIB-12** [MUST] Write a macro that must exist hygienically: parenthesise every parameter use and the whole expression; wrap a multi-statement body in `do { ... } while (0)` with no trailing `;`; never put a `;` at the end of an object-like macro; never pass an argument with side effects to a macro that repeats it; do not paste identifiers with `##`; no `//` comment inside a `\`-continued body; pass a template type with a comma through an alias, not through extra parentheses. *Why:* each of these silently changes the expansion. *Check:* clang-tidy `bugprone-macro-parentheses`, `bugprone-multiple-statement-macro`, `bugprone-macro-repeated-side-effects`; the rest manual. *Severity:* Major. *Source:* Google C++ "Other C++ Features > Preprocessor Macros"; mD C++ 08 (3.2, 3.6, 3.10, 3.14, 3.16).
- **CPP-LIB-13** [MUST] (EDGE) Confine `#if`/`#ifdef` on platform, compiler, ISA or feature to the portability layer or to per-platform `.cc` files that the build selects; test feature macros with `#if defined(CVKIT_HAS_NEON)` or give them explicit `0`/`1` values (with `-Wundef`); keep each block small; never wrap API declarations in `#if`. *Why:* scattered conditional code is untested in most builds, and a misspelt macro in `#if` silently evaluates to 0. *Check:* `grep: '^\s*#\s*(if|ifdef|ifndef|elif)\b'` outside guards and the portability layer; `-Wundef` (CPP-BUILD). *Severity:* Major. *Source:* Google C++ "Other C++ Features > Preprocessor Macros" (conflict), "Header Files > Names and Order of Includes"; mD C++ 08 (3.5, 3.10).
- **CPP-LIB-14** [PREFER] Use `static_assert` rather than `#error` when the condition is a C++ expression (`static_assert(sizeof(void*) == 8)`), and `std::source_location` rather than `__FILE__`/`__LINE__` in new logging helpers. *Why:* both are typed and scoped. *Check:* manual. *Severity:* Minor. *Source:* mD C++ 08 (3.11, 3.15).
- **CPP-LIB-15** [MUST] Choose container construction syntax on purpose: `std::vector<float> scores(n, 0.0f)` makes `n` elements, while braces always mean an element list (`scores{n, 0.0f}` holds two elements). *Why:* a non-empty brace list prefers the `std::initializer_list` constructor (brace initialisation in general: CPP-EXPR-6). *Check:* manual. *Severity:* Major (Critical when the wrong size reaches a buffer or a model input). *Source:* Google C++ "Formatting > Variable and Array Initialization"; CG SL.con.2; mD C++ 01 (2.5, 2.19).
- **CPP-LIB-16** [MUST] Own text with `std::string`; take read-only text you do not own as `std::string_view` and never keep the view past the call unless the lifetime is documented, nor bind it to a temporary; take writable characters as `std::span<char>`; carry opaque bytes (model blobs, DMA buffers) as `std::byte`/`std::span<std::byte>` and numeric pixels as `uint8_t`; use `const char*` only for NUL-terminated strings at C-API boundaries, documented as such. *Why:* each type then says what it is and who owns it. *Check:* clang-tidy `bugprone-dangling-handle`, `bugprone-suspicious-stringview-data-usage`, `bugprone-stringview-nullptr`; `grep: const char\s*\*` in non-wrapper headers; manual. *Severity:* Major. *Source:* CG SL.str.1, SL.str.2, SL.str.3, SL.str.4, SL.str.5, SL.str.11, F.25; Google C++ "Functions > Function Overloading"; mD C++ 01 (2.14).
- **CPP-LIB-17** [MUST NOT] Use C string and conversion functions in C++ code (`strcpy`, `strcat`, `sprintf`, `strtok`, `gets`, `atoi`, `atof`) or the `std::stoi` family (it aborts here, CPP-ERR-15); use `std::string`, `std::string_view` and `std::from_chars`/`std::to_chars`, which neither throw nor allocate and report errors. *Why:* overflow, missing terminators, and no way to tell `0` from failure. *Check:* clang-tidy `bugprone-unsafe-functions`, `bugprone-unchecked-string-to-number-conversion`, `bugprone-not-null-terminated-result`. *Severity:* Major. *Source:* CG SL.str.1; mD C++ 01 (2.14, 2.15).
- **CPP-LIB-18** [MUST NOT] (EDGE) Include `<regex>` in device code; parse with plain code, or do the work offline. *Why:* `std::regex` is slow and large. *Check:* clang-tidy `portability-restrict-system-includes` with `-regex` in a device-code `.clang-tidy` (see Per-project settings); `grep: #\s*include\s*<regex>`. *Severity:* Major. *Source:* CG SL.regex; cv-kit.
- **CPP-LIB-19** [MUST NOT] Use `setjmp`/`longjmp`; a C library that uses them internally (libjpeg, libpng) stays behind its C wrapper (CPP-RES-2). *Why:* they skip destructors. *Check:* clang-tidy `modernize-avoid-setjmp-longjmp` (same as `cert-err52-cpp`; ignore its advice to use exceptions). *Severity:* Critical. *Source:* CG SL.C.1.
- **CPP-LIB-20** [MUST] (EDGE) Treat every file, config, model and sensor read as untrusted: check sizes, magic numbers and versions where the data enters; read whole buffers (`read` into a pre-sized buffer, or `mmap`) rather than byte by byte; test the result of each read, never `eof()` before it. *Why:* malformed input is normal, and `while (!f.eof())` processes the last item twice. *Check:* manual. *Severity:* Major. *Source:* CG SL.io.1, SL.io.2; mD C++ 02 (2.4); see CPP-ERR.
- **CPP-LIB-21** [MUST] Drop C idioms in C++ files: `f()` not `f(void)`; `<cstdio>`-style names for standard C headers (a header shared with C keeps `<stdio.h>` with a NOLINT reason); `struct Foo { ... };` not `typedef struct { ... } Foo;`; no `malloc`/`free` (CPP-RES-6). *Why:* the C forms add nothing in C++ and some change linkage or names. *Check:* clang-tidy `modernize-redundant-void-arg`, `modernize-deprecated-headers` (flags `<stdio.h>`), `cppcoreguidelines-no-malloc`. *Severity:* Minor. *Source:* CG NL.25, CPL.1; Google C++ "Header Files > Names and Order of Includes" (conflict); mD C++ 09 (2.1), mD C++ 01 (2.5).

## CPP-NAME Naming

Naming table (Google naming; the last column is the `readability-identifier-naming` option in the shipped
`.clang-tidy` that checks it):

| Entity | Pattern | Example | clang-tidy option |
|---|---|---|---|
| File | lower snake case, `.h` / `.cc` / `.inc`; tests `_test.cc` | `frame_queue.h`, `frame_queue_test.cc` | none (script, CPP-NAME-3) |
| Class, struct, union | PascalCase | `FrameQueue`, `Pixel` | `ClassCase`, `StructCase`, `UnionCase` |
| Type alias, typedef | PascalCase | `TensorMap` | `TypeAliasCase`, `TypedefCase` |
| Enum type | PascalCase | `ColorOrder` | `EnumCase` |
| Enumerator (scoped or not) | `k` + PascalCase | `ColorOrder::kBgr` | `EnumConstantCase`, `EnumConstantPrefix: k` |
| Concept | PascalCase | `TensorLike` | `ConceptCase` |
| Type template parameter | PascalCase | `T`, `Pixel` | `TypeTemplateParameterCase` |
| Non-type template parameter | snake case, or `k` + PascalCase | `channels`, `kChannels` | `ValueTemplateParameterCase`, `ValueTemplateParameterIgnoredRegexp` |
| Local variable, parameter | snake case | `frame_index` | `VariableCase`, `ParameterCase` |
| Class data member (any access) | snake case + `_` | `queue_`, `max_items_` | `PrivateMemberSuffix`, `ProtectedMemberSuffix` |
| Class static data member | snake case + `_` | `instances_` | `ClassMemberCase`, `ClassMemberSuffix` |
| Struct data member | snake case, no `_` | `num_boxes` | `PublicMemberCase` (a struct's static member needs the NOLINT of CPP-NAME-7) |
| Static-storage constant (namespace, static member, static local) | `k` + PascalCase | `kMaxBatch` | `GlobalConstant*`, `StaticConstant*`, `ClassConstant*` |
| Any `constexpr` variable, locals included | `k` + PascalCase | `kTileSize` | `ConstexprVariableCase`, `ConstexprVariablePrefix: k` |
| Constant whose digits need a separator | `k` + PascalCase + `_digits` | `kVersion1_2` | `GlobalConstantIgnoredRegexp`, `ConstexprVariableIgnoredRegexp` |
| Non-`constexpr` local `const` | snake case, or `kName` if fixed for all calls | `stride`, `kPrefix` | `LocalConstantCase`, `LocalConstantIgnoredRegexp` |
| Function, method | PascalCase | `DecodeFrame()` | `FunctionCase`, `MethodCase` (`main` exempt) |
| Accessor, mutator | snake case | `size()`, `set_threshold()` | `MethodIgnoredRegexp` lets every snake case method pass, so this is manual |
| Function-like API constant | PascalCase, no `k` | `constexpr auto Clamp = ...;` | flagged as a `constexpr` variable; NOLINT (CPP-NAME-11) |
| Namespace | snake case; top level is the project | `cvkit::infer` | `NamespaceCase` |
| Macro | `PROJECT_` + upper snake case | `CVKIT_CHECK(x)` | `MacroDefinitionCase: UPPER_CASE`; the prefix needs `MacroDefinitionPrefix` (Per-project settings) |
| Header guard | `<PROJECT>_<PATH>_<FILE>_H_` | `CVKIT_INFER_TENSOR_H_` | `MacroDefinitionIgnoredRegexp` |

- **CPP-NAME-1** [MUST] Choose names a reader from another team understands without context: the wider the visibility, the more specific the name (an API function names its domain, a loop index can be `i`); do not restate what the enclosing scope already says, do not drop letters inside words (`cnt`, `img_cstm`), and do not give widely visible things vague names (`Result`, `Data`, `Process`, `kNum`). *Why:* names are the first documentation. *Check:* manual. *Severity:* Minor. *Source:* Google C++ "Naming > Choosing Names"; CG NL.7.
- **CPP-NAME-2** [MUST] Use only abbreviations a CV engineer outside the team knows, listed in the project glossary (cv-kit default: `nms`, `iou`, `roi`, `fps`, `bbox`, `rgb`, `bgr`, `yuv`, `nchw`, `nhwc`, `fp16`, `int8`, `cuda`, `onnx`, `trt`), and capitalise them as one word in PascalCase (`RgbToYuv`, `OnnxSession`, `NmsThreshold`, not `RGBToYUV`). *Why:* consistent word boundaries keep names searchable. *Check:* manual (`CamelCase` accepts `StartRPC`). *Severity:* Minor. *Source:* Google C++ "Naming > Choosing Names"; cv-kit.
- **CPP-NAME-3** [MUST] Name files in lower snake case (keep `-` only where the project already uses it), specific to their content (`frame_queue.h`, not `utils.h`), matching the main class (`frame_queue.h` holds `FrameQueue`), tests as `<name>_test.cc`, and never with a basename that exists in `/usr/include` (`time.h`, `math.h`). *Why:* a local `math.h` can shadow the system header. *Check:* script: `find . -regex '.*[A-Z].*\.\(h\|cc\)'` plus a basename comparison with `/usr/include`. *Severity:* Minor. *Source:* Google C++ "Naming > File Names"; mD C++ 01 (2.2).
- **CPP-NAME-4** [MUST] Name every type in PascalCase without underscores: classes, structs, unions, enums, aliases, typedefs, type template parameters and concepts. *Why:* the shape of the name says "type". *Check:* clang-tidy `readability-identifier-naming`. *Severity:* Minor. *Source:* Google C++ "Naming > Type Names", "Concept Names", "Template Parameter Names".
- **CPP-NAME-5** [MUST] Name variables and parameters in snake case (`frame_index`); no camelCase, no Hungarian or type prefixes (`pBuf`, `iCount`, `m_`, `str_name`). *Why:* the type belongs in the type system, not in the name. *Check:* clang-tidy `readability-identifier-naming`. *Severity:* Minor. *Source:* Google C++ "Naming > Variable Names", "Exceptions to the Rules > Windows Code"; CG NL.5, NL.10 (conflict).
- **CPP-NAME-6** [MUST] End every data member of a class with `_`, static and non-static, any access, `const` non-static members included (`max_items_`, not `kMaxItems`); static constants follow CPP-NAME-8. *Why:* members are visible as members at every use. *Check:* clang-tidy `readability-identifier-naming` (`ClassMemberSuffix` covers static members). *Severity:* Minor. *Source:* Google C++ "Naming > Variable Names"; cv-kit (non-static `const` members).
- **CPP-NAME-7** [MUST] Name struct data members, static or not, in plain snake case without `_` (`num_boxes`). *Why:* a struct is passive data and reads like a record. *Check:* clang-tidy `readability-identifier-naming` (flags `num_boxes_`); the class static-member option also flags a struct's static member, so it takes `// NOLINT(readability-identifier-naming): struct static member` or moves into a class. *Severity:* Minor. *Source:* Google C++ "Naming > Variable Names".
- **CPP-NAME-8** [MUST] Name with `k` + PascalCase every `const`/`constexpr` variable with static storage duration (namespace scope, static members, function-local statics, `static constexpr` members of templates) and every `constexpr` variable, local ones included; where digits need a separator use `_` (`kVersion1_2`); never ALL_CAPS. *Why:* one visible mark for "fixed for the whole run"; requiring it for local `constexpr` matches the tool. *Check:* clang-tidy `readability-identifier-naming` (the digit form passes through the shipped `GlobalConstantIgnoredRegexp` and `ConstexprVariableIgnoredRegexp`). *Severity:* Minor. *Source:* Google C++ "Naming > Constant Names"; CG NL.9 (conflict); mD C++ 01 (2.5), mD C++ 08 (2.6).
- **CPP-NAME-9** [MUST NOT] Give a `k` name to a local whose value is computed at run time or differs between calls (`const int kStride = width * 3;`); name it `stride`. *Why:* `k` promises a program-wide constant. *Check:* manual (the tool accepts both forms for non-`constexpr` locals). *Severity:* Minor. *Source:* Google C++ "Naming > Constant Names".
- **CPP-NAME-10** [MUST] Name functions and methods in PascalCase (`DecodeFrame`); snake case is allowed only for cheap accessors and mutators that behave like a member variable (`size()`, `set_threshold(float threshold)`); a method that allocates, locks, blocks or computes is PascalCase. *Why:* snake case signals "as cheap as reading a field". *Check:* clang-tidy `readability-identifier-naming` (catches camelCase; the accessor exemption lets every snake case method pass, so snake case methods are reviewed by hand). *Severity:* Minor. *Source:* Google C++ "Naming > Function Names".
- **CPP-NAME-11** [MUST] Name a namespace-scope or class-scope constant that callers use like a function (a function object or lambda constant) in PascalCase without `k`, with `// NOLINT(readability-identifier-naming): function-like constant`. *Why:* at the call site it reads as a function. *Check:* manual (flagged as a `constexpr` variable). *Severity:* Minor. *Source:* Google C++ "Naming > Function Names".
- **CPP-NAME-12** [MUST] Name namespaces in snake case; the top level is the project's own unique name and matches its directory (`cvkit/infer/` holds `cvkit::infer`); never name a nested namespace after a well-known top-level one (`std`, `absl`, `cv`, `cuda`, `nvinfer1`, `Ort`, `tflite`). *Why:* unqualified lookup finds the nested one first and the error is confusing. *Check:* clang-tidy `readability-identifier-naming`; `grep: 'namespace\s+(std|absl|cv|cuda|nvinfer1|Ort|tflite)\b'` inside project namespaces. *Severity:* Minor. *Source:* Google C++ "Naming > Namespace Names".
- **CPP-NAME-13** [MUST] Name enumerators of scoped and unscoped enums like constants (`kOk`, `kOutOfMemory`), never like macros (`OUT_OF_MEMORY`). *Why:* macro-style enumerators collide with macros. *Check:* clang-tidy `readability-identifier-naming` (both kinds). *Severity:* Minor. *Source:* Google C++ "Naming > Enumerator Names"; CG NL.9.
- **CPP-NAME-14** [MUST] Name a type template parameter like a type (`T`, `Pixel`) and a non-type template parameter like a variable or a constant (`channels` or `kChannels`). *Why:* the parameter reads like the entity it stands for. *Check:* clang-tidy `readability-identifier-naming` (`ValueTemplateParameterCase` with its `k` regexp accepts both forms). *Severity:* Minor. *Source:* Google C++ "Naming > Template Parameter Names".
- **CPP-NAME-15** [MUST] Name every macro in upper snake case with the project prefix (`CVKIT_CHECK(x)`, `CVKIT_INFER_TENSOR_H_`), never in lower case or PascalCase. *Why:* a lower-case macro silently rewrites every matching identifier (`min`, `max`). *Check:* clang-tidy `readability-identifier-naming` (guards pass through `MacroDefinitionIgnoredRegexp`; the project prefix needs `MacroDefinitionPrefix`, see Per-project settings). *Severity:* Minor. *Source:* Google C++ "Naming > Macro Names"; CG NL.9; mD C++ 08 (3.1, 3.6).
- **CPP-NAME-16** [MUST NOT] Use a reserved identifier: any name containing `__`, any name starting with `_` and an upper-case letter, any global name starting with `_`; guards included. *Why:* these belong to the implementation; using them is undefined behaviour. *Check:* clang-tidy `bugprone-reserved-identifier` (flags `__MYCLASS_H_INCLUDED__`). *Severity:* Major. *Source:* CG NL.8; mD BONUS Headers (2.4), mD C++ 08 (3.10).
- **CPP-NAME-17** [MUST] Name an alias by the same rules as any new name, judged where the alias is declared, not where the original lives. *Why:* the alias is read in its own context. *Check:* clang-tidy `readability-identifier-naming` (case); fit: manual. *Severity:* Minor. *Source:* Google C++ "Naming > Aliases".
- **CPP-NAME-18** [MUST] A type or function that mirrors a standard-library or C entity may copy that entity's naming (`begin()`, `end()`, `size()`, `value_type`, `iterator`, a `cvkit_open()` beside `open()`), each with `// NOLINT(readability-identifier-naming): mirrors <entity>`; vendored third-party and generated code keep their own style and are excluded from the naming check. *Why:* generic code and readers expect the standard names. *Check:* manual. *Severity:* Minor. *Source:* Google C++ "Naming > Exceptions to Naming Rules"; CG NL.8.
- **CPP-NAME-19** [MUST NOT] Use easily confused names in one scope (`l` beside `1`, `O` beside `0`, `box` beside `boxes_` for different things) or non-ASCII identifiers. *Why:* misreading a name is a bug. *Check:* clang-tidy `misc-confusable-identifiers`, `misc-misleading-identifier` (Unicode cases only); manual. *Severity:* Minor. *Source:* CG NL.19.
- **CPP-NAME-20** [MUST] Use inclusive, neutral terms in names and comments (`allowlist`/`denylist`, `primary`/`replica`, `leader`/`follower`), `they` for a person of unknown gender and `it` for software. *Why:* code is read by everyone on the team. *Check:* `grep -iE '\b(master|slave|blacklist|whitelist|redline)\b'` (expect hits in third-party names, which keep theirs). *Severity:* Minor. *Source:* Google C++ "Inclusive Language".

## CPP-FMT Formatting

clang-format output is final; the rules below say what it produces and the few points it leaves to people.

- **CPP-FMT-1** [MUST] Every C++ file passes `clang-format --dry-run -Werror` with the project's `.clang-format` (cv-kit ships `BasedOnStyle: Google`, `Standard: c++20`, `DerivePointerAlignment: false`, `PointerAlignment: Left`, `InsertBraces: true`, `IncludeBlocks: Regroup`); nobody hand-formats against it, and CI runs the check on changed files. *Why:* formatting is a tool's job, not a review topic. *Check:* clang-format in CI (exit 1 on violations). *Severity:* Minor. *Source:* Google C++ "Formatting"; cv-kit.
- **CPP-FMT-2** [MUST] Keep lines within 80 columns. Allowed overruns: `#include` lines, guard lines, using-declarations, a comment line holding one URL or command, and a string literal that must stay whole (URI, embedded language, help text with newlines); outside tests such a literal is a named constant at namespace scope near the top of the file. *Why:* side-by-side diffs and small screens. *Check:* clang-format (`ColumnLimit: 80`; wraps calls and parameters, splits long literals, moves a long URL onto its own comment line, never splits an `#include`); manual for the literal placement. *Severity:* Minor. *Source:* Google C++ "Formatting > Line Length".
- **CPP-FMT-3** [MUST] Indent with spaces only, 2 per level and 4 for continuation lines. *Why:* one rendering everywhere. *Check:* clang-format (`UseTab: Never`, `IndentWidth: 2`, `ContinuationIndentWidth: 4`; tab replaced). *Severity:* Minor. *Source:* Google C++ "Formatting > Spaces vs. Tabs"; CG NL.4.
- **CPP-FMT-4** [MUST] Brace every controlled statement, one-line `if` and loop bodies and each branch of `if`/`else` included; break after `{` and before `}`. *Why:* adding a second statement to an unbraced body is a classic bug. *Check:* clang-format `InsertBraces: true`; clang-tidy `readability-braces-around-statements` (`ShortStatementLines: 0`). *Severity:* Minor. *Source:* Google C++ "Formatting > Looping and Branching Statements" (conflict: Google allows short unbraced bodies); cv-kit.
- **CPP-FMT-5** [MUST] Lay out function declarations and definitions as Google does: return type and name on one line (break between them only when needed, without indenting the name), `(` attached to the name, no spaces inside the parentheses, parameters on one line or wrapped aligned with the first or after `(` with a 4-space indent, and `) {` with the brace at the end of the line. *Why:* one shape for every signature. *Check:* clang-format. *Severity:* Minor. *Source:* Google C++ "Formatting > Function Declarations and Definitions"; CG NL.17 (conflict).
- **CPP-FMT-6** [MUST] Format calls and braced initialiser lists the same way: arguments packed per line, wrapped aligned or after `(`/`{` with a 4-space indent, no spaces just inside the brackets (`{0}`). Structured literals (convolution kernels, camera matrices, colour coefficients) may be laid out by hand inside a `// clang-format off` region (CPP-FMT-7). *Why:* layout shows structure only where structure exists. *Check:* clang-format (`{ 0 }` becomes `{0}`; a 3x3 kernel is repacked unless inside `off`/`on`). *Severity:* Minor. *Source:* Google C++ "Formatting > Function Calls", "Braced Initializer List Format".
- **CPP-FMT-7** [MUST] Keep each `// clang-format off` region as small as possible, use it only for structured data or content the formatter damages, and give the reason on the `off` line. *Why:* unformatted regions rot. *Check:* `grep: 'clang-format off'` (regions are honoured). *Severity:* Minor. *Source:* Google C++ "Formatting > Line Length", "Function Calls".
- **CPP-FMT-8** [MUST] Format a lambda's parameters and body like a function and its captures like a list, with no space in a by-reference capture (`[&count]`). Lambda semantics: CPP-FN/CPP-EXPR. *Why:* consistency with functions. *Check:* clang-format (`[& a]` becomes `[&a]`). *Severity:* Minor. *Source:* Google C++ "Formatting > Lambda Expressions".
- **CPP-FMT-9** [MUST] Space control statements as Google does: `if (ready) {`, `} else {`, `for (int i = 0; i < n; ++i) {`, `for (const auto& box : boxes) {`, `switch (mode) {` with `case` indented 2 and its body 4, `case kFast:` with no space before the colon. *Why:* one shape for every statement. *Check:* clang-format. *Severity:* Minor. *Source:* Google C++ "Formatting > Looping and Branching Statements", "Horizontal Whitespace".
- **CPP-FMT-10** [MUST] Attach `*` and `&` to the type in declarations (`float* data`, `const Tensor& input`, `std::vector<float*>`), and write unary `*p`, `&x` and member access `a.b`, `a->b` without spaces. *Why:* one style per codebase. *Check:* clang-format `PointerAlignment: Left` with `DerivePointerAlignment: false` (the Google preset alone keeps a file's majority style). *Severity:* Minor. *Source:* Google C++ "Formatting > Pointer and Reference Expressions and Types"; CG NL.18.
- **CPP-FMT-11** [MUST] Write one statement per line. *Why:* debuggers, diffs and coverage work per line. *Check:* clang-format. *Severity:* Minor. *Source:* CG NL.20.
- **CPP-FMT-12** [MUST] Break a long boolean expression after its operators, with `&&` and `||` at line ends. *Why:* one consistent wrap. *Check:* clang-format (`BreakBeforeBinaryOperators: None`). *Severity:* Minor. *Source:* Google C++ "Formatting > Boolean Expressions".
- **CPP-FMT-13** [MUST] Use the symbolic operators (`&&`, `||`, `!`, `~`, `^`), never the alternative tokens (`and`, `or`, `not`, `compl`, `xor`). *Why:* readers and tools expect the symbols. *Check:* clang-tidy `readability-operators-representation` (the shipped operator lists make it flag `and`, `not` and the other alternative tokens). *Severity:* Minor. *Source:* Google C++ "Formatting > Boolean Expressions".
- **CPP-FMT-14** [MUST NOT] Parenthesise a returned expression without need (`return (count);`); keep parentheses only to group a complex multi-line expression, or where they change meaning (`return (member_);` in a `decltype(auto)` function returns a reference, so it needs a comment). *Why:* stray parentheses suggest a meaning that is not there. *Check:* manual (the shipped `.clang-format` keeps `RemoveParentheses: Leave`; see Per-project settings). *Severity:* Minor. *Source:* Google C++ "Formatting > Return Values".
- **CPP-FMT-15** [MUST] Start every preprocessor directive with `#` in column 0, also inside indented code, and do not indent nested directives. *Why:* directives are not code and should not look nested in it. *Check:* clang-format (`IndentPPDirectives: None`). *Severity:* Minor. *Source:* Google C++ "Formatting > Preprocessor Directives".
- **CPP-FMT-16** [MUST] Lay out a class with its sections in the order `public`, `protected`, `private`, each at most once and empty ones omitted; inside a section put types, constants, factories, constructors and assignment, destructor, other methods, then data; access specifiers indented 1 space and members 2; a blank line before each specifier except the first and none after; base classes on the class line. *Why:* readers find the interface first. *Check:* clang-format for indentation and blank lines (adds the blank line before `private:`/`protected:`, removes one after `public:`, does not reorder sections); clang-tidy `readability-redundant-access-specifiers`; section and member order manual. *Severity:* Minor. *Source:* Google C++ "Formatting > Class Format", "Classes > Declaration Order"; CG NL.16.
- **CPP-FMT-17** [MUST] Put a constructor initialiser list on the signature line when it fits, else break before `:` with a 4-space indent, and give each member its own line when the list does not fit on one. *Why:* one shape for every constructor. *Check:* clang-format (`BreakConstructorInitializers: BeforeColon`, `PackConstructorInitializers: NextLine`). *Severity:* Minor. *Source:* Google C++ "Formatting > Constructor Initializer Lists".
- **CPP-FMT-18** [MUST] Do not indent namespace contents, and close every namespace with `}  // namespace name` (`}  // namespace` for an unnamed one). *Why:* the closing comment says what ends at a far-away brace. *Check:* clang-format (`NamespaceIndentation: None`, `FixNamespaceComments: true`; comment added); clang-tidy `google-readability-namespace-comments`. *Severity:* Minor. *Source:* Google C++ "Formatting > Namespace Formatting", "Scoping > Namespaces", "Scoping > Internal Linkage".
- **CPP-FMT-19** [MUST] Keep horizontal whitespace to Google's form: no trailing spaces; two spaces before an end-of-line comment; spaces around assignment and binary operators, none between a unary operator and its operand; no padding inside `()`, `<>` or `[]`; a space before `{`; `{}` empty without a space. *Why:* whitespace noise hides real changes. *Check:* clang-format (trailing spaces, `std::vector< int >`, `F(int a,int b)` all fixed). *Severity:* Minor. *Source:* Google C++ "Formatting > Horizontal Whitespace"; CG NL.15.
- **CPP-FMT-20** [MUST] Use blank lines sparingly: at most one in a row, none at the start or end of a block, and otherwise only to separate logical steps like paragraphs. *Why:* more code on screen, and blank lines keep meaning. *Check:* clang-format (`MaxEmptyLinesToKeep: 1`, `KeepEmptyLines.AtStartOfBlock: false`; three blank lines before `}` removed); paragraphs: manual. *Severity:* Minor. *Source:* Google C++ "Formatting > Vertical Whitespace".
- **CPP-FMT-21** [MUST] Write floating-point literals with digits on both sides of the point, exponent form included, and a lower-case `f` (upper-case `L`): `0.5f`, `1.0f / 255.0f`, `1.0e-6f`; not `.5f`, `1.f`, `1e-6f` or `1.0F`. Whether to use `float` or `double` literals: CPP-EDGE-15. *Why:* the point and the suffix are easy to miss. *Check:* `grep -E '(^|[^0-9A-Za-z_.])\.[0-9]|[0-9]\.([fFlL]|[^0-9fFlL]|$)|(^|[^0-9.xX])[0-9]+[eE][-+]?[0-9]'` (noisy; review hits); clang-tidy `readability-uppercase-literal-suffix` (the shipped `NewSuffixes` accept `1.0f` and flag `1.0F`). *Severity:* Minor. *Source:* Google C++ "Formatting > Floating-point Literals"; cv-kit.
- **CPP-FMT-22** [PREFER] Group the digits of long literals with digit separators (`1'000'000`, `0xFF'00'FF'00`). *Why:* long digit runs are easy to miscount, especially register masks. *Check:* `grep -E '\b[0-9]{7,}\b|0[xX][0-9a-fA-F]{9,}'`. *Severity:* Minor. *Source:* CG NL.11.
- **CPP-FMT-23** [MUST] Put attributes, and macros that expand to attributes, first in a declaration, before the return type (`[[nodiscard]] Status Load(std::string_view path);`, `CVKIT_EXPORT Status Init();`). *Why:* one place to look for them. *Check:* manual (clang-format does not move tokens). *Severity:* Minor. *Source:* Google C++ "Formatting > Function Declarations and Definitions".
- **CPP-FMT-24** [MUST] Keep source ASCII where possible and always UTF-8: non-ASCII only in tests or as delimiters of parsed external data, never in identifiers; invisible characters written as escapes (`\uFEFF`); no `u8` prefix; no `char16_t`, `char32_t` or `wchar_t` except at Windows API calls; no user-facing text hard-coded in the source. *Why:* encodings and invisible characters break builds and reviews. *Check:* `grep -P '[^\x00-\x7F]'`, `grep -E '\bu8"|\bchar(16|32)_t\b|\bwchar_t\b'`; clang-tidy `misc-misleading-bidirectional`. *Severity:* Minor (Major for bidirectional control characters). *Source:* Google C++ "Formatting > Non-ASCII Characters".
- **CPP-FMT-25** [PREFER] Write `const` before the type (`const float* data`, `const Tensor& t`). *Why:* one reading order across the codebase. *Check:* manual (shipped `QualifierAlignment: Leave`; the alternative is documented by clang-format as possibly unsafe). *Severity:* Minor. *Source:* CG NL.26.
- **CPP-FMT-26** [MUST] Restyle code written to another convention in a separate change: a behaviour change formats only the lines it touches (`git clang-format`), and a formatting change contains no behaviour change; until then, new lines in such a file match cv-kit, not the old style. *Why:* mixed diffs hide behaviour changes. *Check:* manual (diff review). *Severity:* Minor. *Source:* Google C++ "Exceptions to the Rules > Existing Non-conformant Code", "Formatting > Horizontal Whitespace".
- **CPP-FMT-27** [MUST] End every file with exactly one newline. *Why:* POSIX text files, clean diffs. *Check:* clang-format (`InsertNewlineAtEOF: true`). *Severity:* Minor. *Source:* cv-kit.

## CPP-DOC Comments

- **CPP-DOC-1** [MUST] Write comments with `//`; use `/* */` only for `/*name=*/` argument comments, commented-out parameter names, and a licence block where the project's existing policy uses one. *Why:* Google allows either if consistent; cv-kit picks the common one. *Check:* `grep -n '/\*'` excluding `/\*\w+=?\*/`. *Severity:* Minor. *Source:* Google C++ "Comments > Comment Style".
- **CPP-DOC-2** [MUST] Follow the project's existing licence-header policy: if files carry a header (an SPDX line, or a full block), every new file carries the same one; if the repository relies on a single `LICENSE` file, do not add headers. Do not add author lines to new files (version control records authorship). *Why:* Google's text both requires boilerplate in every file and says new files usually have none, so the project's own convention decides. *Check:* manual (cpplint `legal/copyright` checks presence; not shipped). *Severity:* Minor. *Source:* Google C++ "Comments > File Comments" (self-contradictory); cv-kit.
- **CPP-DOC-3** [MUST] Start a header that declares several public abstractions with a file comment that says what the collection is and what does not belong in it; detailed documentation stays with each abstraction. A `.cc` without a header that defines several classes has its own file comment; `foo.cc` and `foo_test.cc` need none when `foo.h` has one. *Why:* the next author needs to know where new code goes. *Check:* manual. *Severity:* Minor. *Source:* Google C++ "Comments > File Comments".
- **CPP-DOC-4** [MUST] Precede every non-obvious class or struct with a comment saying what it is for, how and when to use it, the invariants a caller must respect, and (EDGE) its thread-safety: whether one instance may be used from several threads and which methods are safe concurrently (inference sessions, buffer pools, camera callbacks); add a short usage example when it helps. *Why:* misuse of shared objects is the costliest class of edge bug. *Check:* manual. *Severity:* Minor. *Source:* Google C++ "Comments > Struct and Class Comments".
- **CPP-DOC-5** [MUST] Put usage comments on declarations in the header and how-it-works comments on definitions in the `.cc`; a definition comment does not repeat the declaration comment. *Why:* users read headers, maintainers read implementations. *Check:* manual. *Severity:* Minor. *Source:* Google C++ "Comments > Struct and Class Comments", "Function Comments".
- **CPP-DOC-6** [MUST] Give nearly every function declaration, private methods and `.cc`-local functions included, a comment right before it that says what it does, in the descriptive mood ("Decodes one frame ...", not "Decode one frame ..."); skip it only for the obvious (a trivial accessor, an override that adds nothing to the base comment, a destructor with no cleanup to describe); an override comment describes only what differs from the base. *Why:* the declaration comment is the contract. *Check:* manual. *Severity:* Minor. *Source:* Google C++ "Comments > Function Comments".
- **CPP-DOC-7** [MUST] State in a function comment, where it applies: inputs and outputs, with parameter names in backticks; for each pointer or reference parameter whether it may be null, what null does, and whether the object keeps it after the call returns; for output and in-out parameters whether existing contents are kept, cleared or appended; which error results occur and when, beyond the obvious; (EDGE) cost facts a caller needs: whether it allocates, blocks, synchronises the device, or is safe in a real-time frame path. *Why:* ownership, lifetime and cost are invisible at the call site. *Check:* manual. *Severity:* Minor. *Source:* Google C++ "Comments > Function Comments"; cv-kit (edge cost facts).
- **CPP-DOC-8** [MUST] (EDGE) On every function or type that takes or returns image or tensor data, state the shape, layout (`NCHW`, `NHWC`, `HWC`), element type, value range (`[0, 255]`, `[0, 1]`, mean/std normalised), colour order (`RGB`/`BGR`) and any stride or alignment assumption; durations and sizes state their units. *Why:* (experience) layout and colour-order mismatches give silently wrong output, not crashes. *Check:* manual. *Severity:* Minor. *Source:* cv-kit (mirrors the Python docstring rule); mD C++ 09 (2.5).
- **CPP-DOC-9** [MUST] Make a constructor comment say what it does with its arguments (ownership taken, references kept) and a destructor comment say what non-obvious cleanup it does; neither restates its role ("Constructs a Foo"). Factory contracts: CPP-ERR. *Why:* only the non-obvious part is worth reading. *Check:* manual. *Severity:* Minor. *Source:* Google C++ "Comments > Function Comments".
- **CPP-DOC-10** [MUST] Precede a tricky function body or block with a comment that explains the approach, the steps, and why it beats the obvious alternative (why a lock covers only half the function, why the NEON path differs from the scalar one). *Why:* the reason for a design is not in the code. *Check:* manual. *Severity:* Minor. *Source:* Google C++ "Comments > Function Comments", "Implementation Comments".
- **CPP-DOC-11** [MUST] Comment a data member whenever its type and name do not carry an invariant: sentinel values (`-1` = dynamic dimension, `0` = choose thread count, `nullptr` = not loaded), relations between members, which mutex guards it, and the lifetime of a borrowed pointer; no comment when type and name say it all. *Why:* invariants live in comments until the type system can hold them. *Check:* manual. *Severity:* Minor. *Source:* Google C++ "Comments > Variable Comments".
- **CPP-DOC-12** [MUST NOT] Write comments that narrate the code; explain the why or the intent, or extract and name the code (`IsAlreadyTracked(box)`) so no comment is needed; when code and comment disagree, fix both. *Why:* narration goes stale and adds nothing. *Check:* manual. *Severity:* Minor. *Source:* Google C++ "Comments > Implementation Comments > Don'ts"; CG NL.1, NL.2.
- **CPP-DOC-13** [MUST] Comment every global and static variable: what it is, what it is for and, if not obvious, why it must be global. *Why:* globals are shared state with no visible owner. *Check:* manual. *Severity:* Minor. *Source:* Google C++ "Comments > Variable Comments".
- **CPP-DOC-14** [PREFER] Make a call site self-explaining with a named constant, an `enum` instead of a `bool` parameter, or an options struct (CPP-FN); as a last resort write `/*param_name=*/value`, and then the name must match the parameter. *Why:* `Resize(img, 640, true, nullptr)` says nothing. *Check:* clang-tidy `bugprone-argument-comment` checks the names. *Severity:* Minor. *Source:* Google C++ "Comments > Implementation Comments > Function Argument Comments".
- **CPP-DOC-15** [MUST] Write comments as clear, short English sentences with correct spelling, capitals and full stops; short end-of-line comments may be fragments. *Why:* sloppy comments are read as sloppy code. *Check:* manual (a spell checker such as codespell helps; not shipped). *Severity:* Minor. *Source:* Google C++ "Comments > Punctuation, Spelling, and Grammar"; CG NL.3.
- **CPP-DOC-16** [MUST] Write TODOs as `// TODO(<issue link, bug ID or name>): <what>`; the reference points to the best context, not to a promise; a "later" TODO names a concrete date or event. *Why:* searchable, with someone to ask. *Check:* clang-tidy `google-readability-todo` (flags `// TODO fix this`; with the shipped `Style: Parentheses` its fix writes the guide's `// TODO(<user>): ...` form). *Severity:* Minor. *Source:* Google C++ "Comments > TODO Comments".
- **CPP-DOC-17** [MUST] Deprecate public API with `[[deprecated("use NewName(); removal in <version or date>")]]` on the declaration plus a comment naming the replacement; comment-only deprecation of public API is not enough. *Why:* the compiler then tells every caller. *Check:* manual (`grep -i 'deprecat'` in comments without the attribute). *Severity:* Minor. *Source:* cv-kit (the pinned Google revision has no deprecation section).
- **CPP-DOC-18** [MUST] Every suppression sits on the line it suppresses, says what it suppresses and gives a reason after a colon: `// NOLINT(<check>): <reason>` for a tool finding, with the check named exactly as clang-tidy prints it (a diagnostic printed under several alias names needs all of them in the brackets: in clang-tidy 23, `NOLINT(google-explicit-constructor)` alone leaves the finding reported as `cppcoreguidelines-explicit-constructor,misc-explicit-constructor`), and `// cv-kit: allow[CPP-XXX-n]: <reason>` for a rule that no tool checks. A bare `// NOLINT`, a suppression without a reason, and `NOLINTNEXTLINE` or `NOLINTBEGIN` blocks are themselves findings. *Why:* the suppression is the only escape from a MUST, and its reason is what the reviewer judges. *Check:* `grep -nE 'NOLINT[A-Z]*(\([^)]*\))?\s*$'` (no reason after the check list), plus `grep -nE 'NOLINT[A-Z]*([^(A-Z]|$)'` (no check named), `grep -nE 'NOLINT(NEXTLINE|BEGIN|END)'` (not on the line), `grep -nE 'cv-kit: allow\[[^]]*\]:?\s*$'` (allow without a reason). *Severity:* Minor. *Source:* cv-kit.

## CPP-BUILD Build and verification

- **CPP-BUILD-1** [MUST] Every first-party target calls `cv_kit_strict(<target>)` from the shipped `cmake/cv_kit_strict.cmake` (C++20, no extensions, the full warning set, `-Werror`, `-fno-exceptions -fno-rtti`, GCC extras, `_GLIBCXX_ASSERTIONS` in Debug, sanitizer options); a needed deviation is a per-target or per-file `-Wno-<flag>` with a comment giving the reason. *Why:* the rules above lean on these flags. *Check:* `grep: cv_kit_strict\(` per `add_library`/`add_executable`; `compile_commands.json` shows the flags. *Severity:* Major. *Source:* cv-kit.
- **CPP-BUILD-2** [MUST] `-Werror` applies only to first-party targets (`PRIVATE`, as the module does) and never to consumers or third-party code: no global `add_compile_options(-Werror)`, no `-Werror` in an exported `INTERFACE`; third-party headers come in as `SYSTEM` includes or imported targets. A new compiler warning after an upgrade is fixed in the code, not by removing `-Werror`. *Why:* warnings as errors keep the bar, but must not break other people's builds or fail on vendor headers. *Check:* `grep: add_compile_options\(.*-Werror|INTERFACE.*-Werror`; manual. *Severity:* Major. *Source:* cv-kit.
- **CPP-BUILD-3** [MUST] Debug builds harden the standard library: `_GLIBCXX_ASSERTIONS` for libstdc++ (the module sets it in Debug only; verified it aborts on out-of-range `vector` and `span` `operator[]` and on dereferencing an empty `optional`, and is absent from the Release compile commands), and the libc++ hardening mode (`_LIBCPP_HARDENING_MODE`) on Android NDK builds (not tested by cv-kit); unit tests run in Debug. *Why:* replaces `.at()` as the bounds check during testing (CPP-ERR-15). *Check:* `compile_commands.json` contains `-D_GLIBCXX_ASSERTIONS` for Debug. *Severity:* Major. *Source:* cv-kit.
- **CPP-BUILD-4** [MUST] CI runs the host test suite in two sanitizer jobs: ASan+UBSan (`-DCV_KIT_SANITIZE=ON`, with `-fno-sanitize-recover=all` so undefined behaviour fails the test) and TSan (`-DCV_KIT_TSAN=ON`) over the multi-threaded pipeline tests replaying recorded frames; they are separate builds (the module refuses both at once, verified); sanitizers never reach shipped builds. *Why:* memory errors and races on host are cheap to find and expensive on a device; GCC 13's TSan aborts at start-up with "unexpected memory mapping" on recent kernels (seen on Linux 7.0) until ASLR is reduced (`setarch -R` or `vm.mmap_rnd_bits=28`, see Per-project settings). *Check:* CI configuration; sanitizer: ASan, UBSan, TSan. *Severity:* Major. *Source:* cv-kit; CG CP.9.
- **CPP-BUILD-5** [MUST] CI runs clang-tidy with the shipped `.clang-tidy` (checked with `--verify-config`) over the `compile_commands.json` of the same build, with warnings as errors. The config's `ExtraArgs` add `-Wno-unknown-warning-option` (clang would reject GCC-only flags such as `-Wlogical-op`), `-fexceptions` (the `noexcept` checks stay silent on `-fno-exceptions` compile commands; the build itself keeps `-fno-exceptions`) and the clang-only diagnostics `-Wthread-safety`, `-Wexit-time-destructors` and `-Wglobal-constructors`; a project does not strip them. Suppressions follow CPP-DOC-18. *Why:* the linter covers what the compiler cannot. *Check:* CI configuration. *Severity:* Major. *Source:* cv-kit.
- **CPP-BUILD-6** [MUST] Every configured build exports `compile_commands.json` (`CMAKE_EXPORT_COMPILE_COMMANDS=ON` in the presets; the module does not set it), for host and for each cross target. *Why:* clang-tidy, IDEs and review tooling need the real flags, and the cross database shows target-only code paths. *Check:* file exists in each build directory. *Severity:* Minor. *Source:* cv-kit.
- **CPP-BUILD-7** [MUST] Every change builds in CI for every shipped target (cross toolchain, Release flags) as well as host Debug, and both builds use `-Werror`; at least one optimised build is warning-checked because `-Wnull-dereference` only works with optimisation (verified: silent at `-O0`, fires at `-O2`). *Why:* portability errors and optimisation-dependent warnings show up only in those builds. *Check:* CI configuration. *Severity:* Major. *Source:* Google "Architecture Portability"; cv-kit.
- **CPP-BUILD-8** [MUST] Unit tests run on host and, for the cross-built binaries, on the target device (nightly at least, and before a release). *Why:* ARM's weak memory model, alignment faults, `char` signedness and vendor library versions differ from the x86 dev box. *Check:* CI configuration; test. *Severity:* Major. *Source:* CG CP.101; cv-kit.
- **CPP-BUILD-9** [MUST] A latency and memory regression test runs on the target with a recorded protocol: device and power mode (clocks fixed, for example `nvpmodel` plus `jetson_clocks`), OS/JetPack, driver and runtime versions; model, precision (fp32/fp16/int8), batch and input size; warm-up frames that are discarded (at least 100 or 10 s, whichever is longer) then at least 1000 measured frames; per-stage and end-to-end latency measured with `steady_clock`, reported as p50, p99 and max, plus throughput, peak RSS and peak device memory; the run is repeated 3 times and the median p99 is compared with the stored baseline under a project threshold (for example +5%). *Why:* (experience) single-run averages on unlocked clocks hide regressions and thermal effects; percentiles are what a frame budget is about. *Check:* test on target. *Severity:* Major. *Source:* CG Per.6; cv-kit.
- **CPP-BUILD-10** [MUST] Builds are reproducible: the toolchain is pinned (compiler version, sysroot or JetPack/NDK version, or a container image by digest), dependencies are pinned to exact versions (FetchContent `GIT_TAG` with a commit hash, a lock file, recorded vendor SDK versions), no `__DATE__`, `__TIME__` or `__TIMESTAMP__` (version and build information come from the build system), build paths are stripped (`-ffile-prefix-map=`), and the binary reports its version, commit and build flags. *Why:* a field bug must be reproducible from the binary on the device. *Check:* `grep: __(DATE|TIME|TIMESTAMP)__|GIT_TAG\s+(main|master|v?[0-9.]+)\b`; GCC/Clang `-Wdate-time` once a project adds it (not in the strict set); manual. *Severity:* Major. *Source:* cv-kit; mD C++ 08.
- **CPP-BUILD-11** [PREFER] CI also runs a clang build for clang-only compile diagnostics that the shipped clang-tidy run does not report (`-Wctad-maybe-unsupported`, CPP-TPL-8; `-Wnonportable-include-path`, CPP-HDR-11) and, where the project uses CPP-EDGE-33, `-Wfunction-effects`; thread-safety analysis and the static-storage diagnostics already run through clang-tidy (CPP-BUILD-5). *Why:* GCC lacks these warnings. *Check:* CI configuration. *Severity:* Minor. *Source:* cv-kit.

## Refactor recipes

Each recipe keeps behaviour; the risk says what can still change and the test that pins it.

- **R-CPP-1** Fallible setup to a factory: a constructor that loads and sets an `ok_` flag, or a public `Init()` called after default construction -> a private constructor taking already-acquired resources plus `static Result<T> Create(...)`; callers write `if (!r.ok()) return r.status();` or the project's assign-or-return macro, fixes CPP-ERR-8, CPP-ERR-9, CPP-CLS-18; risk: loading moves to the `Create()` call site, and objects that were stored before `Init()` now need `std::optional<T>` or a `unique_ptr` member; pin with one test per failure cause (missing file, bad plan) asserting the code, and a test that a valid input still gives identical outputs.
- **R-CPP-2** Integer and sentinel returns to the result type: `int Decode(const Buf&, Out*)` returning `-1` -> `Result<Out> Decode(const Buf&)`, or `Status Decode(const Buf&, Out&)` for a reused buffer, fixes CPP-ERR-1, CPP-ERR-6, CPP-FN-11; risk: callers that treated `0` as failure flip meaning; pin with a test on each old return value's path and a review of every call site.
- **R-CPP-3** Log-and-continue to propagation: `if (!s.ok()) { LOG(ERROR) << s; }` followed by success -> `RETURN_IF_ERROR(s);`, with logging moved to the layer that applies the policy, fixes CPP-ERR-3, CPP-ERR-5; risk: a stage that kept running now stops or drops the frame; pin with a fault-injection test of the stage's documented policy.
- **R-CPP-4** RTTI to dispatch: `if (auto* c = dynamic_cast<Conv*>(l)) c->Fuse();` chains -> a virtual function with a base default, or a closed `std::variant<Conv, Pool>` visited with an overload set, fixes CPP-ERR-16, CPP-ERR-17, CPP-ERR-18; risk: subclasses that override now run their override, the "unknown type" fallback disappears, and with a variant the object size changes and a new kind breaks the build (intended); pin with a test per concrete type plus one for the old fallback, and the model-output test.
- **R-CPP-5** Aborting checks to explicit ones: `v.at(i)`, `std::get<Box>(r)`, `opt.value()`, `gsl::narrow<int32_t>(n)` -> a boundary check that returns a status then `v[i]`, `std::get_if<Box>(&r)`, `has_value()` then `*opt`, `CheckedNarrow<int32_t>(n)` returning `std::optional`, fixes CPP-ERR-15, CPP-EXPR-20; risk: an abort becomes an error return that callers must handle; pin with tests at the limits (max, max + 1, negative, out-of-range index) run in Debug with `_GLIBCXX_ASSERTIONS`.
- **R-CPP-6** Throwing SDK behind a wrapper: OpenCV or ONNX Runtime C++ calls in pipeline code -> a small library compiled with `-fexceptions` whose `noexcept` entry points catch everything and return the project status (or the ONNX Runtime C API), fixes CPP-ERR-19; risk: error messages and codes change shape; pin with tests that force each SDK error (bad shape, missing model) and assert the mapped code.
- **R-CPP-7** Failing destructor to `Close()`: `~Writer() { fflush(f_); fclose(f_); }` -> an idempotent `[[nodiscard]] Status Close()` called by the owner, with a best-effort destructor, fixes CPP-ERR-10; risk: call sites must add `Close()`; pin with a test that a write error is now reported and that a second `Close()` is harmless.
- **R-CPP-8** Unchecked vendor calls to the checked helper: `cudaMemcpyAsync(dst, src, n, kind, s);` and one `cudaGetLastError()` at the end of a stage -> `RETURN_IF_ERROR(CheckCuda(cudaMemcpyAsync(...), "copy input"));` and a check right after each launch, fixes CPP-EDGE-26, CPP-ERR-20; risk: errors that were ignored now stop the frame; pin with a fault-injection test (a fake API or an impossible allocation) that asserts the code and the call name.
- **R-CPP-9** Allocation in the frame loop to a preallocated buffer: `std::vector<float> tmp(n);` inside `Process()` -> a member `tmp_` sized in `Create()` and reused each frame, fixes CPP-EDGE-2, CPP-EDGE-3; risk: stale data where code relied on zero-initialisation; pin with the counting-allocator test (0 allocations in steady state) and an output-equality test over a recorded clip.
- **R-CPP-10** Growing queue to a bounded ring: `std::queue<Frame>` plus a condition variable -> a fixed-capacity ring of slot handles with drop-oldest and a drop counter, fixes CPP-EDGE-9, CPP-EDGE-4; risk: frames are dropped under load where they were delayed before; pin with a slow-consumer test asserting bounded latency, bounded memory and counted drops.
- **R-CPP-11** Work out of the lock: inference, a callback or a long copy run under the queue mutex (or `mu_.lock(); work(); mu_.unlock();`) -> take or swap the item under a `std::scoped_lock` in its own block, then do the work after it, fixes CPP-EDGE-8, CPP-CONC-3, CPP-CONC-6, CPP-CONC-7; risk: readers may see the previous result one frame longer, and a callback can now see a queue that changed after the pop; pin with a TSan replay test, a test whose callback pushes back into the queue (it must not deadlock), and a latency test of the camera thread.
- **R-CPP-12** Detached thread to an owned `std::jthread`: `std::thread(&Cam::Loop, this).detach();` with a `volatile bool running_` -> a `std::jthread loop_` member declared after the state it uses, whose function takes a `std::stop_token` and whose waits wake on stop, fixes CPP-EDGE-12, CPP-CONC-11, CPP-CLS-8; risk: shutdown now waits for the loop, which hangs if a wait has no timeout; pin with a start/stop test under TSan and a shutdown-time limit.
- **R-CPP-13** Thread per frame to a fixed pool: `std::async(std::launch::async, Post, f)` per frame -> a pool created at start-up, sized from configuration, with a bounded task queue whose handles carry the result type, fixes CPP-EDGE-11, CPP-CONC-16; risk: task order and parallelism change; pin with an output-equality test and the latency regression test.
- **R-CPP-14** `system_clock` to `steady_clock`: a latency measured with `std::chrono::system_clock::now()` -> `std::chrono::steady_clock::now()`, fixes CPP-EDGE-14; risk: none for durations; values written to logs as wall-clock times keep `system_clock`; pin with a unit test of the timing helper.
- **R-CPP-15** Double math in float code: `y = x * 0.5 + std::exp(-z)` on `float` operands -> `x * 0.5f + std::exp(-z)` with the `float` overloads, fixes CPP-EDGE-15; risk: last-bit differences; pin with a tolerance-based reference test (CPP-EDGE-17).
- **R-CPP-16** Bare quantisation cast to a named conversion: `static_cast<int8_t>(x / scale)` -> `QuantizeInt8(x, scale, zero_point)` that rounds and saturates, fixes CPP-EDGE-20, CPP-EXPR-21; risk: values that wrapped now saturate (intended) and rounding may differ by one; pin with tests at -129, -128, 127, 128 and halfway values.
- **R-CPP-17** Intrinsics to the portability layer: `vaddq_f32` loops in `preprocess.cc` -> `simd::AddF32(span, span)` in the portability directory with a scalar fallback, fixes CPP-EDGE-25, CPP-LIB-6; risk: the fallback must match the SIMD path; pin with a test that runs both on the same random input and compares.
- **R-CPP-18** Raw buffer to RAII: a class with `float* data_`, `int size_` and a destructor calling `delete[]` -> a `std::vector<float>` member (or `std::unique_ptr<float[]>` plus a size) and no hand-written special members, fixes CPP-RES-1, CPP-RES-4, CPP-RES-17, CPP-CLS-9, CPP-CLS-11; risk: the old class may have been copyable by pointer and now deep-copies or is move-only; pin with a test that copies and moves the object and checks independence, under ASan.
- **R-CPP-19** C handle and `goto cleanup` to a wrapper: `cudaMalloc`/`cudaFree`, `open`/`close` or `mmap`/`munmap` paired by hand, or released again on every error branch -> a move-only handle (or `std::unique_ptr` with a stateless deleter) per resource, created by a factory, with `ScopeExit` only as a stopgap, fixes CPP-RES-1, CPP-RES-2, CPP-RES-20, CPP-RES-21, CPP-CLS-15; risk: release moves to scope end in reverse declaration order, which can move a device sync; pin with an error-path test under LeakSanitizer and a handle count before and after many iterations.
- **R-CPP-20** Returned owning pointer: `Model* LoadModel(path)` returning `new` memory -> `std::unique_ptr<Model>` for a polymorphic type, or `Model` by value inside the result type, fixes CPP-RES-3, CPP-RES-8; risk: callers that deleted the result must stop (the compiler flags each site); pin with an ASan test that loads and drops a model.
- **R-CPP-21** Needless `shared_ptr`: a `std::shared_ptr<T>` member or parameter never copied into a second owner -> a `std::unique_ptr<T>` member and `const T&` / `T*` parameters, fixes CPP-RES-9, CPP-RES-12, CPP-PERF-12; risk: destruction may happen earlier; pin with an ASan run over the shutdown path.
- **R-CPP-22** Two guards to one: consecutive `std::lock_guard`s on two mutexes -> `std::scoped_lock lock(a, b);`, fixes CPP-CONC-5; risk: none, the critical section is the same; pin with TSan's lock-order-inversion report on the existing test.
- **R-CPP-23** Condition-variable wait with a predicate: `while (!ready_) cv_.wait(lock);` or a bare `cv_.wait(lock)` -> `cv_.wait(lock, [&] { return ready_ || stop_; });` with `ready_` set under the mutex, fixes CPP-CONC-8; risk: the waiter now returns on stop; pin with a test that stops while a consumer waits and checks that it exits.
- **R-CPP-24** Static cache to an owned workspace: a helper with `static std::vector<float> scratch;` -> a `Workspace` passed in by the caller, one per stream, fixes CPP-CONC-1; risk: memory grows by one workspace per stream; pin with a two-stream TSan test and a memory check.
- **R-CPP-25** Type pun to `std::bit_cast` or `std::memcpy`: `union { float f; uint32_t u; }` or `*reinterpret_cast<const float*>(p + off)` -> `std::bit_cast<uint32_t>(f)`, or `std::memcpy` into a local, fixes CPP-EXPR-19, CPP-CLS-49, CPP-EDGE-22; risk: none when sizes match; add `static_assert(sizeof(float) == sizeof(uint32_t))`, and pin with a test on known bit patterns (0.0f, -0.0f, 1.0f, NaN) and on aligned and misaligned offsets under UBSan.
- **R-CPP-26** C-style casts: `(int)x` and `int(x)` -> `static_cast<int>(x)`, `int64_t{x}` for lossless widening, and `std::lround` where rounding was meant, fixes CPP-EXPR-17, CPP-EXPR-18, CPP-EXPR-21; risk: a C cast that was silently a `const_cast` or `reinterpret_cast` stops compiling (good), and a changed rounding changes outputs; pin with golden values at .5 boundaries and negatives.

- **R-CPP-29** Late initialisation to `const`: a variable declared at the top and assigned in branches -> `const auto x = [&] { ... }();` or a helper that returns the value, fixes CPP-EXPR-2, CPP-EXPR-12; risk: a branch that left the variable unassigned must now return something explicit; pin with a test per branch.

- **R-CPP-35** Pessimising moves: `return std::move(result);` -> `return result;`, and `const std::vector<T> Make()` -> `std::vector<T> Make()`, fixes CPP-FN-15, CPP-FN-16; risk: none; pin with the existing tests and a quiet `-Wpessimizing-move`.

- **R-CPP-58** Hand-written `extern` declarations to one shared header included by the definer and the users, fixes CPP-HDR-26; risk: the compiler now sees type mismatches that were silent undefined behaviour; pin with a full build and tests of the affected paths.
- **R-CPP-59** `atoi` and `std::stoi` to `std::from_chars` with an explicit error check, fixes CPP-LIB-17, CPP-ERR-15; risk: parsing accepts less (no leading spaces or `+`) and partial parses become visible; pin with table tests (`" 12"`, `"+3"`, `"12abc"`, overflow, empty string) and decide each case on purpose.
- **R-CPP-60** Rename to Google naming: `clang-tidy --fix --checks='-*,readability-identifier-naming'`, fixes CPP-NAME-4, CPP-NAME-5, CPP-NAME-6, CPP-NAME-7, CPP-NAME-8, CPP-NAME-10, CPP-NAME-12, CPP-NAME-13, CPP-NAME-14, CPP-NAME-15; risk: public API and ABI break (exported symbols, Python bindings, `dlsym` strings, names stringified by macros, serialised keys), and the fix renames only in translation units it compiles; build every target and binding, search string literals for old names, keep `[[deprecated]]` aliases for public API (CPP-DOC-17), and keep the rename in its own commit.
- **R-CPP-61** Apply clang-format (braces, spacing, pointer alignment) as a formatting-only commit, fixes CPP-FMT-1 and the clang-format-checked CPP-FMT rules; risk: clang-format documents `InsertBraces` as able to produce wrong code; build with `-g0` before and after and compare object-file hashes (identical code proves no behaviour change); include reordering is the include-order recipe above.

## Per-project settings

The shipped configs are generic. These settings depend on the project and are added by the project; each line
says what to add and which rule it serves.

- **Macro prefix** (CPP-NAME-15): in the project's root `.clang-tidy`, under `CheckOptions`:
  `readability-identifier-naming.MacroDefinitionPrefix: <PROJECT>_` (for example `CVKIT_`). Guards still pass
  through the shipped `MacroDefinitionIgnoredRegexp`.
- **Allowed macros** (CPP-LIB-10): under `CheckOptions`:
  `cppcoreguidelines-macro-usage.AllowedRegexp: '^<PROJECT>_(LOG|CHECK|DCHECK|RETURN_IF_ERROR|ASSIGN_OR_RETURN)'`
  (the default `'^DEBUG_*'` allows any macro starting with `DEBUG`).
- **The project's result types** (CPP-ERR-2): extend `bugprone-unused-return-value.CheckedReturnTypes` with the
  project's status and result types, keeping the shipped entries, for example
  `'^::std::error_code$;^::std::error_condition$;^::std::errc$;^::std::expected$;^::boost::system::error_code$;^::cudaError$;^::cvkit::Status$;^::cvkit::Result$'`
  (or `^::tl::expected$`, `^::absl::Status$;^::absl::StatusOr$`).
- **Include categories** (CPP-HDR-9): in `.clang-format`, replace `PROJECT_ROOT` in the `'^"PROJECT_ROOT/'` regex
  with the directory the project's own includes start with (for example `'^"cvkit/'`), and add the third-party
  libraries the project includes with angle brackets to the first regex.
- **Portability directory** (CPP-EDGE-25, CPP-LIB-6): a `.clang-tidy` in that directory only:
  ```yaml
  InheritParentConfig: true
  Checks: '-portability-simd-intrinsics,-portability-no-assembler'
  ```
  (drop `-portability-no-assembler` if no inline assembly lives there).
- **Device-code directories** (CPP-LIB-9, CPP-LIB-18): a `.clang-tidy` in each library directory that ships to
  the device:
  ```yaml
  InheritParentConfig: true
  CheckOptions:
    portability-restrict-system-includes.Includes: '*,-ratio,-cfenv,-fenv.h,-filesystem,-iostream,-regex'
  ```
- **TSan job** (CPP-BUILD-4): configure with `-DCV_KIT_TSAN=ON` and run the tests with reduced ASLR, either
  `setarch "$(uname -m)" -R ctest --test-dir <tsan-build>` or `sysctl -w vm.mmap_rnd_bits=28` on the runner.
- **Extra sanitizers** (CPP-EXPR-21, CPP-EXPR-37): in the ASan+UBSan build, add `-fsanitize=float-cast-overflow`
  (GCC) and, for a pointer-comparison job, `-fsanitize=pointer-compare,pointer-subtract` with
  `ASAN_OPTIONS=detect_invalid_pointer_pairs=1`.
- **Compile database** (CPP-BUILD-6): `"CMAKE_EXPORT_COMPILE_COMMANDS": "ON"` in the `cacheVariables` of every
  configure preset, host and cross.
- **Function effects** (CPP-EDGE-33, only if the project annotates hot functions): append
  `clang-diagnostic-function-effects` to `Checks` and `-Wfunction-effects` to `ExtraArgs` in `.clang-tidy`.
- **Build timestamps** (CPP-BUILD-10, optional): add `-Wdate-time` to the project's warning flags.
- **Return parentheses** (CPP-FMT-14, optional, not recommended by default): `RemoveParentheses: ReturnStatement`
  in `.clang-format` enforces the rule, but clang-format documents the option as able to produce wrong code; use
  it only together with the object-hash comparison of the clang-format recipe.

## Not adopted

Source rules that cv-kit does not turn into a rule, with the reason.

- CG exception-based error handling (NR.3, E.2 as "throw", E.15 throw by value and catch by reference, E.30
  dynamic exception specifications, E.31 catch order, I.10's exception mechanism): incompatible with
  `-fno-exceptions` or removed from the language; the intents are kept in CPP-ERR (see its table).
- CG C.36 (a destructor that cannot release terminates or catches): replaced by CPP-ERR-10.
- CG C.40-C.42 as written (throwing constructors) and E.6 / E.25's `valid()` member: replaced by CPP-CLS-18 and
  the factory of CPP-ERR-8.
- CG C.146-C.148 and Type.2 as written (`dynamic_cast`), C.147's throwing reference cast, Google's allowance of
  `dynamic_cast` when the type is guaranteed, and `absl::down_cast`: RTTI is off; replaced by CPP-ERR-17 and
  CPP-ERR-18. Only the "test before you use the result" half of C.148 survives (CPP-EXPR-35).
- Google's `Init()` as an alternative to factories, and its tolerance of termination on constructor failure:
  banned for public APIs (CPP-ERR-9).
- Google's Windows section (exceptions for ATL/STL, MSVC warning levels, precompiled headers, `resource.h`, COM
  multiple inheritance, Windows type names): cv-kit targets Linux and Android edge devices; the parts that
  generalise are kept (no Hungarian notation, CPP-NAME-5; extensions only behind macros, CPP-LIB-6; no
  `#pragma once`, CPP-HDR-6).
- CG ES.48's `std::ignore =` for discarding `[[nodiscard]]` results: Google's `(void)` with a comment is used
  (CPP-ERR-2).
- CG Type.1.2 (no `static_cast` between arithmetic types): Google prefers braces, then `static_cast`
  (CPP-EXPR-18, CPP-EXPR-20).
- CG Bounds.2 read strictly (index built-in arrays only with constants): too strict for kernels; replaced by
  checking once at the boundary (CPP-EXPR-38) and `std::array` (CPP-EXPR-8).
- CG C.62's enforcement direction (flag `this == &other` tests): `bugprone-unhandled-self-assignment` wants the
  opposite, and correctness wins (CPP-CLS-16).
- CG C.89's XOR hash combining: weak; a real hash-combine is required (CPP-CLS-44).
- CG C.129's dual hierarchies, C.136 stateful implementation mixins, C.137 virtual bases: Google's inheritance
  rules apply (CPP-CLS-32).
- CG C.130's `owner<B*>` clone return, C.50's `make_shared` factory sample, C.134's public debug member, C.166's
  unary `&` in proxy systems: superseded by CPP-CLS-33, CPP-RES-8, CPP-CLS-3 and CPP-CLS-42.
- CG CP.22's `recursive_mutex` remedy: rejected (CPP-CONC-7).
- CG CP.26's namespace-scope joining thread: conflicts with Google's static-storage rule; the thread is a member
  of an owning object (CPP-EDGE-12).
- CG CP.60 / CP.61 futures that carry exceptions and `std::async` as the task factory: replaced by CPP-CONC-16.
- GSL vocabulary (`narrow`, `not_null`, `zstring` / `czstring`, `span_p`, `stack_array`, `dyn_array`,
  `move_owner`, `index`, `joining_thread`, GSL concepts): cv-kit does not depend on GSL; standard or project
  equivalents are named in the rules. `gsl::owner` is kept as an optional marker (CPP-RES-22).
- Rules the compiler already enforces (CG F.46, C.170, T.83) and placeholder entries in the Core Guidelines (T.4,
  T.46, T.82, T.101, T.102, CP.par, CP.vec, CP.mess and the unnumbered concurrency stubs): no rule needed or
  nothing to adopt. The usable idea of R.36 is in CPP-RES-12; T.30 and T.31 are folded into CPP-TPL-5.
- CG profiles, In.0, the Per introduction and the design-concepts front matter, Appendix B (modernisation
  strategy) and Appendix D (tools): not code rules; Appendix B informs the refactor recipes.
- Google's ban on `std::auto_ptr`: removed from the language; a C++20 build rejects it.
- Google's `absl::implicit_cast`, `absl::StrFormat`, `absl/strings`, `absl_nullable`, gflags / `ABSL_FLAG`
  placement and protobuf `package` rules: tied to libraries cv-kit does not assume (Abseil only if already a
  dependency, CPP-LIB-5).
- Google's "Goals of the Style Guide" and its design-review step for new vocabulary names: principles and
  process, not code rules.
- cpplint: not shipped; clang-format and clang-tidy cover its main categories, which are cited for reference only.
- Google's unbraced one-line bodies (CPP-FMT-4), `int x, y;` (CPP-EXPR-3), optional `k` on local `constexpr`
  (always `k`, CPP-NAME-8), `kName` for non-static `const` members (`name_`, CPP-NAME-6), `static` for internal
  linkage (unnamed namespace, CPP-HDR-24), `<stddef.h>` beside `<cstddef>` (CPP-LIB-21), and dynamic
  initialisation of non-local variables (CPP-HDR-30): narrowed to the stricter form, mostly to match the tools.
- Google formatting freedoms that clang-format removes (spaces inside parentheses, `{ 0 }`, optional braces on
  `case`, a space after `#`): one form is enforced (CPP-FMT-1).
- CG SF.6 / SF.7 (`using namespace std` in `.cc` files, `std::literals` in headers), SF.12 (quoting relative to
  the includer), SL.str.12 and NL.11 (literal suffixes), SL.io.3 (prefer iostreams), SL.io.10
  (`sync_with_stdio(false)`, moot without iostreams on device), NL.10 / NL.17 / NL.27 (underscore naming, K&R
  layout, `.cpp`): rejected for Google's rules (CPP-HDR-18, CPP-HDR-10, CPP-LIB-4, CPP-LIB-9, CPP-NAME,
  CPP-FMT-5, CPP-HDR-1).
- CG SL.4 (use the library type-safely): an umbrella covered by the concrete rules.
- methylDragon tutorial items that are source errors (non-compiling samples, the `std::thread t(Functor());`
  vexing parse, wrong container claims) and its trigraphs: used as review hints only; trigraphs are gone from the
  language. Its two-level stringification idiom is allowed inside the logging header (CPP-LIB-11).
- Blanket `noexcept` on every function: noise when nothing can throw (CPP-FN-18).
- `-ffast-math` and relatives as a default: only behind CPP-EDGE-16's reference gate. `-ffp-contract=off` in
  shipped builds: costs speed on AArch64; used only for bit-exact reference tests (CPP-EDGE-17).
- `-Wswitch-default` and `-Wswitch-enum`: they fire on exhaustive enum switches without `default`, which
  CPP-EXPR-42 requires; `bugprone-switch-missing-default-case` covers other switches.
- `llvm-header-guard`: rejects correct Google guards. `cert-dcl58-cpp` and `cert-err52-cpp`: the same checks
  already run as `bugprone-std-namespace-modification` and `modernize-avoid-setjmp-longjmp`.
- `performance-type-promotion-in-math-fn` as the check for CPP-EDGE-15: it does not fire on `sqrt(float)` through
  `<math.h>` in C++; the compiler flags cover the real cases.
- `modernize-use-nodiscard`: noisy on getters; the class-level `[[nodiscard]]` of CPP-ERR-2 covers the important
  cases.
- `clang-format` `QualifierAlignment: Left`: documented as able to produce wrong code; `const` placement stays
  manual (CPP-FMT-25).
