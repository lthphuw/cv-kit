# Python rules: full catalogue

This is cv-kit's complete rule set for Python written by computer-vision and ML engineers. The strict
code-review skill checks code against it, and the behaviour-preserving refactor skill uses it to pick
changes. `rules/python-style.md` is the short, always-loaded summary of this file; where they differ, this
file wins.

**Rule format.** Each rule is one bullet: ID, strength, the rule, *Why*, *Check*, default *Severity*, and
*Source*. IDs are stable; never renumber, only append.

**Citing rules in findings.** Start every finding with the rule ID and the location, then say what is wrong
and what to do: `PY-ERR-2 loader.py:88: bare except in the frame loop swallows KeyboardInterrupt; catch
cv2.error and log it`. Several hits of one rule in one file form one finding that lists the lines.

**Strength.**

- `[MUST]` / `[MUST NOT]`: breaking the rule is a finding. There is no "style preference" escape.
- `[PREFER]`: a judgement call. Report it only when the code is hard to read because of it, and then as Minor.
- Allowed exceptions are written inside the rule ("..., except in tests"). Nothing else is exempt.

**Precedence.**

1. A rule the project has written down (a style guide, CONTRIBUTING file, or a committed tool config) beats
   this catalogue for that project.
2. This catalogue.
3. Formatter output is never argued with: if `ruff format` produces a layout, that layout is correct, and no
   finding may ask for a different one.

**Severity.** The rule gives a default; rate each finding on its own effect and say why when you move it.

- **Critical**: the code can crash, corrupt memory or data, race, give wrong output, or leak a resource in a
  long-running process (a training job, a server, a capture loop), or it breaks a hard constraint of the
  target, such as a blocking call or allocation inside a per-frame path documented as real-time.
- **Major**: a likely bug, a hazard for the next change, a risk that callers misuse the API, a measurable
  cost on a hot path, or missing tests for changed behaviour.
- **Minor**: naming, formatting, documentation, anything `ruff format` or `ruff check --fix` repairs, and
  rules that only change how equivalent code is spelled (no behaviour change, no hazard), even when no tool
  fixes them.

**Suppressions.** The only escape from a MUST rule is a suppression on the line that names the check and
gives the reason after a second `#`:

- ruff: `# noqa: B008  # torch.device is immutable`; for a short block, a matched pair
  `# ruff: disable[N806]  # reason` ... `# ruff: enable[N806]`.
- mypy: `# type: ignore[attr-defined]  # cv2 stubs lack this attribute`.
- A rule with no tool: `# cv-kit: allow[PY-CLS-1]  # required by the plugin API`.

A suppression without a code or without a reason is itself a finding (PY-LINT-2, PY-LINT-3).

**Check field.** `ruff CODE` means the code exists and is enabled by cv-kit's `ruff.toml` (verified with ruff
0.17.2 against the resolved rule list, and tried on test files). `mypy code` is a mypy 2.4.0 error code
under cv-kit's `mypy.ini`. `grep:` gives a Perl-compatible pattern for `grep -nP` or `rg -nP`; treat hits as
candidates, not findings. `manual` means a reviewer has to read the code. A note "(see Per-project settings)" points
to a useful check that the shipped config does not enable.

## Tooling

| Tool | What it enforces | cv-kit configuration |
| --- | --- | --- |
| `ruff format` | All layout: line breaks at 80 columns, 4-space indents, double quotes, spacing, blank lines, magic trailing comma, code inside docstrings. Covers almost all of PY-FMT. | `line-length = 80`, `indent-width = 4`, `quote-style = "double"`, `docstring-code-format = true`, `target-version = "py310"` |
| `ruff check` | Lint rules cited in the *Check* fields: imports, naming, docstring structure, bug patterns (`B`), security (`S`), simplifications, pathlib, logging, NumPy, TODO form. | Selected families: `A ANN ARG B BLE C4 D DTZ E ERA EXE F FBT G I ISC LOG N NPY PERF PGH PIE PL PTH RET RSE RUF S SIM SLF T20 TD TID TRY UP W`. Ignored: `COM812 ISC001 E501 W191 E111 E114 E117 D206 D300` (formatter overlap), and `TD002`, `TD003`, `TRY003` (they contradict the Google guide; see Conflicts). `F` is an accepted name for `N812` (`extend-ignore-names`). Google docstring convention; single-line imports except `typing`, `collections.abc`, `typing_extensions`; relative imports banned; doc lines limited to 80. Test files (`test_*.py`, `*_test.py`) skip `S101 PLR2004 D ANN SLF001`. Preview rules are off. |
| `mypy --strict` | Annotations on every function, type errors, unused or code-less ignores, unreachable code, possibly-undefined names, always-true conditions. | `strict = True`, `warn_unreachable = True`, extra codes `ignore-without-code`, `redundant-expr`, `truthy-bool`, `possibly-undefined`. The guide names pytype; cv-kit uses mypy. |

Run, in this order, from the project root: `ruff format --check .`, `ruff check .`, `mypy <package>` (the
config already turns on `--strict`). pylint is optional and not shipped.

`EXE002` (executable file without a shebang) stays enabled. On filesystems that mark every file
executable (some network or removable mounts, WSL on an NTFS drive) it fires on every file; such a project
may add it to its own `ignore` list.

**What stays manual.** No shipped tool checks these; a reviewer must read for them:

- module-only imports (PY-IMP-1), `@staticmethod` (PY-CLS-1), nested helpers and multi-`for` comprehensions
  (PY-FN-1, PY-FN-4);
- resource release for anything but `open()` (PY-RES-1 to PY-RES-4), thread and process safety (PY-CONC);
- almost all of PY-ML: array truthiness, views and copies, device syncs, inference mode, colour order, data
  order, float comparison;
- docstring content (PY-DOC-5 to PY-DOC-16) and the array contract (PY-ML-4);
- property and accessor design (PY-CLS-3 to PY-CLS-8), error-message quality (PY-STR-14), tests (PY-TEST).

## Rules

### PY-LINT: lint runs and suppressions

- **PY-LINT-1** [MUST] Run `ruff format --check`, `ruff check` and `mypy` with cv-kit's configs (or the project's stricter ones) on every change, in CI and before asking for review; a change that fails them is not ready for review. *Why:* the tools catch whole classes of defects for free and keep review on logic. *Check:* CI log, or run the three commands. *Severity:* Major. *Source:* Google py §2.1, cv-kit.
- **PY-LINT-2** [MUST NOT] Use blanket suppressions: a bare `# noqa`, `# ruff: noqa` without codes, a bare `# type: ignore`, or a file-level `# ruff: noqa: CODE` or new `per-file-ignores` entry added to silence one hit. *Why:* a blanket suppression hides every later defect on that line or in that file. *Check:* ruff `PGH004`, `PGH003`; mypy `ignore-without-code`; `grep: #\s*ruff:\s*noqa`. *Severity:* Major. *Source:* Google py §2.1, cv-kit.
- **PY-LINT-3** [MUST] Put each suppression on the offending line (or use a matched `# ruff: disable[CODE]` / `# ruff: enable[CODE]` pair around a short block), name the exact code, and give the reason after a second `#`, in the forms shown in the introduction. *Why:* the reason tells the next reader whether the suppression still applies. *Check:* `grep: #\s*(noqa(:\s*[A-Z]+[0-9]+(\s*,\s*[A-Z]+[0-9]+)*)?|type:\s*ignore(\[[a-z-]+(\s*,\s*[a-z-]+)*\])?)\s*$`; ruff `RUF104` (unmatched range). *Severity:* Minor. *Source:* Google py §2.1, §3.16.5, cv-kit.
- **PY-LINT-4** [MUST NOT] Leave stale or invalid suppressions: codes that no longer fire, codes that are not enabled (a `# noqa: E501` is itself reported), misspelt codes, unused `type: ignore` comments. *Why:* a stale suppression silently covers the next real defect on that line. *Check:* ruff `RUF100`, `RUF102`, `RUF103`; mypy `unused-ignore`. *Severity:* Minor. *Source:* cv-kit.
- **PY-LINT-5** [MUST NOT] Use `# fmt: off` or `# fmt: skip` to override the formatter, except around a literal table whose row layout carries meaning (a convolution kernel, a 3x3 camera matrix, a colour lookup table), with a reason comment. *Why:* formatter output is not up for debate; the exception keeps matrices readable. *Check:* `grep: fmt:\s*(off|skip)`; ruff `RUF028` (misplaced formatter comment). *Severity:* Minor. *Source:* cv-kit.
- **PY-LINT-6** [MUST] Handle a parameter that an interface forces on a function but the body does not use: on a method marked `@override`, leave it; otherwise make `del name  # Unused.` the first statement. Do not rename it to `_name` or `unused_name` in a public signature, and remove the parameter when no interface requires it. *Why:* renaming breaks keyword callers; `del` states the intent and stops accidental use. *Check:* ruff `ARG001`, `ARG002`, `ARG003`, `ARG004`, `ARG005`. *Severity:* Minor. *Source:* Google py §2.1.
- **PY-LINT-7** [MUST NOT] Commit commented-out code; delete it, version control keeps the history. *Why:* dead code goes stale and misleads readers. *Check:* ruff `ERA001`. *Severity:* Minor. *Source:* cv-kit.
- **PY-LINT-8** [MUST NOT] Commit debugging leftovers: `breakpoint()`, `pdb.set_trace()`, `ipdb`, `IPython.embed()`, bare `dir()` or `help()` calls, notebook magics. *Why:* a breakpoint hangs an unattended job. *Check:* `grep: breakpoint\(|pdb\.set_trace|\bipdb\b|embed\(\)|^\s*(dir|help)\(`; ruff `T100` is not enabled (see Per-project settings). *Severity:* Major. *Source:* mD Python 01, cv-kit.
- **PY-LINT-9** [MUST] Where this catalogue leaves a choice (docstring mood, wording of comments, local index names), match the surrounding file, and do not restyle unrelated code in the same change; but consistency with old code is never a reason to break a MUST rule in new code. *Why:* local consistency keeps diffs small; the catalogue still wins over legacy habits. *Check:* manual (diff review). *Severity:* Minor. *Source:* Google py §4.

### PY-IMP: imports and packages

- **PY-IMP-1** [MUST] Import only packages and modules: `import os`, `from torch.utils import data` and then `data.DataLoader`. Never import a class, function or constant by name (`from torch.utils.data import DataLoader` is a finding). The only exceptions are names from `typing`, `collections.abc` and `typing_extensions`. *Why:* the call site shows where each name comes from, and tests patch one module attribute. *Check:* manual (no ruff rule tells a module from a name). *Severity:* Minor. *Source:* Google py §2.2, mD Python 01, mD Python 03.
- **PY-IMP-2** [MUST] Alias with `as` only to the standard abbreviations `np` (numpy), `pd` (pandas), `plt` (matplotlib.pyplot), `tf` (tensorflow) and `F` (torch.nn.functional); get `nn` with `from torch import nn`. Any other alias, including `from x import y as z`, needs a reason: two modules with the same name, a clash with a local or common parameter name, or a name too long or too generic where it is used. *Why:* everyone reads `np` and `F` the same way; private aliases must be learned file by file. *Check:* `grep: ^\s*(import\s+\S+|from\s+\S+\s+import\s+\S+)\s+as\s+`; ruff `PLC0414`, `PLR0402`, `N811`, `N812` (configured to accept `F`), `N813`, `N814`, `N817`. *Severity:* Minor. *Source:* Google py §2.2, cv-kit.
- **PY-IMP-3** [MUST NOT] Use relative imports (`from . import x`, `from .mod import y`); import through the full package path. *Why:* a module's meaning must not depend on where the importing file sits. *Check:* ruff `TID252`. *Severity:* Minor. *Source:* Google py §2.2, §2.3.
- **PY-IMP-4** [MUST NOT] Make imports work by editing `sys.path`, setting `PYTHONPATH` from code, or relying on the script's own directory being on the path; install the project as a package (`pip install -e .`) and import through its name. *Why:* path tricks make `import utils` resolve to different files on different machines. *Check:* `grep: sys\.path\.(append|insert)|PYTHONPATH`. *Severity:* Major. *Source:* Google py §2.3, mD Python 03.
- **PY-IMP-5** [MUST NOT] Use star imports (`from x import *`). *Why:* they hide where names come from and silently shadow others. *Check:* ruff `F403`, `F405`, `F406`. *Severity:* Major. *Source:* Google py §2.2, mD Python 03.
- **PY-IMP-6** [MUST] Write one import per line; only `typing`, `collections.abc` and `typing_extensions` imports may list several names. *Why:* one import per line sorts and diffs cleanly. *Check:* ruff `E401`, `I001`. *Severity:* Minor. *Source:* Google py §3.13, §3.19.12.
- **PY-IMP-7** [MUST] Place imports at the top of the module, after the module docstring and any `from __future__` import, before constants and code. Import inside a function only to break a real import cycle or to defer an optional, heavy dependency that only that function uses, with the reason in the suppression and an `ImportError` that names the package to install. *Why:* top-level imports show dependencies at a glance and fail at start-up, not mid-run. *Check:* ruff `E402`, `PLC0415`, `F404`. *Severity:* Minor. *Source:* Google py §3.13, mD Python 04.
- **PY-IMP-8** [MUST] Group imports from most to least generic (`__future__`, standard library, third-party, first-party) and sort each group by full module path, ignoring case. *Why:* a fixed order makes duplicates and missing imports obvious. *Check:* ruff `I001`. *Severity:* Minor. *Source:* Google py §3.13.
- **PY-IMP-9** [MUST NOT] Leave unused imports, or import a name twice so the second silently rebinds the first. *Why:* dead imports slow start-up; rebinding changes which object the code uses. *Check:* ruff `F401`, `F811`, `F402`. *Severity:* Minor. *Source:* mD Python 03.
- **PY-IMP-10** [MUST NOT] Name a project module or package after a standard-library or installed third-party module (`random.py`, `test.py`, `types.py`, `logging.py`, `torch.py`, `cv2.py`). *Why:* the local file shadows the real module for every import on that path. *Check:* ruff `A005` (top-level modules only, by default); manual for subpackages. *Severity:* Major. *Source:* mD Python 03.
- **PY-IMP-11** [MUST NOT] Import conditionally at module level (`try: import x` / `except ImportError:`, imports under `if sys.platform ...`). The one exception is an `if TYPE_CHECKING:` block for imports used only in annotations: it sits right after the regular imports, holds only names used in annotations, is sorted like any import block with no blank lines inside, and those names appear only in annotations (with `from __future__ import annotations` or quoted). Optional backends follow PY-IMP-7. *Why:* conditional imports make a module behave differently per environment in ways tests do not see. *Check:* `grep: ^\s*(if\s+(typing\.)?TYPE_CHECKING:|except\s+ImportError)`; mypy; ruff `TC004` is not enabled (see Per-project settings). *Severity:* Major. *Source:* Google py §3.19.13, cv-kit.
- **PY-IMP-12** [MUST] Treat an import cycle as a design defect and break it by moving the shared code into a lower-level module; use a `TYPE_CHECKING` import only when the cycle exists purely for annotations. *Why:* cycles make import order matter and expose half-initialised modules. *Check:* manual (an import-graph tool such as pydeps, if available). *Severity:* Major. *Source:* Google py §3.19.14.
- **PY-IMP-13** [MUST] Keep `__init__.py` free of work: a docstring, imports, `__all__` and `__version__` only; list every public re-export in a sorted `__all__`. *Why:* importing the package runs `__init__.py` for every user, including each spawned worker. *Check:* ruff `RUF022`, `PLE0604`, `PLE0605`, `F822`; manual. *Severity:* Major. *Source:* mD Python 03, cv-kit.
- **PY-IMP-14** [MUST] Give every package directory inside the project an `__init__.py` (no implicit namespace packages). *Why:* imports, test discovery and type checkers resolve regular packages predictably. *Check:* manual (look for package directories without `__init__.py`); ruff `INP001` is not enabled (see Per-project settings). *Severity:* Minor. *Source:* mD Python 03, cv-kit.
- **PY-IMP-15** [MUST NOT] Remove a `from __future__ import annotations` line in a refactor without running the module's tests. *Why:* libraries that read annotations at run time (dataclasses, pydantic, CLI builders) can change behaviour. *Check:* manual (diff review). *Severity:* Minor. *Source:* Google py §2.20.

### PY-ERR: exceptions and assert

- **PY-ERR-1** [MUST NOT] Use `assert` outside test files: not for argument, shape, dtype or range checks, not to narrow types for mypy, not for any condition later code relies on. Raise `ValueError`, `TypeError` or a project exception instead, and narrow types with `if x is None: raise ...`. *Why:* `python -O` removes asserts, so the check vanishes in exactly the runs that skip tests. *Check:* ruff `S101` (test files exempt by config). *Severity:* Major; Critical when the assert is the only guard against silently wrong output. *Source:* Google py §2.4, mD Python 01, cv-kit.
- **PY-ERR-2** [MUST NOT] Write a bare `except:`. Catch `Exception` or `BaseException` only (a) to clean up or add context and then re-raise, or (b) with `Exception` alone, at an isolation boundary (the top of a thread or worker, a request handler, a per-sample guard in a long data loop) that logs the traceback and counts or reports the failure. *Why:* a broad handler swallows Ctrl-C, CUDA out-of-memory and corrupt-sample errors that must surface. *Check:* ruff `E722`, `BLE001`. *Severity:* Major; Critical when it hides failures in a training, inference or data loop. *Source:* Google py §2.4, mD Python 01.
- **PY-ERR-3** [MUST NOT] Swallow an exception silently (`except E: pass` or `continue` with no log and no comment). When ignoring one specific error is correct, use `contextlib.suppress(SpecificError)` or say why in a comment. *Why:* a silent handler turns a failure into wrong output. *Check:* ruff `S110`, `S112`, `SIM105`. *Severity:* Major. *Source:* Google py §2.4, mD Python 01.
- **PY-ERR-4** [MUST] Keep each `try` body to the statements that can raise the handled exception; move the success path into `else:`, and do not `raise` inside a `try` that catches the same type. *Why:* a wide `try` catches errors from unrelated lines and blames the wrong cause. *Check:* ruff `TRY300`, `TRY301`; manual. *Severity:* Major. *Source:* Google py §2.4, mD Python 01.
- **PY-ERR-5** [MUST] Catch the narrowest exception types the handler can deal with, each listed once in a plain tuple (`except (OSError, ValueError):`, never `except (OSError or ValueError):`). *Why:* broad or malformed handler tuples catch the wrong errors, or none. *Check:* ruff `PLW0711`, `B013`, `B014`, `B025`, `B029`, `B030`. *Severity:* Major. *Source:* Google py §2.4.
- **PY-ERR-6** [MUST] Chain a translated exception with `raise NewError(...) from err` (or `from None` when the original adds nothing), and re-raise an unchanged one with a bare `raise`, not `raise err`. *Why:* the original traceback is the evidence for the bug. *Check:* ruff `B904`, `TRY201`, `PLE0704`. *Severity:* Major. *Source:* mD Python 01.
- **PY-ERR-7** [MUST] Raise the built-in that fits: `ValueError` for a bad value (wrong shape, out of range, unsupported dtype), `TypeError` for a wrong type, `KeyError`/`IndexError` for failed lookups, `FileNotFoundError` for a missing file, `NotImplementedError` in abstract stubs. Never `raise Exception(...)`, never a built-in with the wrong meaning (`NameError` for an application error), never `raise NotImplemented` or a literal. *Why:* callers handle errors by type. *Check:* ruff `TRY002`, `TRY004`, `F901`, `B016`. *Severity:* Major. *Source:* Google py §2.4, mD Python 01.
- **PY-ERR-8** [MUST] Derive project exceptions from `Exception` or the closest built-in (`class CalibrationError(ValueError)`), end their names in `Error`, and do not repeat the module name (in module `calib`, `PatternNotFoundError`, not `CalibError`). *Why:* a shared base lets callers catch the family; the suffix shows the role. *Check:* ruff `N818`; manual. *Severity:* Minor. *Source:* Google py §2.4.
- **PY-ERR-9** [MUST NOT] Put `return`, `break` or `continue` inside a `finally` block. *Why:* it discards the exception in flight. *Check:* ruff `B012`, `SIM107`. *Severity:* Major. *Source:* mD Python 01.
- **PY-ERR-10** [MUST NOT] Create an exception without raising it (`ValueError("bad shape")` as a bare statement). *Why:* the check silently does nothing. *Check:* ruff `PLW0133`. *Severity:* Major; Critical when it was the only guard. *Source:* cv-kit.
- **PY-ERR-11** [MUST NOT] Call `sys.exit()`, `exit()` or `quit()` outside a script's `main()` and `__main__` guard; library code raises instead. *Why:* exiting inside a library kills the caller's process without a traceback. *Check:* ruff `PLR1722`; `grep: \b(sys\.)?exit\(|\bquit\(`. *Severity:* Major. *Source:* cv-kit.
- **PY-ERR-12** [MUST] Issue warnings with an explicit category and `stacklevel` (`warnings.warn("...", DeprecationWarning, stacklevel=2)`). *Why:* a warning that points into the library cannot be acted on. *Check:* ruff `B028`. *Severity:* Minor. *Source:* cv-kit.

### PY-STATE: globals, defaults, module-level code, main

- **PY-STATE-1** [MUST NOT] Keep mutable state at module level in library code: no module-level lists, dicts or sets used as caches or registries, no `global` assignments, no class-level counters. When process-wide state cannot be avoided (a plugin registry, a bounded cache), give it a `_private` name, reach it only through functions, comment why it exists, and note that every process (each DataLoader worker, each `multiprocessing` child) has its own copy. *Why:* hidden shared state couples callers, breaks tests, and does not propagate to worker processes. *Check:* ruff `PLW0603`, `PLW0602`, `PLW0604`; `grep: ^_?[a-z]\w*(\s*:\s*[^=]+)?\s*=\s*(\[|\{|dict\(|list\(|set\(|collections\.)`. *Severity:* Major; Critical when code assumes workers see updates made in the parent. *Source:* Google py §2.5, mD Python 02, mD Python 04.
- **PY-STATE-2** [MUST] Make module-level constants immutable (numbers, strings, tuples, frozensets, frozen dataclasses, `types.MappingProxyType` for a read-only mapping), name them `CAPS_WITH_UNDER` (`_CAPS_WITH_UNDER` if internal), and annotate them `typing.Final` when the type is not obvious. *Why:* a "constant" list can be changed by any importer. *Check:* ruff `N816`; manual. *Severity:* Minor. *Source:* Google py §2.5, §3.16.4.
- **PY-STATE-3** [MUST NOT] Use a mutable object as a default argument value: `[]`, `{}`, `set()`, `np.zeros(3)`, `torch.tensor(...)`, a dataclass instance, even when annotated as `Sequence` or `Mapping`. Default to `None` and build the object in the body, or use an immutable default (`()`, `frozenset()`). *Why:* the default is created once, at `def` time, and shared by every call. *Check:* ruff `B006`, `B008`. *Severity:* Major; Critical when the function mutates the default. *Source:* Google py §2.12, mD Python 02.
- **PY-STATE-4** [MUST NOT] Use a default value computed at import time when its value matters: `time.time()`, `datetime.now()`, `Path.cwd()`, `os.environ[...]`, a config or command-line flag read at definition time, device detection. *Why:* the default captures the state at import, not at the call. *Check:* ruff `B008`; manual. *Severity:* Major. *Source:* Google py §2.12.
- **PY-STATE-5** [MUST NOT] Put per-instance state in a mutable class attribute (`labels: list[str] = []` in the class body); create it in `__init__` or with `dataclasses.field(default_factory=list)`, and mark genuine class-wide constants `ClassVar` with an immutable value. *Why:* every instance shares, and mutates, the same object. *Check:* ruff `RUF012`, `RUF008`, `RUF009`. *Severity:* Major; Critical when instances mutate it. *Source:* mD Python 03.
- **PY-STATE-6** [MUST] Keep every module importable without side effects. At module level, only define constants, functions, classes, type aliases, `TypeVar`s and `logger = logging.getLogger(__name__)`; no loading of models or weights, no opening of cameras, datasets or files, no CUDA initialisation, argument parsing, network calls, `logging.basicConfig`, seeding or `print`. *Why:* imports run in tests, in documentation tools, and again in every spawned worker. *Check:* manual (scan module level for calls); `grep: ^[A-Za-z_][\w.]*\(`. *Severity:* Major; Critical when it breaks spawned workers or loads a GPU model on import. *Source:* Google py §3.17, mD Python 03, mD Python 04.
- **PY-STATE-7** [MUST] Put a script's work in `main()` and call it only under `if __name__ == "__main__":`, with no `else:` branch. Every script that uses `multiprocessing`, `ProcessPoolExecutor` or `DataLoader(num_workers>0)` must have the guard. *Why:* with the spawn start method each worker re-imports the main module and would re-run the script. *Check:* `grep: ^if __name__ == "__main__":` on executable files (absence is the hit); manual. *Severity:* Major; Critical for scripts that start processes. *Source:* Google py §3.17, mD Python 04.
- **PY-STATE-8** [MUST NOT] Change process-wide settings in library code: `os.chdir`, writes to `os.environ`, `sys.path` edits, `warnings.filterwarnings` or `simplefilter`, `np.seterr`, `np.set_printoptions`, `torch.set_default_dtype`, `torch.set_num_threads`, `torch.backends.cudnn.benchmark` or `.deterministic`, `cv2.setNumThreads`. Only the application entry point sets these. *Why:* a library call that changes global behaviour breaks unrelated code in the same process. *Check:* ruff `B003`; `grep: os\.chdir|os\.environ\[[^\]]+\]\s*=|os\.putenv|filterwarnings|simplefilter|np\.seterr|set_printoptions|set_default_dtype|set_num_threads|cudnn\.(benchmark|deterministic)\s*=|setNumThreads`. *Severity:* Major. *Source:* mD Python 02, cv-kit.

### PY-FN: functions, closures, comprehensions, generators, decorators

- **PY-FN-1** [MUST NOT] Nest a function or class inside another unless it closes over a local value of the outer function (other than `self` or `cls`) or is a decorator's wrapper; a helper nested only to hide it becomes a module-level `_helper`. *Why:* nested helpers cannot be tested or reused on their own. *Check:* manual. *Severity:* Minor. *Source:* Google py §2.6.
- **PY-FN-2** [MUST] Bind loop variables explicitly when creating functions inside a loop, with `functools.partial(fn, i)` or a default argument (`lambda x, i=i: ...`). *Why:* a closure reads the variable when it is called, so every closure sees the last value. *Check:* ruff `B023`. *Severity:* Critical. *Source:* Google py §2.16, mD Python 04.
- **PY-FN-3** [MUST] Use `nonlocal` only for a small accumulator owned by one closure; shared state any larger becomes a class. *Why:* `nonlocal` state is invisible from the call site. *Check:* manual. *Severity:* Minor. *Source:* Google py §2.16, mD Python 04.
- **PY-FN-4** [MUST NOT] Write a comprehension or generator expression with more than one `for` clause or more than one `if` filter; use nested loops, `itertools.product`, or a named helper. *Why:* multi-clause comprehensions hide the iteration order and are hard to step through. *Check:* manual; `grep: [\[{(][^\]})]*\bfor\b[^\]})]*\bfor\b` (one-line cases only). *Severity:* Minor. *Source:* Google py §2.7, mD Python 01, mD Python 04.
- **PY-FN-5** [MUST] Use comprehensions or generator expressions instead of `map()`/`filter()` with a `lambda`, and pass an `operator` function or a method (`operator.mul`, `str.lower`) instead of a lambda that only wraps one. *Why:* the comprehension reads in order without a throwaway function. *Check:* ruff `C417`, `PLW0108`, `C416`; manual for `operator`. *Severity:* Minor. *Source:* Google py §2.10, mD Python 04.
- **PY-FN-6** [MUST] Keep a lambda to one short line passed inline (a `key=` argument, a callback); never bind one to a name, and turn anything longer than one line or roughly 60 to 80 characters into a `def`. *Why:* a named lambda has a useless `__name__`, cannot be pickled to workers, and hides logic. *Check:* ruff `E731`; manual for length. *Severity:* Minor. *Source:* Google py §2.10, mD Python 03, mD Python 04.
- **PY-FN-7** [MUST] Use a conditional expression only to choose a value, with the true value, the condition and the false value each fitting on one line; otherwise write an `if` statement. Never use one for side effects (`save_a() if ok else save_b()`). *Why:* long or side-effecting ternaries read worse than a plain `if`. *Check:* manual. *Severity:* Minor. *Source:* Google py §2.11, mD Python 01.
- **PY-FN-8** [MUST] Iterate with the container's own iterator and test membership with `in`: `for key in mapping`, `for key, value in mapping.items()`, `for line in file`, `if key in mapping`; use `enumerate()` instead of `range(len(seq))` or a hand-kept counter, and `zip()` for parallel sequences. *Why:* index juggling is slower and invites off-by-one errors. *Check:* ruff `SIM118`, `PERF102`, `SIM113`, `PLC0206`, `PLR1733`, `PLR1736`; `grep: range\(len\(`. *Severity:* Minor. *Source:* Google py §2.8, mD Python 01.
- **PY-FN-9** [MUST NOT] Add, remove or replace items of a list, dict or set while iterating over it; iterate over a snapshot (`list(d)`) or build a new container. *Why:* the loop skips items or raises `RuntimeError` part-way. *Check:* manual (`B909` is preview-only, see Per-project settings). *Severity:* Critical. *Source:* Google py §2.8, mD Python 01.
- **PY-FN-10** [MUST] Pass `strict=True` to `zip()` over sequences that must be the same length (images and labels, boxes and scores); write `strict=False` only where truncation is intended. *Why:* plain `zip` silently drops the tail of the longer input. *Check:* ruff `B905`. *Severity:* Major; Critical when it pairs samples with labels. *Source:* mD Python 01.
- **PY-FN-11** [MUST NOT] Iterate a one-shot iterator twice (a generator, `map`, `filter`, `zip`, an open file, an `itertools.groupby` group) or pass one where `len()` or a second pass is needed (an epoch loop); materialise it with `list()` or give the object an `__iter__` that returns a fresh iterator. *Why:* the second pass is silently empty. *Check:* ruff `B031`; manual. *Severity:* Critical. *Source:* mD Python 01, mD Python 04.
- **PY-FN-12** [MUST] Validate a generator's arguments eagerly: do the checks in a plain function that then returns the generator (or delegates to a private one). *Why:* a generator function's body runs only at the first `next()`, so errors surface far from the bad call. *Check:* manual. *Severity:* Major. *Source:* mD Python 02.
- **PY-FN-13** [MUST] Write a decorator's wrapper with `@functools.wraps(fn)`, forward `*args, **kwargs` (typed with `ParamSpec`), and return the wrapped call's result; decorators follow the same import and naming rules as functions. *Why:* otherwise the name, docstring, signature or return value of the wrapped function is lost. *Check:* manual; mypy `no-untyped-def` flags untyped wrappers. *Severity:* Major. *Source:* Google py §2.17, mD Python 04.
- **PY-FN-14** [MUST NOT] Do work in the part of a decorator that runs at decoration time: no file, socket or database access, no config reads, no logging setup. A decorator applied with valid arguments must always succeed. *Why:* decoration runs at import time, including in tests and documentation tools. *Check:* manual. *Severity:* Major. *Source:* Google py §2.17, mD Python 04.
- **PY-FN-15** [PREFER] Write a decorator only when it removes real repetition or adds a clear cross-cutting behaviour; a plain call is easier to follow. *Why:* decorators hide control flow. *Check:* manual. *Severity:* Minor. *Source:* Google py §2.17.
- **PY-FN-16** [MUST] Keep each function within ruff's default limits as enabled in cv-kit: 5 parameters, keyword-only ones included and `self`/`cls` not counted (`PLR0913`), 5 positional parameters (`PLR0917`), 12 branches (`PLR0912`), 6 return statements (`PLR0911`) and 50 statements (`PLR0915`); group related parameters into a dataclass or split the function. *Why:* functions past these limits are hard to test and change. *Check:* ruff `PLR0913`, `PLR0917`, `PLR0912`, `PLR0911`, `PLR0915`. *Severity:* Major. *Source:* Google py §3.18, cv-kit.
- **PY-FN-17** [PREFER] Keep functions small and focused; once one passes about 40 lines, check whether it splits cleanly into named steps, and split a long function that is hard to debug or that you want to reuse in part. *Why:* the guide sets no hard limit; length is a prompt to look, not a defect. *Check:* manual. *Severity:* Minor. *Source:* Google py §3.18.
- **PY-FN-18** [MUST] Make boolean flags and option parameters keyword-only (`def resize(image, size, *, antialias: bool = True)`) and pass them by keyword. *Why:* `resize(img, s, True)` hides what `True` means and swaps silently. *Check:* ruff `FBT001`, `FBT002`, `FBT003`. *Severity:* Major. *Source:* mD Python 04, cv-kit.
- **PY-FN-19** [MUST NOT] Take several same-typed values that are easy to swap (`h, w`; `x1, y1, x2, y2`; `mean, std`) as plain positional parameters; make them keyword-only or pass one typed value (`Size`, `Box`). *Why:* a `(w, h)` for `(h, w)` swap passes type checks and gives wrong output. *Check:* manual. *Severity:* Major. *Source:* mD Python 03.
- **PY-FN-20** [MUST NOT] Use `*args` or `**kwargs` in a public signature except to forward to another callable; forwarding wrappers type them with `ParamSpec` (`*args: P.args, **kwargs: P.kwargs`) and keep the names `args` and `kwargs`. *Why:* catch-all signatures hide the API from readers and type checkers. *Check:* ruff `ANN002`, `ANN003`; manual. *Severity:* Major. *Source:* mD Python 04, Google py §3.19.10.
- **PY-FN-21** [MUST NOT] Mutate an argument the caller owns (`list.append`, `dict.update`, in-place array or tensor ops such as `arr *= 2`, `t.add_(1)`, `arr[...] = 0`, `out=`) unless the function's name and docstring say so (a trailing underscore, an explicit `out` parameter); copy first otherwise. *Why:* callers do not expect their data to change. *Check:* manual. *Severity:* Critical. *Source:* Google py §3.8.3, mD Python 01.
- **PY-FN-22** [MUST] Return consistently: either every path returns a value explicitly or none does; no `else` after `return`, `raise`, `continue` or `break`; no variable assigned only to be returned on the next line; no trailing bare `return`. *Why:* mixed implicit `None` returns cause `None` errors far downstream. *Check:* ruff `RET501`, `RET502`, `RET503`, `RET504`, `RET505`, `RET506`, `RET507`, `RET508`, `PLR1711`. *Severity:* Minor. *Source:* mD Python 02, mD Python 03, mD Python 04.
- **PY-FN-23** [MUST NOT] Reassign a loop variable or a parameter to an unrelated value, reuse the iterated name as the loop target, or assign a name to itself. *Why:* readers assume a name keeps holding what it held. *Check:* ruff `PLW2901`, `PLR1704`, `B020`, `PLW0127`, `PLW0128`. *Severity:* Major. *Source:* cv-kit.
- **PY-FN-24** [MUST] Use the built-in or standard-library tool instead of re-implementing it: `any`/`all` over a generator expression, `sum`, `math.prod`, `str.join`, `min`/`max`, `dict.get`, `collections.Counter` and `defaultdict`, `itertools.chain.from_iterable`, comprehensions instead of append loops. *Why:* the built-ins are shorter, faster and already tested. *Check:* ruff `SIM110`, `SIM401`, `PLR1730`, `PERF401`, `PERF402`, `PERF403`, `PIE807`, `C419`, `RUF017`. *Severity:* Minor. *Source:* mD Python 01, mD Python 04, mD Python 05.
- **PY-FN-25** [MUST NOT] Use quadratic patterns on data that grows: `list.pop(0)` or `insert(0, x)` in a loop (use `collections.deque`), `x in some_list` inside a loop (build a `set`), `seq.count(x)` for each element (use `Counter`), `sum(list_of_lists, [])`. *Why:* they look fine on test data and stall on real datasets. *Check:* ruff `RUF017`; manual. *Severity:* Major. *Source:* mD Python 01, mD Python 05.
- **PY-FN-26** [MUST NOT] Recurse to a depth that grows with the input (list length, a nested structure of unknown depth); use a loop or an explicit stack, and memoise genuinely recursive definitions with `functools.cache`. *Why:* CPython has no tail-call elimination and stops at its recursion limit, 1000 frames by default. *Check:* manual. *Severity:* Major. *Source:* mD Python 02.
- **PY-FN-27** [MUST] Memoise with `functools.cache` or `functools.lru_cache(maxsize=N)`, not a hand-written dict or mutable default. Never put them on methods (the cache keeps every `self` alive; use `functools.cached_property` or a module-level cached function); cache only on arguments hashed by value (not arrays or tensors), and bound the size when the inputs are unbounded (paths, frames). *Why:* hand-made or unbounded caches leak memory in long runs. *Check:* ruff `B019`, `UP033`; manual. *Severity:* Major; Critical when unbounded in a long-running process. *Source:* mD Python 02, mD Python 04.
- **PY-FN-28** [MUST NOT] Drop the result of a call that returns a new value (`s.strip()`, `name.replace(...)`, `arr.astype(np.float32)`, `t.to(device)` on a tensor, `t.float()`), or keep the `None` returned by an in-place method (`boxes = boxes.sort()`). *Why:* the code looks as if it changed the data and did not. *Check:* manual; mypy `assignment` catches some rebinding cases. *Severity:* Critical. *Source:* mD Python 01.
- **PY-FN-29** [MUST NOT] Build nested lists or lists of objects by multiplying a list (`[[0] * w] * h`, `[[]] * n`, `[Track()] * n`); create each element separately with a comprehension, or use `np.zeros((h, w))` for numeric grids. *Why:* every slot refers to the same inner object. *Check:* `grep: \[\s*(\[[^\]]*\]|\{[^}]*\}|\w+\([^)]*\))\s*\]\s*\*`; manual. *Severity:* Critical. *Source:* mD Python 01, mD Python 03.
- **PY-FN-30** [MUST] Copy deliberately: `b = a` shares the object; `a.copy()`, `list(a)` and `a[:]` copy only the outer container; use `copy.deepcopy` when nested data must be independent. *Why:* a change through one name shows up through the other. *Check:* manual. *Severity:* Major. *Source:* mD Python 01, mD Python 04.
- **PY-FN-31** [MUST NOT] Use `dict.setdefault` or an index into a `defaultdict` merely to read a key (both insert missing keys); read with `in` or `.get()`, and convert a `defaultdict` to a plain `dict` before returning or serialising it. *Why:* a read that inserts changes the data and its later iteration. *Check:* manual. *Severity:* Major. *Source:* mD Python 01, mD Python 05.
- **PY-FN-32** [MUST] Push heap and priority-queue entries as `(priority, tie_breaker, item)` with a counter from `itertools.count()` when the items are not orderable. *Why:* equal priorities otherwise compare the items, which raises for dicts and arrays. *Check:* manual. *Severity:* Major. *Source:* mD Python 05.

### PY-CLS: classes, properties, accessors, dataclasses, power features

- **PY-CLS-1** [MUST NOT] Use `@staticmethod`; write a module-level function instead (`_name` if internal). Allowed only when a third-party API requires a static method, named in the suppression. *Why:* a static method is a function with a longer name that is harder to reuse and test. *Check:* `grep: @staticmethod`. *Severity:* Minor. *Source:* Google py §2.17, cv-kit.
- **PY-CLS-2** [MUST] Use `@classmethod` only for named constructors (`from_config`, `from_onnx`) or for routines that must act on class-wide state such as a registry, which PY-STATE-1 governs. *Why:* other uses blur what depends on the class. *Check:* `grep: @classmethod`; manual. *Severity:* Minor. *Source:* Google py §2.17.
- **PY-CLS-3** [MUST] Keep a property as cheap and unsurprising as reading an attribute: no I/O, no model or weight loading, no device sync or copy, no large allocation, no mutation. Use a method for anything costly, or `functools.cached_property` for an expensive value that never changes. *Why:* callers read properties in loops and assume they are free. *Check:* manual. *Severity:* Major. *Source:* Google py §2.13, mD Python 03.
- **PY-CLS-4** [MUST NOT] Write a property, or a `get_x()`/`set_x()` pair, that only returns or assigns a private attribute; make the attribute public and add a property later if logic appears (callers do not change). Properties that compute a trivially derived value or validate a write are fine. *Why:* pass-through accessors add code and no behaviour. *Check:* manual. *Severity:* Minor. *Source:* Google py §2.13, §3.15, mD Python 03.
- **PY-CLS-5** [MUST] Use explicit `get_x()`/`set_x()` methods when reading or writing is costly or invalidates other state (changing the input size rebuilds anchors and buffers), so the call looks like work. When such methods replace an old property, delete the property so old callers fail loudly. *Why:* attribute syntax promises a cheap operation. *Check:* manual. *Severity:* Major. *Source:* Google py §3.15.
- **PY-CLS-6** [MUST] Define properties with `@property` and `@name.setter`, never `name = property(get_name, set_name)` or a hand-written descriptor; a property takes no parameters. *Why:* the decorator form keeps getter and setter together and is what tools understand. *Check:* `grep: =\s*property\(`; ruff `PLR0206`. *Severity:* Minor. *Source:* Google py §2.13, mD Python 03.
- **PY-CLS-7** [MUST NOT] Use a property for computation that subclasses are expected to override or extend; use a method. *Why:* overriding property behaviour is awkward and easy to get wrong. *Check:* manual. *Severity:* Major. *Source:* Google py §2.13.
- **PY-CLS-8** [MUST] Make a setter (property or method) reject invalid values with `ValueError` or `TypeError` instead of silently clamping or coercing them, and have `__init__` assign through the setter when the setter validates. *Why:* silent coercion hides the caller's bug. *Check:* manual. *Severity:* Major. *Source:* mD Python 03.
- **PY-CLS-9** [MUST] Model configs and plain records as `@dataclasses.dataclass(frozen=True)` (adding `slots=True` and `kw_only=True` as they fit), or as `typing.NamedTuple` when tuple behaviour (unpacking, indexing) is wanted; not as dicts with string keys or classes with hand-written `__init__`, `__repr__` and `__eq__`. Leave out `frozen` only when mutation is part of the design, and say so. *Why:* typed, immutable records catch typos and accidental mutation. *Check:* manual; ruff `RUF008`, `RUF009` for field defaults. *Severity:* Major. *Source:* cv-kit, mD Python 03, mD Python 05.
- **PY-CLS-10** [MUST] Declare named tuples with the class syntax (`class Point(typing.NamedTuple):` with typed fields), not `collections.namedtuple("Point", "x y")` or the functional `typing.NamedTuple(...)` call; a type name must match the name it is bound to. *Why:* a mismatched name breaks pickling to worker processes, and the class form carries types. *Check:* ruff `UP014`; `grep: namedtuple\(`. *Severity:* Minor. *Source:* mD Python 05.
- **PY-CLS-11** [MUST NOT] Use power features: custom metaclasses, `exec`, `eval` or `compile` of generated code, bytecode access, reassigning `__class__` or `__bases__`, monkey-patching third-party modules or classes, `sys.modules` tricks or import hooks, `__getattr__` that invents attributes, frame inspection, or `getattr`/`setattr` with computed names for dispatch (use an explicit dict registry). Standard-library users of these mechanisms (`abc.ABC`, `enum.Enum`, `dataclasses`, `typing.Protocol`, `functools.singledispatch`) are fine. *Why:* code that rewrites itself at run time defeats readers, type checkers and refactoring tools. *Check:* ruff `S102`, `S307`, `B009`, `B010`; `grep: metaclass=|__class__\s*=|__bases__|sys\.modules\[|importlib\.|\bsetattr\(|\bgetattr\(|def __getattr__|currentframe|_getframe`. *Severity:* Major. *Source:* Google py §2.13, §2.19.
- **PY-CLS-12** [MUST] In a subclass's `__init__`, call `super().__init__(...)` (no arguments to `super`) before assigning attributes; never `super(Cls, self)` or `Parent.__init__(self, ...)`. `torch.nn.Module` subclasses must make this call before assigning any submodule or parameter. *Why:* explicit parent calls break cooperative multiple inheritance, and `nn.Module` raises when attributes come first. *Check:* ruff `UP008`; manual. *Severity:* Major. *Source:* mD Python 03.
- **PY-CLS-13** [MUST] Mark every overriding method with `@override` (`typing.override` on Python 3.12 and later, `typing_extensions.override` before) and keep its signature compatible with the base method. *Why:* the marker lets mypy catch a renamed base method, and an incompatible override breaks callers that use the base type. *Check:* mypy `override`; mypy `explicit-override` is not enabled (see Per-project settings). *Severity:* Major for an incompatible signature; Minor for a missing marker. *Source:* Google py §3.8.3.1, mD Python 03.
- **PY-CLS-14** [MUST] Keep dunder methods consistent: define `__hash__` whenever you define `__eq__` (or set `__hash__ = None` on purpose); return `NotImplemented` from binary operators for unsupported operand types; give value classes a `__repr__` that shows their fields, and add `__str__` only when a different user-facing form is needed. *Why:* an `__eq__` without `__hash__` makes instances misbehave in sets and dicts. *Check:* ruff `PLW1641`, `PLE0302`, `PLE0303`, `PLE0304`, `PLE0305`, `PLE0307`, `PLE0308`, `PLE0309`; manual. *Severity:* Major. *Source:* mD Python 03.
- **PY-CLS-15** [MUST NOT] Use double-underscore, name-mangled attributes or methods (`self.__cache`); use a single leading underscore. *Why:* mangling hurts reading and testing and gives no real privacy. *Check:* `grep: self\.__[a-z]\w*[a-z0-9]\b|def __[a-z]\w*[a-z0-9]\(`. *Severity:* Minor. *Source:* Google py §3.16.2, mD Python 03.
- **PY-CLS-16** [MUST NOT] Read or write another class's or module's `_private` members from outside it; tests may. *Why:* private members change without notice. *Check:* ruff `SLF001` (tests exempt by config). *Severity:* Major. *Source:* Google py §3.16.2.
- **PY-CLS-17** [MUST] Declare interfaces with `abc.ABC` and `@abc.abstractmethod`, or with `typing.Protocol` for structural typing; an ABC has at least one abstract method and no empty placeholder methods without `@abstractmethod`. Use a `Protocol` or polymorphism instead of long `isinstance` chains. *Why:* explicit interfaces fail at construction, not deep inside a call. *Check:* ruff `B024`, `B027`; manual. *Severity:* Major. *Source:* mD Python 03.
- **PY-CLS-18** [PREFER] Compose objects rather than building deep inheritance trees, and keep related small classes and functions together in one module (one class per file is not required). *Why:* shallow designs are easier to change. *Check:* manual. *Severity:* Minor. *Source:* Google py §3.16.2, mD Python 03.
- **PY-CLS-19** [MUST NOT] Write `class Foo(object):` or `class Foo():`. *Why:* both are redundant in Python 3. *Check:* ruff `UP004`, `UP039`. *Severity:* Minor. *Source:* mD Python 03.
- **PY-CLS-20** [MUST] Name the first parameter `self` in methods and `cls` in class methods, and never assign to either. *Why:* readers and tools rely on the convention. *Check:* ruff `N804`, `N805`, `PLW0211`, `PLW0642`. *Severity:* Minor. *Source:* Google py §3.16.
- **PY-CLS-21** [MUST NOT] Return a value from, or `yield` in, `__init__`. *Why:* it raises at construction. *Check:* ruff `PLE0100`, `PLE0101`. *Severity:* Major. *Source:* cv-kit.
- **PY-CLS-22** [PREFER] Give classes that are created in very large numbers `__slots__` (or `@dataclass(slots=True)`); for millions of records use arrays instead (PY-ML-9). *Why:* per-instance dictionaries cost memory. *Check:* ruff `PLC0205`, `RUF023` (form of `__slots__`); manual. *Severity:* Minor. *Source:* mD Python 03.

### PY-TYPE: annotations and typing

- **PY-TYPE-1** [MUST] Annotate every parameter and the return type of every function and method in library code, private ones included, with `-> None` on `__init__`; leave `self` and `cls` unannotated (use `Self`, from `typing_extensions` on 3.10, for "returns its own class"). Add annotations in the same change that adds or edits a public API. Test files are exempt from the ruff `ANN` rules. *Why:* mypy checks only annotated code. *Check:* mypy `no-untyped-def`, `no-untyped-call`; ruff `ANN001`, `ANN002`, `ANN003`, `ANN201`, `ANN202`, `ANN204`, `ANN205`, `ANN206`. *Severity:* Major. *Source:* Google py §2.21, §3.19.1, cv-kit.
- **PY-TYPE-2** [MUST] Pass `mypy --strict` with cv-kit's options by fixing errors, not suppressing them: `union-attr`, `arg-type`, `return-value`, `assignment`, `override`, `possibly-undefined`, `truthy-bool`, `truthy-function`, `redundant-expr`, `unreachable`, `no-any-return` and the rest. A justified suppression follows PY-LINT-3. *Why:* each error marks a path where the code can receive a value it does not handle. *Check:* mypy (codes as listed). *Severity:* Major; Critical when the error marks a reachable `None` or wrong-type path. *Source:* cv-kit.
- **PY-TYPE-3** [MUST NOT] Use `typing.Any` where a precise type, a `TypeVar` or a `Protocol` works. When a type really is unknown (an untyped third-party return, parsed JSON), write `Any` explicitly and narrow it straight away. *Why:* `Any` switches off checking for everything it touches. *Check:* ruff `ANN401`; mypy `no-any-return`. *Severity:* Major. *Source:* Google py §3.19.1, §3.19.15.
- **PY-TYPE-4** [MUST] Spell optional values `X | None`, with `None` last, and annotate every parameter that defaults to `None` that way; never `Optional[X]`, `Union[...]` or the implicit form `x: int = None`. *Why:* the annotation must show that `None` is possible, in the 3.10 syntax. *Check:* ruff `RUF013`, `UP045`, `UP007`, `RUF036`. *Severity:* Minor. *Source:* Google py §3.19.5.
- **PY-TYPE-5** [MUST] Use built-in generics and `collections.abc` (`list[int]`, `dict[str, float]`, `tuple[int, int]`, `collections.abc.Sequence[Path]`), never the deprecated `typing.List`, `Dict`, `Tuple`, `Set`, `Type` or `typing.Text`. *Why:* the `typing` aliases are deprecated. *Check:* ruff `UP006`, `UP035`, `UP019`. *Severity:* Minor. *Source:* Google py §3.19.11, §3.19.12.
- **PY-TYPE-6** [MUST] Give generic types their parameters (`Sequence[int]`, `dict[str, torch.Tensor]`, `Callable[[Frame], None]`), never a bare `list`, `dict`, `Sequence` or `Callable`; write `[Any]` explicitly when that is what you mean. *Why:* a bare generic silently means `Any` inside. *Check:* mypy `type-arg`. *Severity:* Minor. *Source:* Google py §3.19.15.
- **PY-TYPE-7** [MUST] Type read-only collection parameters with the abstract type (`collections.abc.Sequence`, `Mapping`, `Iterable`) and return concrete types (`list`, `dict`); `np.ndarray` and `torch.Tensor` are not a `Sequence` to the type checker. *Why:* abstract parameter types accept tuples and lists alike and show that the function does not mutate them. *Check:* manual. *Severity:* Minor. *Source:* Google py §3.19.12.

- **PY-ML-14** [MUST NOT] Force a host-device sync inside a per-batch or per-frame loop without need: `.item()`, `.cpu()`, `.numpy()`, `.tolist()`, `float(t)`, printing or logging a CUDA tensor, a Python `if` on a CUDA tensor, `torch.cuda.synchronize()`. - **PY-ML-15** [MUST NOT] Keep autograd graphs alive by storing tensors that require grad across iterations (`history.append(loss)`); store `loss.detach()`, or `loss.item()` at the logging interval. *Why:* each stored loss keeps its graph and GPU memory until the list goes away, and `torch.cuda.empty_cache()` cannot free it. *Check:* manual. *Severity:* Critical. *Source:* mD Python 05.
- **PY-ML-16** [MUST NOT] Log or print whole arrays or tensors inside a loop; log the shape, dtype and summary statistics, computed once per interval. *Why:* stringifying large tensors is slow, floods logs and syncs the device. *Check:* manual. *Severity:* Major. *Source:* mD Python 04.
- **PY-ML-17** [MUST] Take the device (and dtype) as a parameter instead of hard-coding it: no `.cuda()`, `"cuda:0"` or `torch.device("cuda")` in library code; create tensors directly on the target device (`torch.zeros(n, device=device)`) rather than on the CPU followed by `.to(device)`. *Why:* hard-coded devices break CPU tests and multi-GPU runs, and the extra copy costs time. *Check:* `grep: \.cuda\(\)|["']cuda(:\d+)?["']`. *Severity:* Major. *Source:* cv-kit.
- **PY-ML-18** [MUST] Convert colour order explicitly, at one documented boundary (`cv2.cvtColor(img, cv2.COLOR_BGR2RGB)` right after `cv2.imread`); never flip channels with `[..., ::-1]` without a comment, and copy or make the result contiguous when it goes on to OpenCV or `torch.from_numpy`. *Why:* OpenCV reads BGR while most models expect RGB, and the mistake gives quietly worse predictions. *Check:* `grep: \[\s*\.\.\.\s*,\s*::-1\s*\]`; manual. *Severity:* Critical. *Source:* cv-kit.
- **PY-ML-19** [MUST] Check the results of OpenCV I/O: `cv2.imread` returns `None` on failure, `VideoCapture.read()` returns an `(ok, frame)` pair, and `isOpened()` reports whether a capture or writer opened; raise or stop on failure. *Why:* OpenCV reports these failures without raising, and the `None` surfaces later as a confusing error. *Check:* `grep: cv2\.imread\(|\.read\(\)`; manual. *Severity:* Critical. *Source:* cv-kit.
- **PY-ML-20** [MUST] Make datasets safe for `DataLoader` workers: picklable (no lambdas, open handles or CUDA tensors stored in `__init__`), with heavy handles (h5py, LMDB, video readers) opened lazily in each worker (in `__getitem__` or `worker_init_fn`), and `num_workers` taken from config; the training script has its `__main__` guard (PY-STATE-7). *Why:* a handle opened before the workers fork is shared by all of them and corrupts reads, and unpicklable state crashes spawned workers. *Check:* manual. *Severity:* Critical. *Source:* cv-kit, mD Python 04.
- **PY-ML-21** [MUST NOT] Compare floating-point results with `==` or `!=` (IoU values, scores, coordinates after arithmetic, timestamps); use `math.isclose`, `np.isclose` or `np.allclose`, or `torch.allclose`, with a tolerance chosen for the case and written down. Exact comparison is only for values documented as exact (a sentinel `0.0` meaning "off"). *Why:* rounding makes values that are equal in theory differ in the last bits. *Check:* `grep: [=!]=\s*-?\d+\.\d`; manual. *Severity:* Major; Critical when the comparison decides the output. *Source:* mD Python 01, cv-kit.
- **PY-ML-22** [MUST] Use the numerically stable library function instead of a hand-written formula: `np.hypot` or `math.dist` for distances, `torch.logsumexp`, `F.log_softmax`, `F.cross_entropy` and `F.binary_cross_entropy_with_logits` on logits, a cross-product (shoelace) area or `cv2.contourArea` for polygons; round only when formatting output. *Why:* naive formulas overflow, underflow or lose precision through cancellation. *Check:* manual. *Severity:* Major. *Source:* mD Python 03, mD Python 04.
- **PY-ML-23** [MUST] Time code with `time.perf_counter()`, not `time.time()`; for GPU work call `torch.cuda.synchronize()` before each clock read (or use CUDA events), discard warm-up iterations, and report over several runs. *Why:* the wall clock can jump, and CUDA calls return before the work is done. *Check:* `grep: time\.time\(\)`; manual. *Severity:* Major. *Source:* mD Python 04.
- **PY-ML-24** [MUST] Use timezone-aware datetimes for wall-clock timestamps in logs, run directories and checkpoint names (`datetime.datetime.now(tz=datetime.timezone.utc)`). *Why:* naive times are ambiguous across machines and clock changes. *Check:* ruff `DTZ001`, `DTZ005`, `DTZ007`, `DTZ011`. *Severity:* Minor. *Source:* cv-kit.
- **PY-ML-25** [MUST] Call a `torch.nn.Module` as `model(x)`, never `model.forward(x)`. *Why:* calling `forward` directly skips registered hooks. *Check:* `grep: \.forward\(`. *Severity:* Major. *Source:* mD Python 03.
- **PY-ML-26** [MUST NOT] `copy.deepcopy` a model or a dataset holding large arrays unless a full copy is the intent (an EMA or teacher model), and then say so in a comment. *Why:* the copy doubles GPU or host memory. *Check:* `grep: deepcopy\(`. *Severity:* Major. *Source:* mD Python 04.
- **PY-ML-27** [MUST] Load checkpoints with an explicit `map_location` and `weights_only=True` (PY-RES-9), and verify downloaded weights and datasets against a published hash before use. *Why:* (experience) a truncated or substituted download can load without error and quietly degrade results. *Check:* `grep: torch\.load\(|load_state_dict_from_url|hf_hub_download|urlretrieve`; manual. *Severity:* Major. *Source:* cv-kit.
- **PY-ML-28** [MUST] Replace deprecated NumPy aliases and functions (`np.float`, `np.int`, `np.bool`, names removed in NumPy 2). *Why:* they fail on current NumPy. *Check:* ruff `NPY001`, `NPY003`, `NPY201`. *Severity:* Minor. *Source:* cv-kit.

### PY-TEST: tests

- **PY-TEST-1** [MUST] Add or update tests in the same change for every change in behaviour; a bug fix adds a test that fails without the fix. *Why:* untested changes regress silently. *Check:* manual (diff review). *Severity:* Major. *Source:* cv-kit.
- **PY-TEST-2** [MUST] Before a behaviour-preserving refactor, pin the current behaviour with characterisation tests (outputs for typical and edge inputs) and keep them passing through every step. *Why:* "behaviour-preserving" must be checked, not claimed. *Check:* manual. *Severity:* Major. *Source:* cv-kit.
- **PY-TEST-3** [MUST] Write tests with pytest and plain `assert` statements, which are allowed in `test_*.py` and `*_test.py`; new tests do not use `unittest` assertion methods. Test one behaviour per test. *Why:* pytest turns plain asserts into clear failure messages. *Check:* ruff `S101` (exempt in test files by config); `grep: self\.assert\w+\(`. *Severity:* Minor. *Source:* Google py §2.4.
- **PY-TEST-4** [MUST] Name test files `test_<module>.py` (or `<module>_test.py`) and test functions `test_<unit>_<state>` in `lower_with_under` (for example `test_letterbox_keeps_aspect_ratio`); only a legacy CapWords test module may keep its `test<Unit>_<state>` style. *Why:* the name says what broke; the file patterns match cv-kit's per-file config. *Check:* manual. *Severity:* Minor. *Source:* Google py §3.16.2.
- **PY-TEST-5** [MUST] Test expected exceptions with `pytest.raises(SpecificError, match=...)`, escaping regex characters in `match`; never `pytest.raises(Exception)`. *Why:* a broad check passes on the wrong error. *Check:* ruff `B017`, `RUF043`; `PT011` is not enabled (see Per-project settings). *Severity:* Minor. *Source:* cv-kit.
- **PY-TEST-6** [MUST NOT] Use the network, real cameras, GPUs or large downloads in unit tests; use `tmp_path`, small fixtures and fakes, and mark integration or GPU tests (`@pytest.mark.gpu`) so they skip where the hardware is missing. *Why:* unit tests must run anywhere, quickly. *Check:* manual. *Severity:* Major. *Source:* cv-kit.
- **PY-TEST-7** [MUST] Make tests deterministic: seed explicit generators inside each test, do not depend on test order, the clock, or the order of unsorted data, and compare floats with `np.testing.assert_allclose`, `torch.testing.assert_close` or `pytest.approx` with a stated tolerance. *Why:* flaky tests get ignored. *Check:* manual. *Severity:* Major. *Source:* cv-kit.
- **PY-TEST-8** [MUST] Keep golden files (expected images, arrays, JSON) small and in the repository, record in the test's docstring how they were produced (script and command), compare numeric goldens with a tolerance, and regenerate them only through an explicit opt-in (a command-line flag or environment variable), never automatically on a mismatch. *Why:* goldens that update themselves test nothing. *Check:* manual. *Severity:* Major. *Source:* cv-kit, Google py §3.8.2.1.
- **PY-TEST-9** [MUST] Test the documented array contract of public CV functions (output shape, dtype, value range, colour order) and their edge inputs (an empty batch, a one-pixel image, boxes on the image border). *Why:* contract breaks are the usual CV regressions. *Check:* manual. *Severity:* Major. *Source:* cv-kit.
- **PY-TEST-10** [MUST] Give every decorator its own unit tests. *Why:* a decorator wraps many call sites and fails far from its definition. *Check:* manual. *Severity:* Major. *Source:* Google py §2.17.
- **PY-TEST-11** [MUST] Keep tests isolated: no mutable module state shared between tests, setup in fixtures, no `time.sleep` used to wait for another thread or process. *Why:* tests that share state pass or fail depending on order. *Check:* manual. *Severity:* Major. *Source:* cv-kit.
- **PY-TEST-12** [MUST] Write docstrings for tests only when they add information (how to run the test, unusual setup, an external dependency, golden files); test modules, test classes and test functions need none otherwise. *Why:* the test name carries the rest. *Check:* manual (ruff `D` rules are off for tests). *Severity:* Minor. *Source:* Google py §3.8.2.1.
- **PY-TEST-13** [MUST] Keep the test exemptions (`S101`, `PLR2004`, `D`, `ANN`, `SLF001`) confined to test files; never widen `per-file-ignores` to cover library code. *Why:* the exemptions exist because tests are not API. *Check:* manual (config diff review). *Severity:* Major. *Source:* cv-kit.

## Review order

Walk the catalogue from the rules that can corrupt results to the ones that only affect looks:

1. **PY-RES** and **PY-CONC**: leaks, races, deadlocks, unsafe loaders.
2. **PY-ML**: wrong output (colour order, views, integer overflow, inference mode, data order), device syncs, vectorisation.
3. **PY-ERR**: swallowed or misreported errors, asserts.
4. **PY-BOOL**, **PY-FN**, **PY-STATE**: logic traps, aliasing, mutable defaults, import-time work.
5. **PY-TEST**: tests for the changed behaviour, determinism, goldens.
6. **PY-CLS** and **PY-TYPE**: API design, mypy errors.
7. **PY-IMP** and **PY-STR**: import discipline, logging, messages.
8. **PY-DOC** and **PY-NAME**: contracts, comments, names.
9. **PY-LINT** and **PY-FMT**: suppressions and layout.

**What the tools already cover.** When the three tools ran clean in CI, do not hand-report:

- `ruff format --check` passing: all of PY-FMT except PY-FMT-2 (long strings the formatter cannot split), PY-FMT-3, PY-FMT-6 and PY-FMT-11; PY-STR-5; the layout parts of PY-DOC-1 and PY-DOC-17.
- `ruff check` passing: rules whose *Check* is ruff codes only (for example PY-IMP-3, PY-IMP-5, PY-IMP-6, PY-IMP-8, PY-IMP-9, PY-BOOL-1, PY-BOOL-3, PY-BOOL-10 to PY-BOOL-14, PY-STR-2, PY-STR-8, PY-TYPE-4, PY-TYPE-5, PY-NAME-1, PY-NAME-8, PY-NAME-10, PY-DOC-2, PY-DOC-6, PY-LINT-4, PY-LINT-7). Still read each new suppression for its reason (PY-LINT-3).
- `mypy` passing: PY-TYPE-1, PY-TYPE-2, PY-TYPE-6, PY-BOOL-16.

Rules that combine a tool code with "manual" still need reading: the tool finds only part of the problem.
When the tools were not run, report a single PY-LINT-1 finding, run them if you can, and list their output
as one block rather than one finding per hit.

## Refactor recipes

Each recipe preserves behaviour unless its risk says otherwise. Pin the behaviour first (PY-TEST-2), apply
one recipe at a time, and run the tests after each.

- **R-PY-1** Mutable default to `None`: `def add(box, into=[])` -> `def add(box, into=None)` with `into = [] if into is None else into` as the first line; fixes PY-STATE-3; risk: callers that relied on the shared list as an accidental cache now get a fresh one per call; pin with a test that calls twice and checks the second result.
- **R-PY-2** Broad handler to a narrow one: a five-line `try` with `except Exception: pass` -> a `try` around the one decoding call, `except cv2.error:` that logs and counts, and the rest in `else:`; fixes PY-ERR-2, PY-ERR-3, PY-ERR-4; risk: errors that were swallowed now propagate, so decide the intended behaviour first; pin with tests that feed the failing input and assert the chosen outcome.
- **R-PY-3** `assert` to a raise: `assert img.ndim == 3` -> `if img.ndim != 3: raise ValueError(f"expected an HWC image, got shape {img.shape}")`; fixes PY-ERR-1, PY-ML-6; risk: the exception type changes from `AssertionError` and the check now also runs under `-O`; pin with `pytest.raises(ValueError)` and grep callers for `except AssertionError`.
- **R-PY-4** `open`/`close` pair to `with`: `f = open(p)`, `text = f.read()`, `f.close()` -> `with p.open(encoding="utf-8") as f: text = f.read()`; fixes PY-RES-1, PY-RES-5, PY-RES-6; risk: the explicit encoding changes decoding on machines whose default was not UTF-8, and any use of `f` after the block now fails; pin with a test on a file containing non-ASCII text.
- **R-PY-5** Video capture release: a `cv2.VideoCapture(src)` that is never released -> `try:` around the read loop with `finally: cap.release()`, or a small `@contextlib.contextmanager` `open_capture(src)` that also raises when `isOpened()` is false; fixes PY-RES-1, PY-ML-19; risk: raising on a failed open changes behaviour for callers that treated it as an empty stream; pin with a test using a missing path.
- **R-PY-6** Resource-holding generator to a context manager: `def frames(path)` that opens a capture and yields frames -> `@contextlib.contextmanager def open_frames(path)` that yields an iterator and releases in `finally`; fixes PY-RES-4, PY-DOC-8; risk: call sites change from `for frame in frames(p)` to `with open_frames(p) as frames:`; pin with a test that breaks out early and checks a fake capture's `release()` count.
- **R-PY-7** `os.path` to `pathlib`: `os.path.join(root, name + ".png")` -> `root / f"{name}.png"`; fixes PY-RES-6; risk: functions now return `Path` where callers may expect `str` (string concatenation, JSON, C extensions), so convert with `str()` at those boundaries; pin with tests of return types and exact path strings, including an absolute second part.
- **R-PY-8** `== None` to `is None`: `if mask == None:` -> `if mask is None:`; fixes PY-BOOL-1, PY-BOOL-5; risk: for arrays the old line raised or compared element-wise, so the new behaviour may be the first correct one; pin with tests passing `None` and a real array.
- **R-PY-9** `or` default to an explicit `None` test: `thr = thr or 0.5` -> `thr = 0.5 if thr is None else thr`; fixes PY-BOOL-2; risk: this deliberately changes the result for falsy inputs (`0.0` now means zero), so confirm with the owner; pin with tests for `None`, `0.0` and a normal value.
- **R-PY-10** Index loop to `zip`: `for i in range(len(imgs)): run(imgs[i], labels[i])` -> `for img, label in zip(imgs, labels, strict=True): run(img, label)`; fixes PY-FN-8, PY-FN-10; risk: `strict=True` raises on unequal lengths that were silently truncated before; pin with a length-mismatch test and agree that raising is intended.
- **R-PY-11** `map` with `lambda` to a comprehension: `list(map(lambda b: b * s, boxes))` -> `[b * s for b in boxes]`; fixes PY-FN-5; risk: a bare `map` was lazy and single-pass, so use a generator expression `(b * s for b in boxes)` where the old result was consumed lazily or was large; pin with a test of the consumer.
- **R-PY-12** Named lambda to `def`: `area = lambda b: (b[2] - b[0]) * (b[3] - b[1])` -> `def _box_area(box: Box) -> float:` with the same body; fixes PY-FN-6, PY-TYPE-1; risk: none at run time apart from `__name__`; the function now pickles for workers.
- **R-PY-13** Pass-through accessors to a public attribute: `get_size()` and `set_size()` around `self._size` -> a public `size` attribute; fixes PY-CLS-4; risk: external callers of the methods break, so in a public API keep them for one release with a `DeprecationWarning` (PY-ERR-12); pin with tests that read and write `size`.
- **R-PY-14** `property()` call to decorators: `scale = property(_get_scale, _set_scale)` -> `@property def scale(self)` plus `@scale.setter`; fixes PY-CLS-6; risk: code that called `_get_scale` directly; pin with tests of reading, writing and the setter's validation error.
- **R-PY-15** `@staticmethod` to a module function: `Letterbox.pad(...)` defined as a static method -> module-level `def letterbox_pad(...)`; fixes PY-CLS-1; risk: calls through `self.pad` or the class, and subclasses overriding `pad`, must all move; grep every call site and pin the old entry points with tests before moving.
- **R-PY-16** Config dict to a frozen dataclass: `cfg = {"size": 640, "conf": 0.25}` -> `@dataclasses.dataclass(frozen=True, kw_only=True) class DetectorConfig` with `size: int = 640` and `conf: float = 0.25`; fixes PY-CLS-9; risk: code that mutates the config now raises (use `dataclasses.replace`), `cfg["size"]` becomes `cfg.size`, equality changes, and serialisation needs `dataclasses.asdict`; pin with a round-trip test through the config loader.
- **R-PY-17** Module-level cache to an explicit one: `_MODELS = {}` filled by `get_model(name)` -> `@functools.lru_cache(maxsize=4) def get_model(name: str) -> Model`, or a cache object passed in; fixes PY-STATE-1, PY-FN-27; risk: lifetime and eviction change (a bounded cache may reload) and thread safety must be rechecked; pin with a test that counts loads.
- **R-PY-18** Import-time work to `main()`: `MODEL = load_weights(PATH)` at module level -> a `load_model()` function called by the entry point, with script logic under the `__main__` guard; fixes PY-STATE-6, PY-STATE-7; risk: other modules that read `MODEL` at import break; pin with a test that imports the module with loading mocked and asserts nothing loaded, plus one end-to-end run.
- **R-PY-19** Per-pixel loop to a vectorised call: nested `for y`/`for x` loops setting `out[y, x] = 255 if img[y, x] > t else 0` -> `out = np.where(img > t, 255, 0).astype(np.uint8)`; fixes PY-ML-7; risk: dtype promotion, overflow, rounding and edge handling can differ, and peak memory grows; pin by comparing old and new functions on random inputs that include edge values, exactly for integers and with `assert_allclose` for floats.
- **R-PY-20** Growing array to list-then-stack: `out = np.vstack([out, box])` in a loop -> `rows.append(box)` in the loop and `np.stack(rows)` after it (or `np.empty((0, 4))` when `rows` is empty); fixes PY-ML-8; risk: the empty case (`np.stack([])` raises) and the result dtype; pin with tests for zero, one and many rows.
- **R-PY-21** String accumulation to `join`: `s += f"{k}={v},"` in a loop -> `",".join(f"{k}={v}" for k, v in items)`; fixes PY-STR-4; risk: the trailing separator the loop added disappears; pin the exact output string.
- **R-PY-22** Eager log formatting to arguments: `logger.info(f"batch {i} loss {loss:.3f}")` -> `logger.info("batch %d loss %.3f", i, loss)`; fixes PY-STR-11; risk: a literal `%` in the text must become `%%`, and a wrong argument count fails only when the record is emitted; pin with a `caplog` test.
- **R-PY-23** `print` to logging: `print("saved", path)` in a library -> `logger.info("saved %s", path)`; fixes PY-STR-10; risk: the output moves from stdout to the logging handlers and is hidden at the default WARNING level, so keep `print` in CLI entry points users read; pin with `capsys` and `caplog` tests.
- **R-PY-24** Global seed to a passed generator: `np.random.seed(0)` and `np.random.rand(n)` -> an `rng: np.random.Generator` parameter and `rng.random(n)`; fixes PY-ML-1; risk: the random stream changes, so results are not bit-identical to before; regenerate goldens on purpose (PY-TEST-8) and pin reproducibility for a fixed seed rather than the old values.
- **R-PY-25** Hand-written memo to `functools`: a `_cache` dict keyed by the arguments -> `@functools.lru_cache(maxsize=N)`; fixes PY-FN-27, PY-STATE-3; risk: unhashable arguments now raise `TypeError`, keyword and positional calls are cached separately, and a bounded size recomputes evicted entries; pin with tests that count calls.
- **R-PY-26** Decorator wrapper repair: `def wrapper(x): f(x)` -> `@functools.wraps(f)` on `def wrapper(*args: P.args, **kwargs: P.kwargs) -> R: return f(*args, **kwargs)`; fixes PY-FN-13; risk: the wrapper now returns the wrapped value where it returned `None`, and keyword arguments now pass through; pin with tests of the decorated function's result, `__name__` and `__doc__`.
- **R-PY-27** Parent initialiser to `super()`: `Parent.__init__(self, cfg)` after attribute assignments -> `super().__init__(cfg)` as the first statement; fixes PY-CLS-12; risk: with multiple inheritance the MRO may call more base initialisers, and attributes set by parent and child may now override each other the other way round; pin with tests of the constructed object's attributes.
- **R-PY-28** Positional flag to keyword-only: `def draw(img, boxes, show_labels=True)` -> `def draw(img, boxes, *, show_labels=True)`; fixes PY-FN-18; risk: callers passing the flag positionally get `TypeError`, so update every call site, and in a public API accept both for one release with a deprecation warning; pin with a test of the keyword call.
- **R-PY-29** Multi-clause comprehension to a vectorised call or loops: `[(y, x) for y in range(h) for x in range(w) if m[y, x]]` -> `np.argwhere(m)` or explicit nested loops; fixes PY-FN-4, PY-ML-7; risk: element order and the result type (array rows instead of tuples); pin with an order-sensitive test.
- **R-PY-30** Name and relative imports to module imports: `from .ops import nms` -> `from mypkg import ops` and `ops.nms(...)`; fixes PY-IMP-1, PY-IMP-3; risk: import cycles can appear or disappear, and `mock.patch` targets change (a name import binds once, a module attribute is looked up at each call); pin by running the whole suite and fixing patch targets.
- **R-PY-31** Array truthiness to an explicit test: `if boxes:` on an array -> `if boxes.size:` (non-empty) or `if boxes is not None:` (present), whichever was meant; fixes PY-BOOL-5; risk: the two replacements mean different things, so read the callers to choose; pin with tests for `None`, an empty array and a one-element array.
- **R-PY-32** Exact type check to `isinstance`: `if type(v) == int:` -> `if isinstance(v, int) and not isinstance(v, bool):`; fixes PY-BOOL-8; risk: subclasses, and NumPy integers if you add `np.integer`, are now accepted; pin with tests for `int`, `bool`, `np.int64` and a subclass.
- **R-PY-33** Evaluation under inference mode: `out = model(x)` in an evaluation function -> `model.eval()` and `with torch.inference_mode(): out = model(x)`; fixes PY-ML-13; risk: outputs change when the model has dropout or batch-norm (the bug being fixed), and tensors made under inference mode cannot join autograd later; pin with a golden-output test in eval mode, and restore `train()` where the caller expects it.
- **R-PY-34** Per-step sync to device accumulation: `total += loss.item()` every step -> `total = total + loss.detach()` on the device and one `.item()` per logging interval; fixes PY-ML-14, PY-ML-15; risk: summing in float32 on the device instead of a Python float changes the last digits; pin with `assert_allclose` and a stated tolerance.
- **R-PY-35** `try` inside a loop to a helper: a `try`/`except` around each sample's decode inside the loop -> `def _load_one(path: Path) -> Sample | None:` holding the narrow `try`, called from the loop; fixes PY-ERR-4 and resolves `PERF203` without a suppression; risk: none while the handler stays the same; pin with a test that includes one corrupt sample.
- **R-PY-36** Direct write to atomic replace: `torch.save(state, path)` -> save to a temporary name in the same directory, then `tmp.replace(path)`; fixes PY-RES-7; risk: a temp file left after a crash, and permissions taken from the temp file; pin with a test that makes the save fail and checks the old file is intact.
- **R-PY-37** Long function to named steps: a long `train_step` -> `_forward`, `_compute_loss` and `_update` helpers called in order; fixes PY-FN-16, PY-FN-17; risk: evaluation order, early returns and locals shared between the steps; pin with characterisation tests on fixed inputs and seeds before extracting (PY-TEST-2).
- **R-PY-38** Old typing spellings: `Optional[List[int]]` -> `list[int] | None`; fixes PY-TYPE-4, PY-TYPE-5; risk: libraries that evaluate annotations at run time need Python 3.10 for `|`, which cv-kit targets; pin by importing every changed module in the test run.
- **R-PY-39** Tuple records to typed records: `collections.namedtuple("Det", "box score label")` or a bare tuple -> `class Det(typing.NamedTuple)` with typed fields, or a frozen dataclass when tuple behaviour is not needed; fixes PY-CLS-9, PY-CLS-10; risk: a dataclass no longer unpacks or equals a plain tuple, so keep `NamedTuple` while callers unpack; pin with tests at the unpacking call sites.
- **R-PY-40** Unordered iteration to sorted: `enumerate({p.parent.name for p in paths})` -> `enumerate(sorted({p.parent.name for p in paths}))`; fixes PY-ML-3; risk: the class-to-index map changes once, which invalidates trained checkpoints and stored label maps, so migrate or regenerate them; pin with a test of the map for a fixed directory tree.

## Per-project settings and optional checks

cv-kit's shipped `ruff.toml` already ignores `TD002`, `TD003` and `TRY003` and accepts `F` as an import
alias name for `N812`. The items below are recommendations a project can adopt; every code was confirmed to
exist with `ruff rule` (ruff 0.17.2).

- **Noisy, enabled (keep, suppress with a reason):** `FBT003` on third-party calls that take positional booleans (`model.train(False)`; prefer `model.train(mode=False)`); `PERF203` on per-sample `try` blocks (use R-PY-35); `S603` on every `subprocess` call; `EXE002` on filesystems that mark every file executable (see Tooling).
- **Inert until configured:** `TID251` (`banned-api` is empty; candidates: `os.chdir`, `os.system`, `typing.Text`, `numpy.random.seed`); `TID253` (`banned-module-level-imports` is empty); `lint.logger-objects` is empty, so the `G` rules only see conventionally named loggers (PY-STR-9).
- **Stable, not selected:** `T100` (debugger calls, PY-LINT-8); `INP001` (missing `__init__.py`, PY-IMP-14); `TC001`, `TC002`, `TC003`, `TC004`, `TC005` (type-checking-only imports, PY-IMP-11); `ICN001`, `ICN002`, `ICN003` (import alias conventions, PY-IMP-2, would need the torch aliases added); `PYI026` (type alias annotation, PY-TYPE-9); `PT006`, `PT009`, `PT011`, `PT017`, `PT027` (pytest style, PY-TEST-3, PY-TEST-5); `C901` (complexity, alongside PY-FN-16); `FURB129` (`readlines()` in a `for`, PY-RES-8).
- **Ignored on purpose, with a cost:** `E501` is ignored, so code lines the formatter cannot shorten (long strings) are not reported; only comments and docstrings are, through `W505`. Re-enabling `E501` would report them; otherwise PY-FMT-2 is checked by hand.
- **Preview-only (need `preview = true`):** `PLW1514` (open without encoding, PY-RES-5); `B909` (mutation during iteration, PY-FN-9); `PLR6301` (method that does not use `self`, PY-CLS-1); `PLR0904`, `PLR0914`, `PLR1702` (public methods, locals, nesting depth, PY-FN-16); `FURB118` (lambda instead of `operator`, PY-FN-5); `FURB101` (whole-file read, PY-RES-8); `FURB148` (unused `enumerate` index, PY-FN-8); `PLC2701` (private-name import, PY-CLS-16); `DOC201`, `DOC402`, `DOC501` (Returns, Yields and Raises sections, PY-DOC-7 to PY-DOC-9). The pycodestyle whitespace rules (`E203`, `E231`, `E261`, `E302`, `W391`) are also preview-only, but `ruff format` covers them.
- **mypy:** `explicit-override` is not enabled (PY-CLS-13); `truthy-iterable` is not enabled (PY-BOOL-4). Add both to `enable_error_code`. mypy only checks NumPy and PyTorch code when those packages are installed in its environment; cv-kit has not verified array-specific mypy behaviour.
- **No tool at all:** module-only imports (PY-IMP-1), `@staticmethod` (PY-CLS-1), multi-clause comprehensions (PY-FN-4), array truthiness (PY-BOOL-5), float equality (PY-ML-21), device syncs (PY-ML-14), resource release beyond `open()` (PY-RES-1). These are candidates for a small cv-kit AST check later.

## Not adopted

Items of the Google guide and the tutorial that were checked and deliberately left out:

- **pylint** (§2.1): the Google pylintrc, symbolic `pylint: disable=` names, the deprecated `disable-msg`, and the internal `g-` checks. Replaced by ruff and mypy with code-named suppressions (PY-LINT).
- **pytype** (§2.21, §3.19.7) and `# pytype: disable=` comments. Replaced by mypy (PY-TYPE-2).
- **Formatter choice and editor files** (§1): Black or Pyink, Pyink's single-quote mode, the Vim settings file. Replaced by `ruff format` (PY-FMT-1).
- **Old-Python items**: `from __future__ import generator_stop` and the Python 3.5 guidance (§2.20); type comments (§3.19.8) and `typing.Text` (§3.19.11), kept only as bans (PY-TYPE-11, PY-TYPE-5).
- **2-space indentation** in many guide examples and the pylintrc note about Google's internal style (§3.4): cv-kit uses 4 spaces (PY-FMT-4).
- **Library asserts the code does not rely on** (§2.4): dropped by cv-kit's decision; asserts belong in tests (PY-ERR-1).
- **`_` and `unused_` prefixes for unused arguments** (§2.1): replaced by `del` or `@override` (PY-LINT-6).
- **One-line statements** (§3.14): the allowance for `if x: y` without `else` is dropped because the formatter splits it (PY-FMT-9).
- **`'''` for multi-line strings** in projects that use single quotes (§3.10): cv-kit uses double quotes everywhere (PY-STR-5).
- **Import layout details** (§3.13): the deprecated fifth import group and the optional blank line between groups are left to the isort settings.
- **absl** (§3.17): `app.run(main)` and absl flags are not required; the rule about flag values as defaults survives in general form (PY-STATE-4).
- **The `Any`-alias workaround for typing cycles** and its blank-line rule (§3.19.14): replaced by refactoring or `TYPE_CHECKING` (PY-IMP-12).
- **Partial annotation by judgement** (§3.19.1): replaced by full annotation (PY-TYPE-1).
- **Block-level `pylint: disable=invalid-name`** (§3.16.5): replaced by per-line `noqa` or a ruff range pair (PY-NAME-4).
- **Permissive statements that need no rule**: comments may sit right above a `def` (§3.5); parentheses around tuples are optional (§3.3); breaking at the highest syntactic level (§3.2) and spacing around arithmetic operators (§3.6) are the formatter's call; tuple-part names in a docstring need not match variable names (§3.8.3); constrained `TypeVar`s and `AnyStr` are allowed, not required (§3.19.10); "exceptions are allowed but use them with care" (§2.4), "generators, closures and default arguments are fine" (§2.9, §2.12, §2.16) and "be familiar with type hints" (§3.19.1) are background, covered by the specific rules.
- **Judgement calls fixed by cv-kit**: the choice of f-string, `%` or `.format` (§3.10) is settled by PY-STR-1; 2 or 4 spaces in docstring sections (§3.8.3) is settled at 4 (PY-DOC-6).
- **Gaps in the guide itself**: sections 2.15 and 3.9 do not exist in this revision; the guide's oddities (a misplaced anchor, an invalid "good" example, a Python 2 `urllib` call) carry no rule.
- **Tutorial errors**: its Python 2 syntax, `long` and `double` types, the claim that `deque` is thread-safe, the `memo={}` advice, `__del__` as a destructor, `__name` as private, explicit `object` bases and its broken samples were used only as pitfalls; where they contradict a rule they appear in the Conflicts table.
- **Tutorial topics too narrow for a review rule**: `print`'s `sep=`/`end=`, `int(text, base)`, `str.isdigit` caveats, the deletion of the `except ... as err` name, `heapq.nlargest`, `ChainMap`, `Counter.update` semantics, linked-list implementations, Numba and Cython pointers (vectorisation is covered by PY-ML-7).
